# 03 核心概念

Magel 以值语义、非空引用和确定性清理组织资源，并由独立的借用来源与控制流检查约束引用、
移动和释放。完整能力见[当前能力与边界](17-capabilities.md)，具体语法见[语言参考](04-language-reference.md)。

## 1. 值语义与显式移动

```magel
struct Point { int64 x; int64 y; };
void shift(Point p) { p.x = p.x + 10; }
int64 main() {
    Point a;
    a.x = 1;
    a.y = 2;
    Point b = a;
    b.x = 99;
    shift(a);
    println("a=({}, {}) b=({}, {})", a.x, a.y, b.x, b.y);
    return 0;
}
```

```text
a=(1, 2) b=(99, 2)
```

拥有值的普通赋值和按值传参复制，修改副本不影响来源。字符串、容器和拥有字段沿值语义处理，
大对象复制可能产生分配和遍历成本；省复制时选择引用，转移已有资源时选择 `move`。
引用值复制仍引用原对象，含引用字段的聚合不会因此复制引用目标；宿主资源也有各自的可复制约束。

`move(T mut&)` 转移现有句柄和拥有字段，不执行来源的 close/drop。来源绑定随后禁止读写和重绑。
只有所有到达路径都完整移动后，才能重新声明同名变量；新变量具有新的存储身份。
详见[所有权移动](23-ownership-move.md)。

## 2. 非空引用与可选引用

```magel
T mut&     // 可变引用
T const&   // 只读引用
T &        // 与 T const& 等价
```

引用必须绑定有效来源，语言没有可解引用的 null 引用。需要“可能没有引用”时，使用
`Option<T const&>` 或 `Option<T mut&>`：Value 包含有效引用，None 不包含引用。
这是容器的空态，不改变引用本身的非空约束。

```magel
int64 value = 7;
int64 mut& alias = &value;
alias = 9;
Option<int64 const&> optional = Option<int64 const&>::Value(&value);
```

引用的只读权限与来源寿命都要满足要求。引用不能返回局部变量、按值形参或短寿命临时值的地址，
也不能存入比来源活得更久的位置；来源会沿别名、Option/Result、元组、结构体和容器传播。
引用逃逸使用 `MGL1204` 等诊断，指向原文件位置。

## 3. 借用来源与控制流检查

编译器的独立检查器为变量和字段建立来源路径，合并分支与循环状态，并跟踪 move、drop、delete
之后的访问。已移动或已释放来源的读取、写入和重复移动按对应规则拒绝，常见诊断为 `MGL1205`。
对完整移动后的二次声明使用新身份，旧别名不会自动指向新变量。

Magel 允许多个别名共享同一对象；通过一个可变引用修改，其他有效别名会观察到变化。
它不使用“一个可变借用或多个只读借用”的全局独占规则，也不据此保证任意宿主并发访问安全。
检查覆盖编译器能够建模的存储、别名和控制流；动态下标、递归结构、跨函数副作用及原始宿主
内存操作具有具体边界，见[借用控制流与算法验证](11-algorithm-validation.md)。

## 4. 无 GC 与确定性清理

拥有值在生命周期结束时递归清理。`Closeable` 负责关闭，`Drop` 负责析构；同时实现时先 close
再 drop。显式终结按生命周期状态避免重复清理，不把已终结值恢复成可读写的有效对象。
`defer`、`scope(exit)` 可登记作用域退出动作。

```magel
struct Resource : Drop {
    String name;
    void drop() { println("drop {}", self.name); }
};
int64 main() {
    {
        Resource r;
        r.name = "conn";
        println("using");
    }
    println("after block");
    return 0;
}
```

```text
using
drop conn
after block
```

`T mut& p = heap T;` 创建手动分配的存储，须按规则 `delete p;`，不能把离开引用作用域当作自动释放
目标存储的承诺。文件、进程、数据库与其他宿主句柄按各自 Drop/Closeable 契约管理。
幂等 delete/drop、分配身份和 sweep 的边界见[验证说明](11-algorithm-validation.md)。

## 5. 内存与执行边界

- 桌面运行池默认 512 MiB，可配置；独立 MCU 的池、宏和外部内存按板级工程配置。
- 越界、无效引用、容量和转换有相应检查；整数运算按类型位宽归一，不承诺所有算术溢出都会抛错。
- AOT checked/unchecked、VM 校验、静态借用分析和宿主 C/C++ 正确性分别描述，不能合并成完整内存安全证明。
- `std::watchdog` 可在启用后由宿主处理分配失败、显式请求、水位或超时重启；旧运行期对象不能跨重启继续使用。
- 无 GC 提供确定的拥有值释放点；硬实时仍须控制分配、执行时长、宿主调用和平台中断，反射不承诺硬实时。

## 6. 按需求选择传递方式

| 需求 | 方式 |
| --- | --- |
| 获得独立拥有值 | 普通赋值或按值传参，遵循实际类型的复制契约 |
| 只读访问并减少复制 | `T const&` 或 `T &`，来源须保持有效 |
| 修改来源 | `T mut&`，同时满足可写性和来源寿命 |
| 转移资源 | `move(&value)`，旧绑定禁止读写；完整移动后可二次声明 |
| 表示可能没有值或引用 | `Option<T>` 或 `Option<T &>` |
| 返回可处理的错误 | `Result<T,E>` 与显式传播协议 |

## 7. 常见诊断

| 诊断 | 含义与处理 |
| --- | --- |
| MGL1204 | 引用超过来源寿命；改为返回拥有值，或由调用方提供更长寿命来源 |
| MGL1205 | 访问移动、析构或释放后的来源；修正使用顺序及绑定身份 |
| 类型或重载不匹配 | 核对值/引用、可写性、数值范围及函数签名，不使用强转绕过资源契约 |
