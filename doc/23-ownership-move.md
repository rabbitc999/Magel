# 资源所有权移动

[返回文档目录](README.md) · [资源所有权移动](en/23-ownership-move.md)

`move(T mut&)` 转移原有资源。普通赋值和普通按值参数仍然复制；直接接收移动结果时，字符串、容器、Any、闭包及聚合中的拥有字段不再深拷贝。

```magel
struct Packet { String text; List<int64> values; };
int64 main() {
    Packet source;
    source.text = "payload";
    source.values.push(42);
    Packet result = move(&source);
    Packet source;
    source.text = "next";
    println("{} {}", result.text, result.values[0]);
    return 0;
}
```

移动只求值一次来源引用，接收原有句柄和存储槽，随后清空源存储并结束源值生命周期。移动期间不调用源值的 `close` / `drop`，接收方最终负责清理。用户不能再依赖旧版移动时触发析构的副作用；需要立即关闭外部资源时显式调用相应的关闭接口。

源值移动后禁止读取、写入或重新绑定；须重新声明新的同名变量后使用。标量也遵守移动后读取和重复移动检查。完整移动后的同名重新定义仍然允许，但所有到达声明的路径都必须完成移动；仅移动字段或仅部分分支移动不满足条件。部分字段移动后，未重叠字段仍可使用，不能把完整聚合当有效值读取。

移动保留引用字段的借用约束，不延长引用目标的寿命。静态检查覆盖编译器能够跟踪的变量、字段、别名和控制流；不承诺跟踪原始内存操作或任意外部宿主行为。聚合的运行期生命周期标记继续防止重复移动与重复析构。

文件与进程句柄可以转移，不通过复制获得外部资源。数组本身、无具体布局的接口值、不透明宿主类型仍不支持直接移动；可以移动数组中的具体元素。手动 `new` 的存储块在移出其值后仍须 `delete`，删除旧存储不会销毁已交给接收方的资源。

验证使用原始槽的身份对比，确认字符串、List、Map、Set、Any 和闭包的移动结果保持原句柄；结合析构计数、嵌套字段、返回链、丢弃结果、自移动赋值、循环、重新定义、文件写入、解释执行、AOT 和 MCU 回归检查资源只由最终所有者释放。

## fn 捕获与移动闭包

外部局部变量默认按 `const&` 捕获，`fn const(...)` 与默认写法等价：能看到来源的新值，但不能修改来源。`fn mut(...)` 按 `mut&` 捕获并允许写回。`fn copy(...)` 捕获可修改的独立副本；`fn move(...)` 把来源的拥有值移入闭包，原绑定禁止读写，须重新声明新的同名变量后使用。复制闭包会复制内部拥有状态，引用捕获仍指向同一来源。按引用捕获不得超出来源寿命；拥有捕获仅在其中不包含短寿命引用时可以返回。捕获列表写作 `fn copy[a, b] mut[c] const[d] move[e](int64 x) { ... }`，未列出的外部局部变量默认按 `const&` 捕获；列表后可追加一个默认方式，如 `fn copy[a, b] mut(int64 x)` 表示其余变量按 `mut&` 捕获。默认方式只能声明一次，`copy[a, b] mut const(...)` 会报错。

```magel
int64 n = 1;
auto read = int64 fn() { n };
auto write = int64 fn mut(int64 x) { n += x; return n; };
auto counter = int64 fn copy[n]() { n += 1; return n; };
n = 10;
assert(read() == 10);
assert(write(1) == 11);
assert(counter() == 2);
auto transferred = int64 fn move[n]() { n += 1; return n; };
int64 n = 20;
assert(transferred() == 12);
assert(n == 20);
```

列表中重复的名称、不存在的变量、与形参重名的变量，以及对只读来源的 `mut` / `move` 捕获会被拒绝。显式列表中的变量即使未在函数体使用也会捕获。捕获的是整个变量；copy/move 一个引用值不会取得其所指对象的所有权，也不会延长所指对象的寿命。全局变量的未限定直接访问仍使用全局存储；需要快照时在列表中显式列出。数组值需先转换为容器或显式引用。文件和进程句柄可 move 捕获，无法复制；复制包含这些句柄的闭包会被拒绝。

## match 区间迁移

match 仅接受左闭右开 `[a,b)` 与闭区间 `[a,b]`；`(a,b)` 和 `(a,b]` 不再支持。整数、浮点及字符串遵守同一规则。整数旧开区间可按离散端点调整，浮点和字符串需要左开条件时使用守卫或 if/elif。普通元组表达式保持原有语义。

## for-in 整数区间

`for (uint8 x in [0,255]) { ... }` 依次产生 0 到 255，共 256 项；`[0,255)` 不包含 255。支持 int8/uint8/int16/uint16/int32/uint32/int64/uint64。省略变量类型时按端点整型推导，普通整数字面量默认 int64。

区间在内部表示为惰性 `Iterator<T>`，直接复用 for-in 的迭代协议，不创建列表。两个端点从左到右各求值一次，并且两个端点都必须在 T 的取值范围内，包括半开区间的上端点。常量错误在编译期拒绝，动态端点在循环前检查。int8 的范围是 -128..127，所以 `for(int8 x in [0,255])` 会报错。反向区间 a>b 报错；[a,a) 是空区间，[a,a] 恰好产生一项。

闭区间到达上界后直接结束，不计算“最大整数 + 1”，因此 uint8 255 和 uint64 18446744073709551615 均可作为合法闭上界。循环变量是每轮取得的值，修改它不改变内部迭代进度；break、continue、返回与 fn 捕获沿用现有规则。


## 带值退出

显式 `yield i;` 优先移动接收值表达式内部的可写局部变量，外部变量复制；临时结果直接接管。存在清理回调时保留独立结果供回调访问来源。详见[带值退出的移动与清理](04-language-reference.md#带值退出的移动与清理)。
