# 第 1 章 第一个程序

万事开头难，但这一章只干三件事：把工具装好、跑出一行字、看懂这行字是怎么来的。

读完这一章，你会有第一个能跑的程序，也会知道「出错」在 Magel 里长什么样——
后者比前者重要，因为接下来每一章你都会用到它。

---

## 1.1 把工具装好

Magel 只有**一个**命令行程序，叫 `magel`，解释、编译、建工程、跑测试全在它里面。
装它有两条路。

**这条路最短：用发布包。** 拿到 `dist/magel-<版本>-<平台>-<架构>.tar.gz`，解开，
把里面的 `bin/` 加进 PATH，就完事了。

**这条路最全：从源码构建。** 适合想改编译器的人，也适合想看清内部的人：

```sh
sh gen.sh      # 用 IELR 从 magel.gram 生成前端
make           # 构建 magel 与 libparser.a
```

`gen.sh` 需要一份 [ParseEngine](https://github.com/rabbitc999/ParseEngine) 文法生成器，
细节见[快速开始](../../doc/01-quickstart.md#1-安装)，这里不展开。

装完了，敲一句：

```sh
magel help
```

屏幕上滚出一大串用法，就说明装好了。**先别急着读完那串帮助**——那是给有经验的人查的，
跟着这本书走，你会一个个认识里面的选项。

> **Windows 用户注意**：程序名是 `magel.exe`。在 Git Bash / MSYS 里写 `./magel`
> 能自动找到 `magel.exe`；光写 `magel` 会去 PATH 里找，可能找到的不是你当前目录这一份。
> 本书后文一律写 `magel`，你自己敲的时候按环境补上 `./`。

## 1.2 Hello, Magel

新建一个文件 `hello.mgl`，内容如下：

```magel
int64 main()
{
    println("Hello, Magel!");
    return 0;
}
```

```text
Hello, Magel!
```

然后运行它：

```sh
magel run hello.mgl
```

屏幕上出现 `Hello, Magel!`，第一个程序就成了。

`magel run` 这个写法看着啰嗦，其实 `run` 是可以省的——直接

```sh
magel hello.mgl
```

效果一样。但本书会一直写 `magel run`，因为**把场景写出来**在人多的时候少很多误会：
`magel hello.mgl Alice` 和 `magel run hello.mgl Alice` 是同一件事，
但 `magel check hello.mgl` 完全是另一件事。

---

## 1.3 逐行看懂它

就三行，一行一行来。

**第一行：`int64 main() {`**

程序从哪里开始跑？从 `main` 开始。这个名字是**定死的**，不能改成 `Main`、`start`
或者别的什么。前面的 `int64` 是它返回的东西的类型，`()` 里现在空着，意思是它不接收参数。

`int64` 是一种整数类型：能装 64 位的有符号整数，大概正负九百多万亿。
为什么入口要返回一个整数？因为操作系统想看它：返回 `0` 表示「正常结束」。
你在终端里看到的 `echo $?`，读的就是这个值。

**第二行：`println("Hello, Magel!");`**

`println` 是「打印一行」的意思：把括号里的东西写到屏幕上，末尾自动换行。
它是 Magel 核心库里最常用的函数，不用 `import` 就能用。

行尾那个 `;` 是分号，表示**这句话说完了**。跟 C、Java 一样。

**第三行：`return 0;`**

告诉操作系统「我正常结束了」，然后交还控制权。

**最后的花括号 `}`** 是 `main` 的结尾。

看出来了吗——花括号划范围，分号断句，这和 C 系语言一模一样。
这是 Magel **刻意**这么做的：你已经会的东西，它不想让你重学一遍。

## 1.4 `run` 和 `check`

现在故意把程序弄坏一次，看看会发生什么。把第二行末尾的分号删掉：

<!-- fail -->
```magel
int64 main()
{
    int64 x = 1
    return 0;
}
```

再跑：

```text
语法错误：hello.mgl 第 3 行第 5 列：期望 条件(if) / 自增(++) / 自减(--) / 加号(+) 等 44 个之一，实际是 返回(return)
   |
 3 |     return 0;
   |     ~~~~~~
```

三件事值得注意：

- 它告诉你**第 3 行第 5 列**，还把出问题的那段源码抄给你、底下画上波浪线。
  第 1 行少了个分号，报的却是第 3 行——这是**解析器在往后看**：它读完第 2 行
  还在等一个分号，结果等来了 `return`，于是「在 `return` 这里」断了。
  看到报错位置和你以为的不一致时，先看**报错位置的前面**。
- 内部记号名被翻译成了人话：`条件(if)`、`返回(return)`。你没看错，就是中文。
  报错语言跟着系统走，可以用 `magel lang en` 或环境变量 `MAGEL_LANG` 换掉。
- 那句「等 44 个之一」说了它在等什么。这种话现在看不懂没关系，
  以后你写多了，一眼就知道是「这里少了个东西」。

**重要**：这个错误是**编译期**就报出来的，程序一个字符都没执行。
这就是 Magel 和其他很多语言不同的地方——**能编译期拦住的，绝不放到运行期**。

如果你只想检查代码写没写对、不想真的跑它，用：

```sh
magel check hello.mgl
```

`check` 做前两步（预处理、解析与类型检查），不执行、也不产出文件。
写代码的时候这个命令用得比 `run` 还多：**先 check 再 run**，
能省掉很多「跑到一半才发现写错了」的时间。

> 还有个更细的用法：`magel check hello.mgl json`，输出机器可读的 JSON 诊断。
> 这是给编辑器插件用的，平时不用管。

## 1.5 那行字背后发生了什么

`magel run` 看着像「执行脚本」，其实它在一个进程里做完了四件事：

1. **预处理** —— 处理 `%include`、`%define`、`%if` 这类指令（第 19 章讲）；
2. **解析与类型检查** —— 语法、类型、引用的生命周期都在这里查，不通过就不执行；
3. **降级为四元式** —— 把程序翻译成虚拟机认识的中间表示；
4. **解释执行** —— 在当前进程里跑起来。

前三步就是「编译」，第四步才是「执行」。把 `run` 换成别的场景词，
前三步是一样的，只是最后一步换了形态：

| 你想 | 命令 |
| --- | --- |
| 直接跑起来 | `magel run src/main.mgl` |
| 只检查、不跑 | `magel check src/main.mgl` |
| 导出字节码 `.svmb` | `magel svmb src/main.mgl out build/app` |
| 导出本地可执行程序 | `magel aot src/main.mgl out build/app.exe` |

第四种（AOT）会把程序真的编译成本地机器码，得到一个不依赖 `magel` 的可执行文件。
这三条路的区别在第 22 章讲；现在你只要知道：**同一份源码，可以有好几种走法**。

## 1.6 小结

这一章你认识了：

- 入口函数固定叫 `main`，返回 `int64` 或 `void`；`void main` 正常完成时退出码为 0，panic 仍失败；
- `println(...)` 打印一行，来自核心库，不用 import；
- 分号断句、花括号划范围，和 C 系语言一样；
- `magel run` 跑，`magel check` 只查；
- 报错会给出**行列位置**和**画了波浪线的源码**，而且大多在编译期就报出来了。

还有一件事本章没讲：`println` 为什么不用 `import`？因为它属于**核心模块 `lang`**，
而 `lang` 是自动加载的。别的模块就没这个待遇了，第 18 章会讲清楚。
