# 第 14 章 泛型

第 13 章的接口，解决的是「一个函数吃多种类型」——但它靠的是**运行期**的胖引用和类型号，
每调一次都有分派开销。

这一章的**泛型**解决同一个问题，思路完全不同：**在编译期**为每一种用到的类型，
分别生成一份专门的代码。跑起来没有分派，因为它压根就是一开头就定死的。

先看它要治什么病。

---

## 14.1 问题：换一种类型，逻辑就得抄一遍

写一个「谁大取谁」的函数。整数版：

```magel
int64 maxOf(int64 a, int64 b)
{
    if (a > b)
    {
        return a;
    }
    return b;
}
```

字符串也想要一个——逻辑一字不差，只有类型不同：

<!-- no-run -->
```magel
String maxOf(String a, String b)
{
    if (a > b)
    {
        return a;
    }
    return b;
}
```

`int64`、`float64`、`String`……每加一种类型就得抄一份。用第 4 章的重载能跑，
但你心里清楚：**这三份代码长得一模一样，只是类型不同。** 类型之间应该有办法复用。

---

## 14.2 泛型函数：把「类型」也变成参数

泛型的写法很简单：在函数名的**尖括号**里声明一个类型参数 `T`，
然后**在原本写类型的地方写 `T`**。

```magel
T maxOf<T>(T a, T b)
{
    if (a > b)
    {
        return a;
    }
    return b;
}

int64 main()
{
    println("{}", maxOf(3, 9));
    println("{}", maxOf("apple", "pear"));
    return 0;
}
```

```text
9
pear
```

`T` 是一个**占位符**，代表「先不定，等调用时再说」的类型：

- `maxOf(3, 9)` —— 编译器一看实参是 `int64`，就把 `T` 当成 `int64`；
- `maxOf("apple", "pear")` —— 这次 `T` 是 `String`。

**一个定义，两种类型。** 加第三种也不用改 `maxOf` 一个字。

> 调用时 `T` 是怎么定下来的？靠**实参推导**——编译器看实参是什么类型，
> 就把 `T` 绑成什么类型。

---

## 14.3 显式写出来，或者让编译器推

推导不是每次都行。你可以把类型实参**显式写出来**，写法是把类型放在函数名后的尖括号里：

```magel
T maxOf<T>(T a, T b)
{
    if (a > b)
    {
        return a;
    }
    return b;
}

int64 main()
{
    println("{}", maxOf<int64>(3, 9));
    println("{}", maxOf<String>("apple", "pear"));
    return 0;
}
```

```text
9
pear
```

什么时候必须显式？**实参推不出唯一答案的时候。** 比如 `int64` 和 `float64` 混着喂：

<!-- fail -->
```magel
T maxOf<T>(T a, T b)
{
    if (a > b)
    {
        return a;
    }
    return b;
}

int64 main()
{
    println("{}", maxOf(1, 2.0));
    return 0;
}
```

报错直接点名：

```text
magel：泛型函数 maxOf 的类型实参推导冲突，请显式指定类型实参
note: 第 2 个实参实际为 float64，形参模式为 ...
```

`1` 是 `int64`、`2.0` 是 `float64`，编译器推不出 `T` 该是哪一个——**Magel 不做隐式转换
（第 3 章）**，所以它宁可停下来让你说清楚，也不自作主张。
想让这个调用成立，就写 `maxOf<float64>(1.0, 2.0)`（注意 `1` 也要改成 `1.0`，
`float64` 之间才谈得上比较）。

## 14.4 泛型结构体

结构体也能带类型参数。声明的时候在名字后写 `<>`，字段就能用这些参数当类型：

```magel
struct Duo<T, U>
{
    T first;
    U second;
};

int64 main()
{
    Duo<int64, String> d;
    d.first = 1;
    d.second = "a";
    println("{} {}", d.first, d.second);
    return 0;
}
```

```text
1 a
```

`Duo<T, U>` 要两个类型参数。`Duo<int64, String>` 是一个「第一格是整数、
第二格是字符串」的结构。`Duo<String, int64>` 又是另一个。

> **一个坑**：别给泛型起名 `Pair`。`Pair` 是标准库自带的 `Pair`（随 `lang`
> 自动加载，不用 import），你再声明一个同名的泛型，会报
> 「泛型：重复的泛型声明 Pair」——那个报错没提「和标准库撞了」，容易懵。

泛型结构体的方法也能用 `T`：

```magel
struct Box<T>
{
    T value;
    T get()
    {
        return value;
    }
    void put(T v)
    {
        value = v;
    }
};

int64 main()
{
    Box<int64> b;
    b.put(41);
    println("{}", b.get());
    Box<String> s;
    s.put("hi");
    println("{}", s.get());
    return 0;
}
```

```text
41
hi
```

`Box<int64>` 和 `Box<String>` 各自有一份 `put` / `get`，参数和返回值都变成了具体的类型。

## 14.5 约束：给类型参数提要求

`maxOf<T>` 里用了 `a > b`。这要求 `T` 支持比大小——如果你拿一个没有 `>` 的结构体
去实例化，它会报错。与其等报错，不如**提前声明这个要求**。

约束写在类型参数后面，用冒号接一个接口（第 13 章的接口）：

```magel
interface Valued
{
    int64 value();
};

struct Num: Valued
{
    int64 n;
    int64 value()
    {
        return n;
    }
};

int64 read_value<T: Valued>(T item)
{
    return item.value();
}

int64 main()
{
    Num x;
    x.n = 42;
    println("{}", read_value(x));
    return 0;
}
```

```text
42
```

`<T: Valued>` 读作「`T` 必须是实现了 `Valued` 的类型」。有了这条，函数体里就能放心地
调 `item.value()`——编译器知道 `T` 一定有这个方法。多个约束用逗号隔开：
`<T: A, U: B>`。

约束把「报错时机」提前了。拿一个没实现 `Valued` 的类型去调，编译器立刻拦下：

<!-- fail -->
```magel
interface Valued
{
    int64 value();
};

int64 read_value<T: Valued>(T item)
{
    return item.value();
}

int64 main()
{
    println("{}", read_value(3));
    return 0;
}
```

```text
magel：read_value 的类型实参 int64 未实现接口 Valued
```

一句话说清：**约束是写给编译器看的承诺，它保证函数体里那些方法一定存在。**

## 14.6 单态化：编译期展开，运行期零开销

泛型最有意思的地方，是它**根本不存在于运行期**。

编译器在编译时，为每个**实际用到的**类型实参，生成一份专门的函数/结构体：
`maxOf<int64>` 编译出一份只处理 `int64` 的代码，`maxOf<String>` 编译出另一份。
这个做法叫**单态化**（monomorphization）——「单一形态化」。

三个直接后果：

1. **没有运行期分派。** 调用 `maxOf(3, 9)` 和调用一个手写的 `maxOf(int64, int64)`
   一样快，机器码是同一份；这跟第 13 章的接口胖引用完全不同（那个要查类型号）。
2. **泛型代码的检查发生在实例化时。** `maxOf<T>` 的函数体里写着 `a > b`，
   编译器在**没看到**具体类型之前不会去挑它的毛病；等你拿一个不支持 `>` 的类型来实例化，
   它才报错——而且报的是**那个实例**的错：

   <!-- fail -->
   ```magel
T twiceOf<T>(T v)
{
    return v + v;
}

struct P
{
    int64 x;
};

int64 main()
{
    P p;
    p.x = 1;
    println("{}", twiceOf(p).x);
    return 0;
}
```

   ```text
   magel：没有匹配的运算符接口实现：P + P（由左操作数实现 Add<R,T> 这类左接口，
   或由右操作数实现 RightAdd<R,T> 这类右接口）；不会偷偷按数值算
   ```

   `twiceOf<int64>` 和 `twiceOf<String>` 都没问题（整数 `+` 整数、字符串 `+` 字符串），
   只有 `twiceOf<P>` 这一份不行。

3. **代码会变大。** 每个实例都是一份独立的机器码，用一百种类型就生成一百份。
   这是泛型的代价，换来的是运行期的干净。

> 顺带一提：`Pair<K, V>`（14.4 节提过的那个）本身就是泛型结构体——
> 标准库也在用同一套机制。

## 14.7 默认类型参数

类型参数可以有**默认值**，写在参数名后面用 `=` 接：

<!-- no-run -->
```magel
struct Wrap<T, U = T>
{
    T a;
    U b;
};
```

`Wrap<int64>` 会写成 `Wrap<int64, int64>`——`U` 缺省就跟着 `T` 走。
默认值可以引用**前面**的参数（`U = T` 合法），但不能引用后面的、也不能是自己。

> 默认类型参数在初学阶段基本用不到，先把 14.2–14.6 吃透。这一节只是让你在别人的代码里
> 见到 `struct Foo<T, U = T>` 时知道那是什么意思。

## 14.8 接口还是泛型？

这两个都能「一个函数吃多种类型」，怎么选？看一遍这张表：

| | 接口（第 13 章） | 泛型（本章） |
| --- | --- | --- |
| 何时定类型 | **运行期** | **编译期** |
| 开销 | 胖引用 + 类型号分派 | 无（代码已展开） |
| 代价 | 每次调用有分派成本 | 代码体积变大 |
| 怎么用 | 类型在运行期才知道（如从容器里取） | 类型在编译期就能定 |
| 共同点 | 用接口做约束（`<T: Valued>`）能结合起来 | 同左 |

**经验法则**：

- 编译期就知道类型 → **泛型**；运行期才定 → **接口**。
- 两者能合起来用：泛型加约束 `<T: Shape>` 就是「泛型 + 接口」，既零开销、
  又能调接口方法。

---

### 编译期整数参数

泛型支持 `N: int64` 等整数泛型参数，长度参与单态化，不能传入运行期变量。结构体的一维和二维定长数组字段使用这些常量确定布局。

<!-- verify-book -->
```magel
struct Buffer<T, N: int64>
{
    T data[N];
    int64 len()
    {
        return N;
    }
};
int64 main()
{
    Buffer<int64, 4> buffer;
    buffer.data[0] = 7;
    println("{} {}", buffer.len(), buffer.data[0]);
    return 0;
}
```

```text
4 7
```

`Buffer<int64,4>` 与 `Buffer<int64,8>` 是不同实例。二维矩阵同理：

<!-- no-run -->
```magel
struct Matrix<T, rows: int64, cols: int64>
{
    T data[rows][cols];
};
```

长度可以有默认值，仍须是可在编译期求值的 int64 常量；运行期长度继续用 `T a[] = new[n]`。

### 关联类型

接口体内的 `type Item;` 声明关联类型，实现者用 `type Item = T;` 提供具体类型，受约束泛型可以写 `C.Item`。

<!-- verify-book -->
```magel
interface Container
{
    type Item;
    Item get(int64 index);
};
struct Numbers: Container
{
    type Item = int64;
    Item get(int64 index)
    {
        return index + 10;
    }
};
C.Item first<C: Container>(C value)
{
    return value.get(0);
}
int64 main()
{
    Numbers numbers;
    println("{}", first<Numbers>(numbers));
    return 0;
}
```

```text
10
```

接口内是关联类型产生式，模块层的 `type` 仍是类型别名，原有类型参数 `<T: Valued>` 保持可用。

### 泛型返回控制表达式

返回块、`if`、`match` 和 `loop` 同样可以使用类型参数 T。具体类型确定后，编译器再按该类型检查每条结果路径。

<!-- verify-book -->
```magel
T fromLocal<T>(T value)
{
    return
    {
        T local = value;
        yield local;
    };
}

T chooseValue<T>(bool first, T left, T right)
{
    return if (first)
    {
        T local = left;
        yield local;
    }
    else
    {
        yield right;
    };
}

int64 main()
{
    String word = "generic";
    String copied = fromLocal<String>(word);
    int64 number = chooseValue<int64>(false, 4, 9);
    println("{} {} {}", word, copied, number);
    return 0;
}
```

```text
generic generic 9
```

`local` 在值表达式内部，通过 `break` 隐式移动；`right` 在表达式外部，按值复制。函数形参本身也是调用者值的副本，所以这里不会消耗调用者的 `word`。泛型不会取消分支类型一致、生命周期或清理检查，返回引用也不能指向已经退出的局部对象。


## 14.9 小结

| 你会了 | 关键点 |
| --- | --- |
| 泛型函数 | `T maxOf<T>(T a, T b)`，类型参数写在名字后 |
| 调用 | 可推导 `maxOf(3, 9)`，可显式 `maxOf<int64>(3, 9)` |
| 泛型结构体 | `struct Duo<T, U> { T first; U second; }` |
| 约束 | `<T: Valued>`，保证函数体能调接口方法 |
| 单态化 | 编译期按类型实参各生成一份，运行期无分派开销 |
| 报错时机 | 约束不满足 → 调用处报；无约束泛型的体 → 实例化时报 |
| 命名坑 | 别用标准库已占的泛型名（如 `Pair`） |
| 默认类型参数 | `<T, U = T>`（进阶，先了解） |
