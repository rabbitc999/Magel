# 附录 A 常见错误速查

学一门语言，一半时间花在「看懂报错」上。这份附录把本书撰写过程中**真跑出来**的
常见报错收在一起：每条都写清了**它长什么样**、**你为什么踩到**、**怎么改**。

> 这里的每一条消息都是 **Magel 1.0.0** 工具链的真实输出（中文本地化）。
> 带 `<!-- fail -->` 标记的代码块会在本书的校验脚本里**每次都被重跑一遍**，
> 所以它们不会随着工具链演进而失真。

---

## A.1 报错的三种长相

Magel 的报错分三类，看**开头几个字**就能分清：

| 开头 | 是哪一类 | 什么时候出现 |
| --- | --- | --- |
| `magel：……` | **编译期错误**（语义检查） | 运行之前，代码「含义不对」 |
| `语法错误：文件 第 行第 列：……` | **语法错误** | 运行之前，代码「话都说不通」 |
| `magel：运行期错误：……` | **运行期错误** | 程序跑到那一句才炸 |

编译期错误和语法错误都**不会生成程序**，改好再跑就行。运行期错误说明程序编过了、
跑起来了，但执行到某一步出了事（除零、越界、`unwrap` 空值……），后面还会跟着
`出错位置` 和一段 `调用栈（外 → 内）`，告诉你**是哪一行、哪个函数**出的事。

一个真实例子，`1 / 0` 跑出来的样子：

<!-- fail -->
```magel
int64 main()
{
    int64 a = 1;
    int64 b = 0;
    println("{}", a / b);
    return 0;
}
```

```text
magel：运行期错误：整数除零
出错位置：hello.mgl:4（main）
调用栈（外 → 内）：
  main  hello.mgl:4 [thread 0 coroutine 0 ip 12]
```

从上往下读：先是「整数除零」，再是出错的行号，最后是一份调用栈——
`调用栈（外 → 内）` 意思是**从最外层往里读**，最后一行是炸掉的那一层。

**诊断码。** 一部分编译期错误带一个 `[MGLxxxx]` 编号（比如下一节的 `[MGL1204]`）。
编号是稳定的，遇到没见过的错误可以把编号拿去官方文档里搜。

## A.2 编译期错误速查

这是你会遇到最多的一类。按「你可能写下的东西」排序：

| 现象 | 真实消息 | 怎么办 |
| --- | --- | --- |
| 用没声明的变量 | `magel：引用了没声明的变量：y` | 检查拼写；变量必须先声明再用 |
| 调没定义的函数 | `magel：调用了没定义的函数：nosuch` | 名字拼错，或者忘了 `import` |
| 同一个块里重名 | `magel：同一个块里不能重复声明：x（要遮蔽外层变量就在内层块里声明）` | 换名字；想遮蔽就用内层块 |
| 给 `const` 赋值 | `magel：不可变变量（const）不能再赋值：LIMIT` | 去掉 `const`，或不该在这里改 |
| 类型对不上（赋值/返回/传参） | `magel：不能隐式转换：String -> int64（请显式强转）` | 见下面 A.2.1 |
| 整数字面量超出目标范围 | `magel：整数字面量 200 超出 int8 的取值范围（-128..127）` | 换类型，或换成范围内的值（见 A.2.2） |
| `if` 条件不是布尔 | `magel：if 条件必须是 bool，现在给的是 int64（数值条件请显式写成 `(bool)值` 或比较表达式）` | 写比较表达式，别拿数字当布尔 |
| 实参个数/类型对不上 | `magel：调用 函数 f 找不到匹配的重载：(int64, int64, int64)；没有参数类型能对上的重载（候选：f）` | 数实参个数；看类型是否精确对上 |
| 接口没实现完 | `magel：struct Circle 实现了接口 Shape，但没有完全实现：area() -> int64（接口要求同名、同返回类型、同形参类型；一个都不能少）` | 把接口里的方法补全，签名一字不差 |
| `match` 漏了分支 | `magel：enum match 必须覆盖所有变体或提供 `_` 兜底分支；缺少：Color::Green` | 补上缺的变体，或加 `_ =>` 兜底 |
| 自定义泛型名撞了内置 | `magel: generics: 重复的泛型声明 Pair` | 换个名字（内置有 `Pair`，改叫 `Duo` / `Entry` 之类） |
| 找不到模块 | `magel：模块：找不到模块 no_such_module（需要 no_such_module.mgl）` | 检查 `import` 的名字与文件是否在同目录 |
| 引用声明没初始化 | `magel：引用声明必须初始化，缺省值请使用 Option<T mut&>` | 引用必须当场绑定；可能为空就用 `Option<T mut&>` |
| 只读引用被写入 | `magel：只读引用（`T const&`）不能写入元素` | 改用 `T mut&` |
| 悬垂引用（返回局部引用） | `magel：[MGL1204] 返回值中的引用不能超过局部来源的生命周期（int64 mut&，所属类型 ，来源 local）` | 别把指向局部变量的引用交出去 |
| 引用已被释放还在用 | `magel：[MGL1205] 借用来源已释放，不能继续访问：表达式` | 检查 `Drop` / 作用域，别在对象没了以后还用它 |

### A.2.1 「不能隐式转换」——最高频的一条

九成的类型报错都是这一句。先记住第 3 章 3.8 节的规矩：
**Magel 只放行「装得下」的方向**。下面这几种会自动放行（不用签字）：

| 方向 | 例子 |
| --- | --- |
| 同符号整型变宽 | `int8 → int64`、`int32 → int64`、`uint8 → uint32` |
| 无符号 → **更宽的**有符号 | `uint8 → int32`、`uint32 → int64` |
| 整型 → 浮点 | `int64 → float64`、`int32 → float32` |
| 浮点变宽 | `float32 → float64` |

反方向一律要**显式强转** `(目标类型)值`。最常见的四种：

<!-- fail -->
```magel
int64 main()
{
    int64 big = 70000;
    int32 small = big;
    // 缩窄：位宽变小
    println("{}", small);
    return 0;
}
```

```text
magel：不能隐式转换：int64 -> int32（请显式强转）
```

- **缩窄**（位宽变小）：`int64 → int32`、`float64 → float32`、`uint8 → int8` → 写 `(int32)big`
- **有符号 → 无符号**：`int32 → uint32`、`int64 → uint64`（目标更宽也不行，负数塞不进去）→ 写 `(uint32)x`
- **跨大类**：`float64 → int64`、`char`/`bool` ↔ `int64` → 写 `(int64)f`
- **浮点字面量**：`float32 f = 1.5;` 里的 `1.5` 是 `float64`，往更窄的 `float32` 放也要签字 → `(float32)1.5`

> **`+` 号在谁身上，谁就有错。** 读这条报错只要看箭头两边：
> 左边是「你给的」，右边是「它想要的」，改左边（强转）或者右边（换类型）都行。

### A.2.2 「整数字面量超出取值范围」

这是「字面量落进槽位」时**独立的**一道检查——十进制字面量的值装不进目标整型就报错：

<!-- fail -->
```magel
int64 main()
{
    uint8 b = 256;
    // uint8 只到 255
    return 0;
}
```

```text
magel：整数字面量 256 超出 uint8 的取值范围（0..255）
```

规矩（第 3 章 3.10 节）：

- `uint8 b = 255;` ✅（在 `0..255` 里）、`int16 s = -300;` ✅（在 `-32768..32767` 里）；
- `uint8 b = 256;` ❌、`int8 x = 200;` ❌ —— **不再静默回绕**；
- `0x` / `b` 前缀的字面量按**位模式**放行（`int8 x = 0xFF;` 得到 `-1`），不做范围检查；
- **显式强转不走这条检查**：`(uint8)256` 得到 `0`，是你签字的结果。

### A.2.3 引用相关的错，多在「生命周期」上

引用一共就两类错，认清就能改：

**第一类：引用没绑定就声明。** Magel 没有空引用：

<!-- fail -->
```magel
int64 main()
{
    int64 mut& r = 5;
    // 引用要从对象身上取地址，不能绑字面量
    return 0;
}
```

```text
magel：不能隐式转换：int64 -> int64 mut&（请显式强转）
```

改成绑定一个**确实存在**的对象：`int64 x = 5; int64 mut& r = &x;`。

**第二类：引用活得比目标久。** 编译期就会拦：

<!-- fail -->
```magel
int64 main()
{
    int64 mut& r;
    println("{}", r);
    return 0;
}
```

```text
magel：引用声明必须初始化，缺省值请使用 Option<T mut&>
```

把指向局部变量的引用**返回出去**，报的是 `[MGL1204]`：

```text
magel：[MGL1204] 返回值中的引用不能超过局部来源的生命周期（int64 mut&，所属类型 ，来源 local）
```

规矩只有一条：**来源必须比引用活得久**。来源是参数、是调用方给的，就安全；
来源是本函数的局部变量，就不行。详细展开见[第 7 章](07-引用.md)。

## A.3 语法错误速查

语法错误长这样：`语法错误：文件 第 行第 列：期望 ……，实际是 ……`，并且会画出
出错位置和一个小波浪线 `~~~~`。消息里的记号名（`条件(if)`、`分号(;)` 之类）都是中文，
照着它说的补就行，行列号也是准的。

| 现象 | 真实消息 | 怎么办 |
| --- | --- | --- |
| 语句少写分号 | `语法错误：x.mgl 第 3 行第 5 列：期望 条件(if) / 自增(++) / 自减(--) / 加号(+) 等 44 个之一，实际是 返回(return)` | 看行号，上一句末尾补 `;` |

类型声明的尾部分号是可选的：`struct`、`enum`、`interface` 在 `}` 结束，可以再写 `;`，也可以不写。不要把合法的省略分号误当成错误；普通声明、赋值、返回和 `do ... while` 的分号仍然要保留。

<!-- verify-book -->
```magel
struct Point
{
    int64 x;
    int64 y;
}

int64 main()
{
    Point point;
    println("{}", point.x);
    return 0;
}
```

```text
0
```

其它几条词法/语法坑（第 3 章 3.10 节实测过）：

| 你可能想写 | 实际会怎样 | 改成 |
| --- | --- | --- |
| `0b1010` | 词法错误（前缀是 `b`） | `b1010` |
| `1_000` | 语法错误（下划线分隔不认） | `1000` |
| `1.0F` / `1U` | 后缀必须小写 | `1.0f` / `1u` |

## A.4 运行期错误速查

运行期错误**都带 `magel：运行期错误：` 前缀**，后面跟具体原因、出错位置和调用栈。
它们不是「未定义行为」，是**明确被检查到的**错误——出问题的那一下，程序会停下来
告诉你，而不是悄悄读到垃圾数据。

| 现象 | 真实消息（首行） |
| --- | --- |
| 整数除以零 | `magel：运行期错误：整数除零` |
| 定长数组越界 | `magel：运行期错误：数组下标越界：fixed 的下标 5，长度 3` |
| `List` 越界 | `magel：运行期错误：vec 下标越界：5（长度 1）` |
| 展开空的 `Option` | `magel：运行期错误：panic：called Option.unwrap() on None` |
| 展开 `Err` 的 `Result` | `magel：运行期错误：panic：called Result.unwrap() on Err` |
| `expect` 落空 | `magel：运行期错误：panic：<你写的消息>` |
| `assert` 失败 | `magel：运行期错误：panic：<你写的消息>` |
| 主动 `panic` | `magel：运行期错误：panic：<你写的消息>` |

`unwrap` 空 `Option`，一次看清楚它长什么样：

<!-- fail -->
```magel
int64 main()
{
    Option<int64> none = None;
    println("{}", none.unwrap());
    return 0;
}
```

```text
magel：运行期错误：panic：called Option.unwrap() on None
```

> **注意区分两种「空」。** `Option<int64> none;`（**默认构造**）不是空——
> 它的 `isNone()` 是 `0`，里面装的是默认值 `0`。**真正的空**要显式写
> `Option<int64> none = None;`，这时 `isNone()` 才是 `1`。第 16 章讲过这个区别。
> 所以 `unwrap` 报错的是「`= None` 那种空」，不是随便一个 `Option` 变量。

**越界的两条消息措辞不同**（一个是数组、一个是 `List`），别以为是两种错：

```text
magel：运行期错误：数组下标越界：fixed 的下标 5，长度 3     <- 定长数组，带变量名
magel：运行期错误：vec 下标越界：5（长度 1）                <- List
```

## A.5 工具链与工程错误

| 现象 | 真实消息 | 怎么办 |
| --- | --- | --- |
| 用了注解/反射但工具链不支持 | `magel：x.mgl 第 1 行第 1 列：注解与反射功能未开启，请使用支持该能力的工具链及 --reflection` | 用带反射的构建，运行时加 `--reflection`（第 20 章） |
| 调了不存在的方法 | `magel：方法只能调在 struct 上：fooBar` | 方法名拼错，或那个类型上真没有这个方法 |
| 嵌入模式用了被禁的能力 | （编译期门禁） | 见[第 22 章](22-交付与部署.md)的 `[embedded]` 一节 |

`方法只能调在 struct 上：xxx` 这条**措辞有误导性**：它不是说「你不能在 struct 上调
方法」，而是说「你调的这个方法**没找到**」。看到它，先回去核对方法名。

反射那条同理——**不是你的代码错，是工具链没开那个功能**。
本书第 20 章的所有例子都得靠一个开了反射的工具链来跑，默认构建会直接拒绝。

## A.6 排查五步法

卡住了，按这个顺序走，八成能自己解决：

1. **看开头几个字**，定类别：`语法错误` → 语法；`magel：` → 编译期；
   `magel：运行期错误：` → 运行期。三类改法完全不同。
2. **语法/编译期：看行号，往上一行找。** 报错行常常只是「被发现」的地方，
   真正的问题往往在上一行（典型的：少分号）。
3. **类型报错：读箭头。** `不能隐式转换：A -> B` 就是「你给了 A，它要 B」。
   要么强转左边，要么把右边换成 A。
4. **引用报错：问「来源是谁」。** 来源是本函数的局部变量吗？是就错在这；
   来源是参数、是更长命的对象吗？那就是别的地方。
5. **还是不懂：拿消息关键词去查。** 消息里的中文（比如「只读引用」）和诊断码
   （`[MGL1204]`）都能拿去文档或代码里搜——这套消息是刻意写清楚给人看的。
