# 第 16 章 错误处理

前面十几章，代码都假定「一切顺利」：输入是合法的、列表不是空的、除法不会除以零。
真实程序里这些假定经常不成立。这一章讲 Magel 怎么处理「事情没按预期走」。

先说结论：**Magel 没有异常**。没有 `try` / `catch` / `throw`。出错有两条路——
**「可能空」用 `Option`、「可能失败」用 `Result`**，两者都放在**返回值**里，由调用者显式处理。

---

## 16.1 为什么不用异常

多数语言用异常：调用一个函数，它可能半路 `throw`，控制流**突然**跳到别处。
问题是你**看不出**一个函数会不会抛——签名里没写，得读文档或者读源码。

Magel 把「可能失败」这件事**写进类型里**：返回 `Option<T>` 就表示「可能没有值」，
返回 `Result<T, E>` 就表示「可能失败，且带一个原因 `E`」。**失败变成了一种普通的返回值。**

好处是你不会忘。函数签名上写着 `Option<…>`，你就知道**必须**处理「没有」的情况，
编译器会盯着你。

---

## 16.2 `Option<T>`：可能没有值

`Option<T>` 只有两种状态：`Value(v)`（有个值）或者 `None`（没有）。
拿「找第一个等于目标的元素」举例——找到了有值，没找到就是「没有」：

```magel
Option<int64> findFirst(List<int64> xs, int64 target)
{
    for (int64 x in xs)
    {
        if (x == target)
        {
            return Option<int64>::Value(x);
        }
    }
    return Option<int64>::None;
}

int64 main()
{
    List<int64> xs;
    xs.push(3);
    xs.push(7);
    println("{}", findFirst(xs, 7).isValue());
    println("{}", findFirst(xs, 9).isNone());
    println("{}", findFirst(xs, 7).unwrap());
    println("{}", findFirst(xs, 9).unwrapOr(-1));
    return 0;
}
```

```text
1
1
7
-1
```

- 造值：`Option<int64>::Value(x)`，空：`Option<int64>::None`；
- `isValue()` / `isNone()` 是 `bool`，问「有没有」；
- `unwrap()` 取值——**空的时候它会 panic**（见 16.4）；
- `unwrapOr(-1)` 取值，但空的时给个兜底值——**这是最常用的一个**。

> `Option` 和 `Result` 都属于核心模块 `lang`，**不用 `import`**，拿来就用。

### 简写：`Value(v)` / `None` 可以省掉 `Option<int64>::`

上面的例子都写了全称 `Option<int64>::Value(x)`——清楚，但啰嗦。**上下文能看出类型时，
简写也合法**：返回类型是 `Option<int64>` 的函数体里，直接写 `Value(x)` 和 `None`；
`match` 的分支模式里同样可以直接写 `Value(v)` / `None`，不用带类型前缀：

<!-- verify-book -->
```magel
Option<int64> findFirst(List<int64> xs, int64 target)
{
    for (int64 x in xs)
    {
        if (x == target)
        {
            return Value(x);
        }
    }
    return None;
}

int64 main()
{
    List<int64> xs;
    xs.push(3);
    xs.push(7);
    println("{}", findFirst(xs, 7).unwrap());
    println("{}", findFirst(xs, 9).unwrapOr(-1));
    match (findFirst(xs, 3))
    {
        Value(v) => { println("found = {}", v); }
        None => { println("no"); }
    }
    return 0;
}
```

```text
7
-1
found = 3
```

什么时候必须写全称？**编译器猜不出来的时候**——比如把变体存进一个没有目标类型的
局部变量、或者函数返回类型不是这个枚举。拿不准就写全称，它永远是对的。

## 16.3 `Result<T, E>`：可能失败，还带原因

`Option` 只说「有没有」，不说「为什么没有」。要带原因就用 `Result<T, E>`：
`Ok(v)` 表示成功、带着结果；`Err(e)` 表示失败、带着原因 `e`（`e` 可以是任意类型）。

```magel
Result<int64, String> safeDiv(int64 a, int64 b)
{
    if (b == 0)
    {
        return Result<int64, String>::Err("除以零");
    }
    return Result<int64, String>::Ok(a / b);
}

int64 main()
{
    println("{}", safeDiv(10, 2).isOk());
    println("{}", safeDiv(10, 0).isErr());
    println("{}", safeDiv(10, 2).unwrap());
    return 0;
}
```

```text
1
1
5
```

- `Ok(v)` / `Err(e)` 造两个状态；
- `isOk()` / `isErr()` 判断；`unwrap()` / `unwrapOr(…)` / `expect(…)` 取值；
- 出错原因 `E` 类型随便挑：字符串、错误码、甚至一个自己的枚举。

**`Option` 与 `Result` 的关系**：`Option<T>` 差不多就是 `Result<T, ()>`——
「失败了，但没什么可说的」。要带原因，就用 `Result`。

把两个状态都处理干净，用第 10 章的 `match`：

```magel
int64 main()
{
    Result<int64, String> r = Result<int64, String>::Err("坏了");
    match (r)
    {
        Result<int64, String>::Ok(v) =>
        {
            println("ok {}", v);
        }
        Result<int64, String>::Err(e) =>
        {
            println("err {}", e);
        }
    }
    Option<int64> o = Option<int64>::Value(3);
    match (o)
    {
        Option<int64>::Value(v) =>
        {
            println("v={}", v);
        }
        Option<int64>::None =>
        {
            println("none");
        }
    }
    return 0;
}
```

```text
err 坏了
v=3
```

`match` 是**唯一能安全取出载荷**的办法——它逼你把两个分支都写全，
不像 `unwrap` 那样偷偷 panic。

## 16.4 四个「取出来」的工具，别用错场合

拿到一个 `Option` / `Result`，想取出里面的值，有四种办法：

| 写法 | 空 / 失败时 | 什么时候用 |
| --- | --- | --- |
| `unwrap()` | **panic**，程序中止 | 你*确信*不可能是空（比如刚判过） |
| `expect("…")` | **panic**，带上你的话 | 同上，但想留一句解释 |
| `unwrapOr(fallback)` | 返回 `fallback` | 空是正常情况，兜个默认值 |
| `match` | 两个分支都走 | 想分别处理（最稳） |

`unwrap` 用错了，程序会在运行期**直接崩**：

<!-- fail -->
```magel
int64 main()
{
    Option<int64> none = Option<int64>::None;
    println("{}", none.unwrap());
    return 0;
}
```

```text
magel：运行期错误：panic：called Option.unwrap() on None
出错位置：<内建 lang>:122（__magel_match_next_59）
调用栈（外 → 内）：
  main  hello.mgl:3 [thread 0 coroutine 0 ip 40]
```

`expect` 一样会 panic，只是消息换成你写的那句：

<!-- fail -->
```magel
int64 main()
{
    Option<int64> none = Option<int64>::None;
    println("{}", none.expect("必须要有值"));
    return 0;
}
```

```text
magel：运行期错误：panic：必须要有值
```

**一句话记法**：`unwrap` / `expect` 是「**你说它不可能是空**」的赌注。
只要那份自信的来源不是**刚刚检查过**，就用 `unwrapOr` 或 `match`。

## 16.5 `?`：失败就自动往上抛

一层层写 `match` 太啰嗦。假设你要算 `half(half(n))`，每次都要检查中间结果有没有值：

<!-- no-run -->
```magel
Option<int64> quarter(int64 n)
{
    Option<int64> h = half(n);
    if (h.isNone())
    {
        return Option<int64>::None;
    }
    // 手写传播
    Option<int64> q = half(h.unwrap());
    if (q.isNone())
    {
        return Option<int64>::None;
    }
    // 又来一遍
    return q;
}
```

`?` 运算符把这个套路压成一行：**「如果没值 / 失败了，就地返回同样的空」**。

```magel
Option<int64> half(int64 n)
{
    if (n % 2 == 0)
    {
        return Option<int64>::Value(n / 2);
    }
    return Option<int64>::None;
}

Option<int64> quarter(int64 n)
{
    int64 h = half(n)?;
    return half(h);
}

int64 main()
{
    println("{}", quarter(8).unwrap());
    println("{}", quarter(4).isNone());
    println("{}", quarter(6).isNone());
    return 0;
}
```

```text
2
0
1
```

`int64 h = half(n)?;` 读作：

- `half(n)` 有值 → `?` 把值取出来赋给 `h`，继续往下；
- `half(n)` 是 `None` → **整个 `quarter` 立刻返回 `None`**，后面的代码不执行。

`?` 对 `Result` 一样管用，而且会把 `Err` 原样往上传：

```magel
Result<int64, String> safeDiv(int64 a, int64 b)
{
    if (b == 0)
    {
        return Result<int64, String>::Err("除以零");
    }
    return Result<int64, String>::Ok(a / b);
}

Result<int64, String> chain(int64 a, int64 b, int64 c)
{
    int64 q = safeDiv(a, b)?;
    return safeDiv(q, c);
}

int64 main()
{
    println("{}", chain(100, 5, 2).unwrap());
    println("{}", chain(100, 0, 2).isErr());
    return 0;
}
```

```text
10
1
```

**用 `?` 有个硬条件：所在函数的返回类型必须接受操作数的失败载荷。** 标准 Option/Result 按各自约定接收，错误类型不匹配时需显式映射。否则编译器拦下：

<!-- fail -->
```magel
Option<int64> half(int64 n)
{
    if (n % 2 == 0)
    {
        return Option<int64>::Value(n / 2);
    }
    return Option<int64>::None;
}

int64 quarter(int64 n)
{
    int64 h = half(n)?;
    return h;
}

int64 main()
{
    println("{}", quarter(8));
    return 0;
}
```

```text
magel：使用 `?` 的函数也必须返回同样的可空枚举，现在返回 int64
```

道理很简单：`?` 可能要把 `None` 往外抛，那外层函数**必须接得住**——
它得也返回 `Option<int64>`。想用 `?` 又不想让 `quarter` 变成 `Option`，是行不通的。

## 16.6 `panic` 和 `assert`：什么时候该「直接崩」

上面都是「可恢复的错误」——调用者能处理。但有些情况属于**程序写错了，不该继续跑**：
数组越界、不变量被破坏、参数是 null 级别的荒谬……这时候就该**立刻中止**，别带着坏状态往下走。

- `panic("消息")` 无条件中止，打印消息；
- `assert(条件, "消息")` 条件不成立就 panic。消息可省。

```magel
int64 mustPositive(int64 n)
{
    if (n <= 0)
    {
        panic("必须是正数");
    }
    return n;
}

int64 main()
{
    println("{}", mustPositive(5));
    return 0;
}
```

```text
5
```

`assert` 失败的样子：

<!-- fail -->
```magel
int64 main()
{
    int64 x = -1;
    assert(x > 0, "x 必须为正");
    println("不会到这");
    return 0;
}
```

```text
magel：运行期错误：panic：x 必须为正
出错位置：<内建 lang>:111（assert$bool$string）
调用栈（外 → 内）：
  main  hello.mgl:3 [thread 0 coroutine 0 ip 13]
```

**怎么选**？

| 情况 | 用什么 | 理由 |
| --- | --- | --- |
| 输入不合法、文件打不开、找不到元素 | **`Option` / `Result`** | 调用者能处理，往上交 |
| 逻辑里「绝不该发生」的事 | **`panic` / `assert`** | 发生了就是 bug，早崩早发现 |

`assert` 是**开发期**的工具：它帮你抓「我以为是这样，其实是那样」。
上线时可以保留（成本很低），也可以视情况删掉——但**别拿它处理正常业务错误**。

---

### 用户自定义传播

`?` 不限于标准库的 `Option` 和 `Result`。自定义类型也可以规定“怎样取出成功值，怎样向调用者传播失败”。这需要两端配合：操作数类型实现 `Try<T, R>`，当前函数的返回类型实现匹配的 `FromResidual<F, R>`。

先看三个类型参数各自负责什么：

| 类型参数 | 含义 | 本例中的类型 |
| --- | --- | --- |
| `T` | 成功后，`?` 表达式产生的值的类型 | `int64` |
| `R` | 失败时传递给返回类型的载荷类型 | `NoneResidual` |
| `F` | 接住失败的函数返回类型，也是 `FromResidual` 的实现类型自身 | `Option<int64>` |

`Try<T, R>` 要求提供实例方法 `TryBranch<T, R> branch()`。它把操作数拆成两种情况：`Continue(T)` 表示继续执行，`Break(R)` 表示传播失败。这里的 `Continue` 和 `Break` 是枚举变体名；`TryBranch::Break(...)` 本身不会退出函数，也不是退出循环的 `break;` 语句。真正的提前返回由 `?` 的编译器降级逻辑完成。

`FromResidual<F, R>` 则要求提供静态方法 `F fromResidual(R residual)`。它只负责把失败载荷变成完整的函数返回值。编译器依据**包含 `?` 的函数的返回类型**选择这个方法，而不是依据接收成功值的局部变量类型选择。

<!-- verify-book -->
```magel
enum Step: Try<int64, NoneResidual>
{
    Value(int64 value), Empty;
    TryBranch<int64, NoneResidual> branch()
    {
        match (self)
        {
            Step::Value(value) =>
            {
                return TryBranch<int64, NoneResidual>::Continue(value);
            }
            Step::Empty =>
            {
                return TryBranch<int64, NoneResidual>::Break(NoneResidual::None);
            }
        }
        panic("unreachable");
    }
};
Option<int64> addOne(Step step)
{
    int64 value = step?;
    return Option<int64>::Value(value + 1);
}
int64 main()
{
    println("{} {}", addOne(Step::Value(4)).unwrap(), addOne(Step::Empty).isNone());
    return 0;
}
```

```text
5 1
```

在 `Step` 的定义中，`Value(int64 value)` 保存成功值，`Empty` 表示没有值。`branch()` 将前者映射为 `TryBranch<int64, NoneResidual>::Continue(value)`，将后者映射为 `TryBranch<int64, NoneResidual>::Break(NoneResidual::None)`。`NoneResidual` 是“没有值”这个失败情况的载荷类型；它本身不是 `Option<int64>`，也没有保存成功值。

现在逐步看 `int64 value = step?;`：

1. **成功路径**：调用 `addOne(Step::Value(4))`，`step.branch()` 得到 `Continue(4)`。`step?` 的结果是里面的 `4`，类型是 `int64`，所以局部变量 `value` 得到 `4`。函数继续执行下一句，返回 `Option<int64>::Value(5)`。
2. **失败路径**：调用 `addOne(Step::Empty)`，`step.branch()` 得到 `Break(NoneResidual::None)`。编译器取出失败载荷，交给当前返回类型 `Option<int64>` 的静态 `fromResidual` 方法。该方法产生 `Option<int64>::None`；编译器保存返回结果、执行离开函数所需的作用域清理，然后立即返回。局部变量 `value` 不会完成初始化，后面的 `value + 1` 也不会执行。

标准库已经让 `Option<T>` 实现了 `FromResidual<Option<T>, NoneResidual>`，所以它能接住 `Step` 产生的失败载荷。这里不要求 `Step` 和 `Option<int64>` 是同一种类型；把两端连接起来的是完全匹配的 `NoneResidual`。

下面用伪代码表示 `addOne` 中传播的控制流；它只解释降级含义，不是另一套需要手写的 Magel 语法：

```text
拆分结果 = step.branch()              // 操作数和拆分调用各求值一次
如果拆分结果是 Continue(成功值)：
    value = 成功值
    继续执行 return Option<int64>::Value(value + 1)
如果拆分结果是 Break(失败载荷)：
    返回结果 = Option<int64>::fromResidual(失败载荷)
    执行当前函数退出路径上已登记的作用域清理
    返回 返回结果
```

因此输出第一项是 `5`，第二项是 `1`：第一次调用的 `unwrap()` 取出 `5`，第二次调用返回 `None`，`isNone()` 得到真。本书的布尔输出用 `1` 表示真、`0` 表示假。第二次调用没有执行 `unwrap()`，不会因为没有值而触发 panic。

**类型检查发生在编译期。** 编译器检查来源类型的传播协议、`branch()` 的结果类型，以及当前函数返回类型是否具有匹配的 `FromResidual<F, R>`。例如把 `addOne` 的返回类型改成 `int64`，即使某次运行传入的肯定是 `Step::Value(4)`，也不能省去失败路径的检查：`int64` 没有对应的接收协议，编译就会失败。自定义返回类型也可以实现这个协议，但 `F` 必须是该返回类型自身，`R` 必须匹配来源的失败载荷。

**清理和所有权仍按普通函数退出规则处理。** `?` 不是异常，不会跳到调用者中的某个捕获块。失败时先得到完整的返回结果，再执行当前函数退出路径上已登记的 `defer`、`Drop`、`Closeable` 等清理；成功时继续当前作用域，不会提前执行整条退出路径的清理。编译器保存必要的中间值，避免重复求值，也不会把即将失效的局部存储引用作为可安全逃逸的结果。

本例的具名变量 `step` 使用只读的 `Try.branch` 协议，`?` 不等于无条件移动操作数。需要消费所有权的传播另有 `TryMove<T, R>.intoBranch()` 协议；显式移动传播必须由来源类型提供对应实现，不能仅靠加一个 `?` 获得移动能力。

不同 `Result` 错误类型不会只因为都表示失败就自动互转，可以先用 `mapErr` 显式转换；`Option` 转 `Result` 可以用 `okOr` 或 `okOrElse` 补上错误信息。选择接收协议和转换方式时，应以实际失败载荷类型为准。

## 16.7 小结

| 你会了 | 关键点 |
| --- | --- |
| 没有异常 | 用返回值表达失败，签名上看得见 |
| `Option<T>` | `Value(v)` / `None`，`isValue` / `isNone` |
| `Result<T, E>` | `Ok(v)` / `Err(e)`，`isOk` / `isErr`，带原因 |
| 取值 | `unwrap` / `expect`（空则 panic）、`unwrapOr`（兜底）、`match`（最稳） |
| `?` | 空 / 失败就地返回；操作数实现 Try，返回类型实现对应的 FromResidual |
| `panic` | 无条件中止，用于「不该发生」 |
| `assert` | 条件不成立就 panic，抓开发期的 bug |
| 选型 | 可恢复 → `Option`/`Result`；不该发生 → `panic`/`assert` |
