# 第 6 章 值语义

从这一章开始，我们进入 Magel 与别的语言**真正分岔**的地方。

前面五章你学的东西，在 C、Java、Go、Rust 里大都能找到对应的写法和直觉。
但这一章讲的那条规则，会让你需要**改掉一些习惯**。

先不改，先看一个现象。

---

## 6.1 一个让人愣一下的例子

```magel
struct Point
{
    int64 x;
    int64 y;
};

int64 main()
{
    Point a;
    a.x = 1;
    a.y = 2;

    Point b = a;
    // 把 a 赋给 b
    b.x = 99;
    // 改 b

    println("a=({}, {}) b=({}, {})", a.x, a.y, b.x, b.y);
    return 0;
}
```

```text
a=(1, 2) b=(99, 2)
```

**改了 `b`，`a` 没变。**

如果你从 Java、Python、JavaScript 或 C# 过来，你刚才很可能在等 `a` 也跟着变成 99——
那些语言里 `b = a` 之后，两个名字指的是**同一块数据**。

如果你从 Rust 过来，你等的是**编译器报错**——那些语言里 `let b = a;` 之后 `a` 就废了。

Magel 两个都不是。它给的是第三种：

> **`Point b = a;` 把 `a` 完整地复制了一份给 `b`。两个变量从此各过各的。**

这就是**值语义**。

---

## 6.2 复制是整套的

这不是「只复制了数字、里面的东西还是共享的」。是**整套**复制：

```magel
struct Bag
{
    List<int64> items;
};

int64 main()
{
    Bag original;
    original.items.push(1);

    Bag copy = original;
    // 整只袋子复制一份，连同里面的表
    copy.items.push(2);

    println("original={} copy={}", original.items.len(), copy.items.len());
    return 0;
}
```

```text
original=1 copy=2
```

`copy.items.push(2)` 只动了 `copy` 自己那份。`original` 里的表还是只有 1 个元素。

字符串也一样：

```magel
int64 main()
{
    String original = "hello";
    String copy = original;

    copy[0] =(char)72;
    // 72 就是 'H'

    println("{} {}", original, copy);
    return 0;
}
```

```text
hello Hello
```

改 `copy` 的第一个字符，`original` 安然无恙。

**这里有个重要的推论**：结构体的字段、容器的元素、嵌套了好几层的值……
赋值时全都跟着复制。**没有「浅复制 vs 深复制」的选择题，只有一种复制：深到底。**

---

## 6.3 函数参数也是复制

第 4 章你已经见过这条规则，现在你知道它从哪来了：

```magel
struct Point
{
    int64 x;
    int64 y;
};

void shift(Point point)
{
    point.x = point.x + 10;
}

int64 main()
{
    Point a;
    a.x = 1;
    a.y = 2;

    shift(a);
    println("a=({}, {})", a.x, a.y);
    return 0;
}
```

```text
a=(1, 2)
```

`shift` 里改了 `point.x`，调用方的 `a` 一动不动。因为 `point` 是**一份副本**。

**函数改不到外面**——这是 Magel 的默认行为，不是限制。想改到外面，是**第 7 章**
要学的显式引用（`Point mut&`）。

---

## 6.4 和 Rust 的关键区别：没有「移动」

Rust 里 `let b = a;` 之后 `a` 就不能用了——值被**移动**走了。Magel 没有这回事：

**普通赋值、按值传参、`return` 返回值，都不会销毁源值。** `a` 照常可用。

那「我要把值交给别人、自己不要了」怎么办？Magel 给了你一个**显式的**操作：
`move`（6.6 节）。要点是——**它是你主动写的，不是编译器默默做的**。

这个区别看起来小，但它决定了你读代码时的心智负担：

| | Rust | Magel |
| --- | --- | --- |
| 看到 `let b = a;` | 得在脑子里算「`a` 还能用吗」 | 不用算，`a` 就是还能用 |
| 想省一次复制 | 靠移动语义自然发生 | 写 `move(&a)`，一眼能看出来 |
| 读代码时 | 要跟着所有权走 | 赋值就是复制，没有隐藏状态 |

---

## 6.5 代价：复制是要花钱的

现在讲实话。值语义不是白拿的。

**每次赋值、每次传参、每次返回，都在复制。** 一个装着一万条记录的容器、
一个几兆的缓冲区，按值传来传去就是真的在搬内存。

所以什么时候要小心？

- **大对象当参数**：函数要读一个几 MB 的结构体，别按值传。
- **循环里赋值**：`for-in` 里每轮都在复制元素（小元素无所谓，大结构体就很痛）。
- **深层嵌套的结构体**：复制是**递归到底**的，层数越多越贵。

那怎么避免？答案是第 7 章：

<!-- no-run -->
```magel
void inspect(BigData const& data)
{
    ...
}
// 只读，不复制
void update(BigData mut& data)
{
    ...
}
// 要改，不复制
```

**注意这是你主动的选择**，不是编译器偷偷帮你优化掉复制。这一点很重要：

- 你写了 `const&`，说明「我知道这里不复制」；
- 你写了按值，说明「我接受这次复制，我需要一份独立的副本」。

编译器不会在你背后做决定，所以**性能上发生了什么，读代码就能看出来**。

## 6.6 显式转移所有权：`move`

有时候你确实想要「把原有资源交给另一个值，原来的值不再使用」。Magel 把它写成一个函数：

```magel
struct Message
{
    String text;
};

int64 main()
{
    Message source;
    source.text = "hello";

    Message result = move(&source);
    println("{}", result.text);
    return 0;
}
```

```text
hello
```

`move(&source)` 做的事情，按顺序是：

1. 把 `source` 原有的资源句柄交给结果，不深拷贝资源；
2. 清空源存储并结束源值生命周期，不执行它的 `close` / `drop`；
3. 接收方取得所有权，最终由接收方执行清理。

三条规矩：

- **参数必须写 `&source`**，也就是传一个 `T mut&`。传普通值或者只读引用会编译报错。
- **移动之后不能再读 `source`**：

  <!-- fail -->
  ```magel
struct Message
{
    String text;
};

int64 main()
{
    Message source;
    source.text = "hello";
    Message result = move(&source);
    println("[{}] [{}]", source.text, result.text);
    return 0;
}
```

  ```text
  magel：[MGL1205] 借用来源已移动或销毁，不能继续访问（源对象已经销毁）：text
  ```

  要再用这个名字，须**重新声明**（如 `Type source = something;`）建立新的绑定；旧绑定禁止读写。

- **`move` 可以省去资源的深拷贝**：接收方取得原有字符串和容器的句柄，源值不能再读。需要继续使用源值时保留普通复制，临时只读访问则使用 `const&`。

> 什么时候真的需要 `move`？把一份数据「转移到别的地方」的时候，
> 比如从缓冲区里取出结果、把临时结构体的内容装进长期对象。
> 那时候用 `move` 说清楚「源不要了」，比留在那里等它被析构更明确。

---

## 6.7 为什么值得这么设计

回过头看，Magel 为这条规则付出了什么、又买到了什么。

**付出的**：多一些复制，大对象要自己记得写 `const&`。

**买到的**：

1. **没有别名共享，也就没有「谁改了它」。** 一个函数拿到的是副本，
   它不可能在你不知情的时候改掉你的数据。调试「这个值怎么变了」的时间大幅减少。
2. **不需要所有权标注、不需要生命周期参数。** 复制出来的值跟源没有任何关系，
   所以不存在「它活得比源久」的问题——第 7 章你会看到，引用才需要关心这个。
3. **容器、返回值、参数传递的行为完全一致。** 一套规则走遍全语言，
   没有「这里共享那里复制」的记忆负担。
4. **确定性释放变得自然。** 每个值有明确的归属（哪个变量、哪一层作用域），
   离开作用域就能干净地清掉——这是第 8 章。

一句话：**Magel 用「多一点复制」换「少一点你可能想不通的事」。**

---

## 6.8 小结

| 你会了 | 关键点 |
| --- | --- |
| 赋值 | `b = a` **复制整个值**，之后 `a`、`b` 互不影响 |
| 复制范围 | 深到底：字段、容器元素、字符串，全都复制 |
| 传参 | 形参是副本，函数改不到调用方 |
| 返回 | 返回值也是副本，源值照常可用 |
| 与 Rust | 没有隐式移动，普通赋值不动源值 |
| 与 Java/Python | 没有共享，`b = a` 不是「两个名字一块数据」 |
| 省复制的办法 | 显式写引用 `const&` / `mut&`（第 7 章） |
| 显式转移 | `move(&x)` = 转移资源所有权；旧绑定禁止读写，二次声明建立新绑定（`MGL1205`） |
