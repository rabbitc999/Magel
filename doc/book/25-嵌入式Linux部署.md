# 第 25 章 嵌入式 Linux 部署

嵌入式 Linux 设备提供进程、文件系统和系统运行库。Magel 使用同一份共享 VM 执行业务程序，
目标宿主由设备对应的 C++17 工具链构建。部署前需要确认处理器架构、运行库、可用内存与原生依赖。

本章说明部署流程和集成边界，不把桌面测试视为特定设备的实机验证。

## 25.1 程序与宿主分别准备

Magel 编译器解析源码、检查类型与借用、优化四元式，导出 `.svmb` 字节码。Linux 宿主加载
字节码、数据区与布局，由 `stackvm::Machine` 执行；宿主本身由目标 C/C++ 工具链构建。

```text
开发机：.mgl → 解析与检查 → 优化四元式 → .svmb / .data.bin / .layout
目标机：Linux 进程 → 加载并校验 → 绑定原生胶水 → VM 执行 → 清理并退出
```

| 源码入口 | 部署职责 |
| --- | --- |
| [library/stackvm](../../library/stackvm/) | 共享 VM 核心与独立命令行宿主 |
| [source/glue](../../source/glue/) | 标准对象、文件、网络与其他原生胶水 |
| [宿主回调示例](../../example/native-callbacks/README.md) | 注册原生接口、加载字节码及同步回调 |
| [部署说明](../06-deployment.md) | 产物、资源与执行边界 |

## 25.2 使用目标工具链构建

设备上可以直接使用本机 C++17 工具链构建 VM；开发机交叉编译时，应提供匹配目标系统的
CMake toolchain 文件，其中指定编译器、目标架构和 sysroot。以下命令中的文件路径由部署者提供：

```sh
cmake -S library/stackvm -B build/linux-vm \
    -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_TOOLCHAIN_FILE=/path/to/target-linux-toolchain.cmake
cmake --build build/linux-vm --target magel-stackvm -j4
```

主机编出的可执行文件不能仅靠复制就变成另一架构的程序。检查目标使用的 libc、C++ 运行库、
动态链接器及库版本；原生胶水和外部数据库客户端也必须匹配。反射默认同时编入编译器和 VM。

## 25.3 导出并部署程序

先在开发机验证业务程序，再导出三份配套文件：

```sh
magel svmb app.mgl out build/app
```

部署 `app.svmb`、`app.data.bin`、`app.layout`，以及程序实际读取的配置、静态资源和所需依赖。
三份执行产物来自同一次导出，更新时应作为一组替换，避免混用字节码和布局。
运行方式以目标宿主的 `--help` 为准；自定义宿主可参考回调示例中的加载流程。

字节码不包含任意操作系统服务。使用网络、文件或 SQL 时，宿主须注册对应胶水，
并提供权限、系统库和外部服务。设备使用普通 Linux 宿主；网络、线程和反射按实际构建与
应用需求启用，不另设嵌入式部署模式。

## 25.4 配置资源与生命周期

`Program` 保存执行程序，`DataArea` 保存数据与布局，`NativeRegistry` 保存原生绑定，
`Machine` 保存一轮执行状态。数据区、注册表、堆和借用的宿主资源必须在运行及回调期间有效。

按设备实际容量设置内存与指令预算。持续输出可下沉到日志接口，避免把全部输出积累在内存中。
关闭不使用的宿主功能时，核对编译器产物要求的特征位；没有编入反射的 VM 只能执行显式
`--no-reflection` 生成的对应程序。

## 25.5 错误处理与服务恢复

分别处理缺文件、字节码损坏、特征不兼容、原生绑定缺失、语言 panic 和预算超限。
宿主应记录原始诊断与退出状态，在执行结束后释放本轮程序、数据、注册表和资源。

可由 Linux 服务管理器根据退出状态重启宿主。重启进程不自动保存全局值、闭包环境或未完成事务；
需要恢复的业务状态应通过应用协议或持久存储管理。宿主 C/C++ 内存破坏仍按进程故障处理，
VM 不能保证从任意原生错误恢复。

## 25.6 在目标设备验收

先验证最小程序，再逐项测试所需文件、网络、数据库及回调。记录设备型号、CPU 架构、Linux
发行版、工具链、库版本和预算，检查正常退出、重复执行、错误诊断及资源回收。
性能与长期运行结果以该目标的实际测量为准。
