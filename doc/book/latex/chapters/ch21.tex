\chapter{与 C 互操作}
\label{ch:21}

到第 20 章为止，你的程序都活在自己的世界里。可现实中有太多东西是现成的 C 库：压缩、加密、数据库、图形、系统调用……你不可能全都重写一遍。

这一章讲怎么跨过 Magel 和 C 的边界，两个方向：

\begin{itemize}

\item Magel 调 C——用 \texttt{abi} 块调动态库里导出的函数；

\item C 调 Magel——把你的函数交给 C 的运行时。

\end{itemize}

\section{三种集成方式}

工具链支持三条路，按「需要多少 C 侧配合」排：

{\small\setlength{\tabcolsep}{4pt}
\begin{longtable}{>{\raggedright\arraybackslash}p{\dimexpr 0.267\linewidth-2\tabcolsep\relax}>{\raggedright\arraybackslash}p{\dimexpr 0.501\linewidth-2\tabcolsep\relax}>{\raggedright\arraybackslash}p{\dimexpr 0.212\linewidth-2\tabcolsep\relax}}
\toprule
方式 & 用在哪 & 你要准备什么 \\
\midrule
\endhead
\texttt{abi} 块 & 调动态库里按 C ABI 导出的函数 & 一份 \texttt{.\allowbreak{}dll} / \texttt{.\allowbreak{}so} \\
宿主胶水绑定 & 把 C++ 函数注册进工具链，Magel 侧当普通函数调 & 写一点 C++ \\

\bottomrule
\end{longtable}
}

\texttt{abi} 块是最轻的一条——不用改工具链，不用重新编译，运行时直接加载库。

\section{\texttt{abi} 块：调动态库里的 C 函数}

假设你有一个 C 文件 \texttt{native.\allowbreak{}c}：

\par
\medskip
\begin{lstlisting}[style=c]
#include <stdint.h>

#if defined(_WIN32)
#define MAGEL_ABI_EXPORT __declspec(dllexport)
#else
#define MAGEL_ABI_EXPORT
#endif

MAGEL_ABI_EXPORT int32_t abi_add(int32_t left, int32_t right) {
    return left + right;
}

MAGEL_ABI_EXPORT const char *abi_name(void) {
    return "native";
}
\end{lstlisting}
\par
\medskip

先把它编成动态库（说句实话：「怎么编动态库」是 C 的事，和 Magel 无关）：

\par
\medskip
\begin{lstlisting}[style=sh]
gcc -shared -o native.dll native.c
\end{lstlisting}
\par
\medskip

然后在 Magel 里声明想用的函数：

\par
\medskip
\begin{lstlisting}[style=magel]
abi "./native.dll"
{
    int32 native_add(int32 left, int32 right) = "abi_add";
    String native_name() = "abi_name";
}

int64 main()
{
    println("{} {}", native_add((int32)20, (int32)22), native_name());
    return 0;
}
\end{lstlisting}
\par
\medskip

\par
\medskip
\begin{lstlisting}[style=out]
42 native
\end{lstlisting}
\par
\medskip

\texttt{abi} 块的语法是：

\par
\medskip
\begin{lstlisting}[style=out]
abi "<动态库路径>" {
    <返回类型> <Magel侧名字>(<形参表>) = "<库里的符号名>";
}
\end{lstlisting}
\par
\medskip

关键就是那个 \texttt{=\allowbreak{}}：等号右边是库里真实导出的符号名，左边是你想用的名字。两者可以不一样——给一批 C 函数起统一风格的 Magel 名，就靠它。

\begin{tip}{提示}
路径是运行时按当前工作目录找的。所以 \texttt{.\allowbreak{}/\allowbreak{}native.\allowbreak{}dll} 得跟你的程序在同一个目录下跑。
\end{tip}

\section{结构体、引用、字符串}

标量只是热身。真实场景里你还要传结构体（按值）、引用（原地改）、字符串：

\par
\medskip
\begin{lstlisting}[style=c]
API Point move_point(Point p, int32_t dx, int32_t dy) {
    p.x += dx; p.y += dy;
    return p;
}
API void bump(int32_t *value) { ++*value; }
API const char *greet(void) { return "hello from C"; }
\end{lstlisting}
\par
\medskip

Magel 侧：

\par
\medskip
\begin{lstlisting}[style=magel]
struct Point
{
    int32 x;
    int32 y;
};

abi "./abi_demo.dll"
{
    Point move_point(Point p, int32 dx, int32 dy) = "move_point";
    void bump(int32 mut& value) = "bump";
    String greet() = "greet";
}

int64 main()
{
    Point p;
    p.x = 1;
    p.y = 2;
    Point q = move_point(p, (int32)10, (int32)20);
    println("{} {} / {} {}", p.x, p.y, q.x, q.y);

    int32 n = 41;
    bump(&n);
    println("{}", n);

    println("{}", greet());
    return 0;
}
\end{lstlisting}
\par
\medskip

\par
\medskip
\begin{lstlisting}[style=out]
1 2 / 11 22
42
hello from C
\end{lstlisting}
\par
\medskip

三个要点：

\begin{enumerate}

\item 结构体按值传——C 的 \texttt{Point p} 对应 Magel 的 \texttt{Point p}，布局默认按 C 规则对齐。所以 Magel 这边得声明一个字段顺序、类型都一致的 \texttt{struct}；

\item C 的 \texttt{int32\_t *value} 对应 \texttt{int32 mut\& value}（第 7 章的可变引用），调用处写 \texttt{bump(\allowbreak{}\&n)\allowbreak{}}——取地址用 \texttt{\&}，和 Magel 内部引用是同一套写法；

\item C 的 \texttt{const char *} 对应 \texttt{String}。

\end{enumerate}

\end{longtable}

\section{数组与「可空」：边界上的两个特殊话题}

数组用 \texttt{T[\allowbreak{}]\allowbreak{}} 传，长度单独给一个参数；如果返回的数组长度由某个形参决定，在末尾用 \texttt{[\allowbreak{}count]\allowbreak{}} 标注：

\par
\medskip
\begin{lstlisting}[style=magel]
abi "./native.dll"
{
    Packed[] packed_numbers(int32 count) = "packed_numbers" [count];
    void packed_fill(Packed[] values, int32 count) = "packed_fill";
}
\end{lstlisting}
\par
\medskip

「空」是这个边界上唯一允许出现空的地方。 Magel 内部的引用永远非空（第 7 章），但 C 函数可能返回空指针。这时候用 \texttt{Option<\allowbreak{}T mut\&>\allowbreak{}} / \texttt{Option<\allowbreak{}T const\&>\allowbreak{}} 接：

\par
\medskip
\begin{lstlisting}[style=magel]
abi "./native.dll"
{
    Option<Packed const&> packed_snapshot() = "packed_snapshot";
}
\end{lstlisting}
\par
\medskip

返回 \texttt{None} 就代表 C 那边给了个空指针；传参时也可以传\texttt{Option<\allowbreak{}Packet mut\&>\allowbreak{}:\allowbreak{}:\allowbreak{}None}，C 侧收到的就是空指针。

\begin{tip}{提示}
这是「空」唯一能跨过边界的通道。 跨过边界之后，一切又回到「引用非空」的老规矩。
\end{tip}

\texttt{packed} 结构体用于对接 C 侧 \texttt{\#pragma pack} 的紧凑布局——C 里用\texttt{\#pragma pack(\allowbreak{}push,\allowbreak{} 1)\allowbreak{}} 压过的地方，Magel 侧就声明成 \texttt{struct X packed \{ … \}}。

完整例子见 \href{https://github.com/rabbitc999/Magel/tree/master/doc/examples/abi_buffers}{\texttt{doc/\allowbreak{}examples/\allowbreak{}abi\_buffers/\allowbreak{}}}——它覆盖了结构体嵌套、紧凑布局、数组读写、可空引用、返回值长度等全部边界情况。

\section{宿主胶水：把 C++ 函数注册进来}

不想走动态库、想让 C++ 函数像普通函数一样调？写一个 \texttt{bind\allowbreak{}Magel\allowbreak{}Glue} 把它注册进工具链：

\par
\medskip
\begin{lstlisting}[style=cpp]
#include <cstdint>
#include <string>

struct ExportCounterTag;
using ExportCounter = magel_glue::Handle<ExportCounterTag, std::uint64_t>;

bool bindMagelGlue(magel_glue::Registry &registry, Memory::String *error)
{
    return registry.bindTyped<std::uint32_t, Memory::String>(
               "demo_cpp_text_size",
               [](Memory::String arg0) {
                   return static_cast<std::uint32_t>(arg0.size());
               }, error);
}
\end{lstlisting}
\par
\medskip

Magel 侧就像声明普通函数：

\par
\medskip
\begin{lstlisting}[style=magel]
int32 demo_cpp_text_size(String text);

int64 main()
{
    println("{}", demo_cpp_text_size("hello"));
    return 0;
}
\end{lstlisting}
\par
\medskip

两条约定：

\begin{itemize}

\item 复杂宿主对象一律用整数句柄过边界——不要把 C++ 对象本体塞进 Magel 值里，而是用 \texttt{magel\_glue:\allowbreak{}:\allowbreak{}Handle<\allowbreak{}Tag,\allowbreak{} Abi\allowbreak{}Type>\allowbreak{}} 给它一个「名义类型」，Magel 侧拿到的是个整数；

\item 泛型函数实例化后键名带后缀：\texttt{demo\_cpp\_identity<\allowbreak{}int32>\allowbreak{}} 对应键名\texttt{demo\_cpp\_identity\_\_int32}。

\end{itemize}

宿主类型的名字是编译期就绑死的，所以这条路比 \texttt{abi} 强类型、报错也早，胶水需要编入宿主或 AOT 产物；AOT 可直接通过 --glue 指定文件。

\subsection{\texttt{impl}：把宿主函数绑定到协议}

结构体用继承列表声明普通接口实现；\texttt{impl 类型 :\allowbreak{} 接口 =\allowbreak{} 宿主绑定名;} 则把宿主函数接到单方法接口或转换协议。它不是一套任意 \texttt{impl Type \{ .\allowbreak{}.\allowbreak{}.\allowbreak{} \}} 语法。

下面使用工具链自带的演示胶水。实际项目需要先在 C++ 注册同名绑定，不能只写声明就假设运行时存在它。

\par
\medskip
\begin{lstlisting}[style=magel]
type HostHandle<T> = uint64;
impl uint64 : ExplicitConvert<HostHandle<int32>> = demo_counter_from_uint;
impl HostHandle<int32> : ExplicitConvert<uint64> = demo_counter_to_uint;

interface HostValue
{
    int64 hostValue();
}
impl HostHandle<int32> : HostValue = demo_counter_to_uint;
HostHandle<int32> demo_cpp_add(HostHandle<int32> left, HostHandle<int32> right);

int64 main()
{
    HostHandle<int32> left = cast<HostHandle<int32>>((uint64)20);
    HostHandle<int32> right = cast<HostHandle<int32>>((uint64)22);
    HostHandle<int32> total = demo_cpp_add(left, right);
    println("{} {}", cast<uint64>(total), total.hostValue());
    return 0;
}
\end{lstlisting}
\par
\medskip

\par
\medskip
\begin{lstlisting}[style=out]
42 42
\end{lstlisting}
\par
\medskip

接口签名、宿主参数和返回值必须一致。同步回调通过 \texttt{Native\allowbreak{}Call\allowbreak{}Context:\allowbreak{}:\allowbreak{}invoke} 与 \texttt{magel\_glue:\allowbreak{}:\allowbreak{}Function} 使用同一套 VM/AOT 规则；不要把函数值中的运行时地址当作宿主机器函数指针。完整胶水约定见\href{https://github.com/rabbitc999/Magel/blob/master/doc/08-host-integration.md}{宿主集成}。

\section{反方向：宿主调用 Magel}

宿主有三种可用方式：

{\small\setlength{\tabcolsep}{4pt}
\begin{longtable}{>{\raggedright\arraybackslash}p{\dimexpr 0.093\linewidth-2\tabcolsep\relax}>{\raggedright\arraybackslash}p{\dimexpr 0.887\linewidth-2\tabcolsep\relax}}
\toprule
方式 & 调用路径 \\
\midrule
\endhead
独立 VM & 宿主加载 .svmb 和数据区，注册胶水，由 Machine 执行；适用于当前 MCU 工程 \\
AOT C 导出 & Magel 用 export 声明，AOT 生成库和 C 头文件，宿主按头文件创建上下文并调用导出函数 \\
同步回调 & Magel 将具名函数或 fn 值传给 C++ 胶水，胶水用 Function 包装或 Context::invoke 调回；VM/AOT 共用 \\
\bottomrule
\end{longtable}
}

库可以没有 main，但至少有一个 export。按后缀输出 .dll / .so 共享库或 .o 可重定位文件，并生成同名 C 头文件；.o 需要宿主链接器，不是动态加载器直接加载的共享库。不支持 .lib / .a 静态库。上下文初始化不自动调用源码的 main。

export 只供 AOT，VM 执行和字节码导出遇到它会报错。普通同步回调不要求 export，支持闭包、高阶函数、引用和多层重入；函数值与上下文只在所属宿主回调期间同步使用。

AOT 的 static runMagel 是生成 C++ 内部的整程序入口，不能当作通用动态库 C 导出或字节码加载器。完整 API 与可运行代码见\href{https://github.com/rabbitc999/Magel/blob/master/doc/08-host-integration.md}{宿主集成}及\href{https://github.com/rabbitc999/Magel/blob/master/example/native-callbacks/README.md}{胶水回调示例}。
