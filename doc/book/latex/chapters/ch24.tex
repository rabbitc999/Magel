\section{沿 main.mgl 读完一次请求}

现在回到 \texttt{main.\allowbreak{}mgl}，把前面的界面、ER 图与真实代码对应起来。这个文件没有使用 Web 框架，HTTP 协议、会话和业务分发都能在同一文件里找到。建议先读文件末尾的 \texttt{main}，再沿函数调用往回追。

\subsection{main：先准备长期状态，再处理短期请求}

入口是 \texttt{int64 main(\allowbreak{}List<\allowbreak{}String>\allowbreak{} arguments)\allowbreak{}}。参数循环识别监听地址、端口、MySQL 连接、数据库名称、初始化文件和跨源来源。\texttt{decimal} 返回 \texttt{Option<\allowbreak{}int64>\allowbreak{}}，端口必须在 0–65535 内；它逐字检查十进制数字，并在乘十之前判断是否会超出上限，不把错误输入悄悄变成 0。

参数读取完成后，\texttt{main} 创建一个 \texttt{App app}。\texttt{App} 把数据库连接、\texttt{List<\allowbreak{}Session>\allowbreak{}} 会话表、随机状态和 \texttt{allow\allowbreak{}Origin} 集中在一起，生命周期覆盖整个服务。\texttt{connect} 建立 MySQL 连接、设置 \texttt{utf8mb4}、选择数据库；\texttt{ensure\allowbreak{}Schema} 判断业务表是否就绪，必要时读取初始化 SQL。失败路径调用 \texttt{app.\allowbreak{}stop(\allowbreak{})\allowbreak{}} 关闭连接并返回。

随后才创建 \texttt{Tcp\allowbreak{}Listener}。当配置端口为 0 时，必须用 \texttt{listener.\allowbreak{}local\allowbreak{}Port(\allowbreak{})\allowbreak{}} 取得系统实际分配的端口；就绪文件写入的也是这个值，测试客户端据此连接。主循环的核心代码如下，摘自实际入口：

\par
\medskip
\begin{lstlisting}[style=magel]
while (maximum == 0 || handled < maximum)
{
    TcpSocket socket = listener.accept((int32)1000);
    if (!socket.isOpen())
    {
        continue;
    }
    Request request = readRequest(&socket, actualPort);
    Response response = route(&app,&request);
    bool sent = sendResponse(&socket,&response, app.allowOrigin);
    socket.close();
    handled = handled + 1;
}
\end{lstlisting}
\par
\medskip

每条连接依次经过接收、路由、发送、关闭。\texttt{maximum} 为 0 时持续服务，正数用于确定性测试；请求处理完毕才增加计数。当前代码把发送结果保存为 \texttt{sent}，但没有重试发送失败的响应。循环退出后，入口再关闭监听器并调用 \texttt{app.\allowbreak{}stop(\allowbreak{})\allowbreak{}}。

注意两个寿命：\texttt{App} 和监听器存在于循环外，单次请求的 \texttt{socket}、\texttt{request}、\texttt{response} 存在于循环内。这样下一次请求可以继续使用数据库和会话，但不会共享上一条请求的临时正文。

\subsection{Request 与 readRequest：TCP 字节不等于完整 HTTP 请求}

\texttt{Request} 保存解析后的方法、路径、查询串、正文、媒体类型、Authorization 以及解析状态；\texttt{Response} 只保存状态码、媒体类型和正文。把协议层结果集中成值对象后，业务函数就不必再次切分原始报文。

\texttt{read\allowbreak{}Request} 首先循环调用 \texttt{socket.\allowbreak{}receive(\allowbreak{}4096)\allowbreak{}}，把数据追加到 \texttt{raw}，直到找到 \texttt{\textbackslash\{\}r\textbackslash\{\}n\textbackslash\{\}r\textbackslash\{\}n}。一次 TCP receive 可能只取得半个请求头，也可能同时带回部分正文，所以不能用“一次 receive 就读完一个请求”的假设实现 HTTP。

请求头结束后，函数拆分请求行，校验 HTTP/1.0 或 HTTP/1.1，分离 \texttt{path} 与 \texttt{query}，再逐行检查头部。它拒绝重复 Content-Length、非法 Host、不支持的 Transfer-Encoding 和 Expect；POST/PUT 缺少 Content-Length 时返回 411。随后继续接收，直到正文达到声明长度，再按该长度截取。

这些失败不会直接执行 SQL，而是写入 \texttt{request.\allowbreak{}status}。\texttt{route} 开头看到非零状态，就生成对应的错误响应。协议层与业务层因此只有一个明确交接点。

这仍是有边界的示例：请求头与正文有上限，连接逐条处理；\texttt{accept} 的等待时间不等于已接收连接具有完整的读超时。一个迟迟不发完正文的客户端仍可能阻塞后续请求，不能把这段循环描述成并发 HTTP 服务。

\subsection{route：先处理公开入口，再查会话}

\texttt{route(\allowbreak{}App mut\& app,\allowbreak{} Request const\& request)\allowbreak{}} 的参数说明了职责：它可能改变应用的会话状态，但只读取本次请求。代码的先后顺序很重要：

\begin{enumerate}

\item 请求解析失败：立即生成错误响应。

\item OPTIONS：直接生成预检响应。

\item GET \texttt{/\allowbreak{}api/\allowbreak{}health}：执行 \texttt{SELECT 1}，确认数据库实际可用。

\item \texttt{/\allowbreak{}api/\allowbreak{}login}：只允许 POST，并调用 \texttt{app.\allowbreak{}login}。

\item 非 \texttt{/\allowbreak{}api/\allowbreak{}} 路径：返回 404，明确告诉调用方静态页面由另一个服务器提供。

\item 其余 API：提取 Bearer 令牌、查找会话，然后按资源分发。

\end{enumerate}

核心的会话检查只有两行：

\par
\medskip
\begin{lstlisting}[style=magel]
Session session = app.findSession(bearerToken(request.authorization));
if (!session.valid)
{
    return errorResponse(401, "未登录或会话已失效，请重新登录");
}
\end{lstlisting}
\par
\medskip

\texttt{bearer\allowbreak{}Token} 检查 Bearer 前缀，\texttt{find\allowbreak{}Session} 在 \texttt{App.\allowbreak{}sessions} 中查找令牌，找不到时返回 \texttt{valid=\allowbreak{}false} 的会话值。登录函数在核对用户名和口令之后创建会话，并把令牌、用户信息和可见模块树一起返回。注销则删除会话表里的对应记录，所以后续使用旧令牌的请求会失败。

\texttt{issue\allowbreak{}Token} 使用应用的随机状态生成 64 个十六进制字符。阅读代码时，应把“令牌字符串长度”与“密码学安全性”分开；这个练习项目不因此具备完整的生产认证方案。

\subsection{dispatchStudents 与 allow：路由不直接等于业务授权}

通过会话检查后，\texttt{split\allowbreak{}Resource} 把 \texttt{/\allowbreak{}api/\allowbreak{}students} 与后续资源部分分开，交给 \texttt{dispatch\allowbreak{}Students}。它进一步同时判断资源尾段和 HTTP 方法。例如，根资源的 GET 是列表，POST 是新增；\texttt{/\allowbreak{}\{id\}} 的 PUT 是修改，DELETE 是删除；\texttt{/\allowbreak{}query} 只接受 POST。

下面是实际的列表与新增分支摘录：

\par
\medskip
\begin{lstlisting}[style=magel]
if (request.method == "GET")
{
    if (!allow(session.level, "student", "list",&denial))
    {
        return denial;
    }
    return app.listStudents("", "");
}
if (request.method == "POST")
{
    if (!allow(session.level, "student", "add",&denial))
    {
        return denial;
    }
    return app.createStudent(&request);
}
\end{lstlisting}
\par
\medskip

同一个资源，动作不同，权限门槛也不同。\texttt{allow} 先通过 \texttt{action\allowbreak{}Need\allowbreak{}Level} 查权限表；动作不存在属于服务端配置错误，返回 500；当前等级不足则生成 403；通过后才调用业务方法。前端隐藏“新增”按钮只是界面提示，真正挡住直接 HTTP 请求的是这里。

班级、课程、成绩和用户模块采用相同的分发结构，但业务规则并不完全相同。例如，成绩有统计动作，用户模块还有重置口令与修改权限，不能只复制学生路由然后替换表名。

\subsection{JSON、SQL 与结果封装：新增和查询各追一遍}

新增学生时，\texttt{create\allowbreak{}Student} 调用 \texttt{read\allowbreak{}Json\allowbreak{}Body}，先确认媒体类型为 \texttt{application/\allowbreak{}json}，再解析正文。\texttt{text\allowbreak{}Field} 读取字符串并 trim；\texttt{int\allowbreak{}Field} 要求真正的 JSON 整数，类型不符或越界时给失败哨兵值。函数把需要的字段保存为独立的 String／整数后，关闭 JSON 根对象，再校验姓名、性别和班级关系。

这个顺序同时展示了 Magel 的值语义和资源边界：临时 JSON 文档结束后，已经取得的值仍可用于 SQL；不能把借用文档内部对象的短命引用直接保存出去。阅读失败分支时，也要检查 \texttt{root.\allowbreak{}close(\allowbreak{})\allowbreak{}} 是否在应有位置执行。

SQL 值通过当前数据库连接的 \texttt{db.\allowbreak{}quote(\allowbreak{}.\allowbreak{}.\allowbreak{}.\allowbreak{})\allowbreak{}} 转义。比如登录查询把姓名和口令作为值拼入固定 SQL，查询学生时也是在已知语句骨架上追加经过处理的条件。\texttt{quote} 处理的是值，不是任意表名和列名；启动参数里的数据库名称属于另一类配置输入，不能把它与浏览器传来的字段混为一谈。

列表查询可以从 \texttt{student\allowbreak{}List\allowbreak{}Sql} 开始读：

\par
\medskip
\begin{lstlisting}[style=magel]
" FROM student st"
" LEFT JOIN sclass cl ON cl.sclass_id = st.sclass_id"
" LEFT JOIN selection se ON se.student_id = st.student_id"
\end{lstlisting}
\par
\medskip

LEFT JOIN 让“尚未分班”和“尚无成绩”的学生仍然出现在列表里。\texttt{COUNT(\allowbreak{}se.\allowbreak{}selection\_id)\allowbreak{}} 统计实际成绩记录；换成 COUNT(*) 会把连接产生的空行也算进去。平均分使用 AVG、ROUND 和 IFNULL，\texttt{student\allowbreak{}Group\allowbreak{}Sql} 补齐 GROUP BY 与排序，避免在 ONLY\_FULL\_GROUP\_BY 模式下依赖不确定的分组行为。

执行结果由 \texttt{Result\allowbreak{}Set} 承接，先检查 \texttt{rows.\allowbreak{}ok}，再读取行列。\texttt{student\allowbreak{}Row} 把一行转成 JSON 对象，字符串经过 \texttt{json\allowbreak{}String} 处理；\texttt{list\allowbreak{}Envelope} 最后补上 \texttt{items}、\texttt{count}、\texttt{total} 和 \texttt{limit}。因此页面既能显示当前返回多少行，也知道服务端列表上限。

\subsection{sendResponse：统一协议出口，再回到浏览器}

路由函数返回 \texttt{Response} 后，\texttt{send\allowbreak{}Response} 才负责写 HTTP 状态行、Content-Type、按 UTF-8 字节计算的 Content-Length、CORS 头和 \texttt{Connection:\allowbreak{} close}，最后追加正文。浏览器接到响应，按状态码决定显示数据还是错误信息，并用 \texttt{text\allowbreak{}Content} 把用户字段放进页面。

CORS 响应头让浏览器决定是否允许页面读取跨源响应，它不取代 Bearer 会话与后端权限。OPTIONS 不执行业务 SQL；真正的数据请求仍要重新走身份和动作检查。

现在可以拿一条操作自己追踪：登录管理员，点击“新增学生”，在浏览器网络面板中找到 POST \texttt{/\allowbreak{}api/\allowbreak{}students}，然后按 \texttt{read\allowbreak{}Request → route → dispatch\allowbreak{}Students → allow → create\allowbreak{}Student → send\allowbreak{}Response} 对照源码。故意省略姓名、使用学生令牌或提交不存在的班级，分别观察字段校验、权限校验和关系校验在哪一步返回。

\section{验收与交付}

项目已经提供两类回归，使用独立测试库；在准备好 MySQL 的机器上运行：

\par
\medskip
\begin{lstlisting}[style=sh]
python tests/magel_ipage_student_server.py --backends run
python tests/magel_ipage_student_server_browser.py --browser "C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"
\end{lstlisting}
\par
\medskip

接口回归覆盖登录、角色权限、五模块业务、统计与 HTTP 边界；浏览器回归真正从不同源访问 API，检查菜单、增删改查和 HTML 注入防护。本章截图来自该真实浏览器回归，数据来自仓库夹具。

后端可通过 AOT 交付：

\par
\medskip
\begin{lstlisting}[style=sh]
./magel.exe aot example/sql-magel/example/ipage-student-server/main.mgl --out build/student-server.exe
\end{lstlisting}
\par
\medskip

AOT 默认 checked 和 O3。前端目录仍单独部署，MySQL 服务与客户端依赖也需要准备；不能因为后端生成了可执行文件，就认为数据库与页面已经一并打包。

该示例沿用练习数据中的明文口令，会话没有到期与刷新机制，前端的登录尝试次数也不构成服务端限流。正式服务需进一步完善认证、会话、TLS、SQL 参数绑定、超时及并发；本章的目标是把现有应用的职责与请求链路讲清楚。
