# 第 21 章 与 C 互操作

到第 20 章为止，你的程序都活在自己的世界里。可现实中有太多东西是现成的 C 库：
压缩、加密、数据库、图形、系统调用……你不可能全都重写一遍。

这一章讲**怎么跨过 Magel 和 C 的边界**，两个方向：

- **Magel 调 C**——用 `abi` 块调动态库里导出的函数；
- **C 调 Magel**——把你的函数交给 C 的运行时。

---

## 21.1 三种集成方式

工具链支持三条路，按「需要多少 C 侧配合」排：

| 方式 | 用在哪 | 你要准备什么 |
| --- | --- | --- |
| `abi` 块 | 调**动态库**里按 C ABI 导出的函数 | 一份 `.dll` / `.so` |
| 宿主胶水绑定 | 把 C++ 函数注册进工具链，Magel 侧当普通函数调 | 写一点 C++ |
| 嵌入（AOT + `runMagel`） | 宿主程序调用编译好的 Magel 逻辑 | AOT 产物 |

`abi` 块是**最轻**的一条——不用改工具链，不用重新编译，运行时直接加载库。

---

## 21.2 `abi` 块：调动态库里的 C 函数

假设你有一个 C 文件 `native.c`：

```c
#include <stdint.h>

#if defined(_WIN32)
#define MAGEL_ABI_EXPORT __declspec(dllexport)
#else
#define MAGEL_ABI_EXPORT
#endif

MAGEL_ABI_EXPORT int32_t abi_add(int32_t left, int32_t right) {
    return left + right;
}

MAGEL_ABI_EXPORT const char *abi_name(void) {
    return "native";
}
```

先把它编成动态库（说句实话：「怎么编动态库」是 C 的事，和 Magel 无关）：

```sh
gcc -shared -o native.dll native.c
```

然后在 Magel 里声明想用的函数：

<!-- dll tmp/abi21/native.c native.dll -->
```magel
abi "./native.dll"
{
    int32 native_add(int32 left, int32 right) = "abi_add";
    String native_name() = "abi_name";
}

int64 main()
{
    println("{} {}", native_add((int32)20, (int32)22), native_name());
    return 0;
}
```

```text
42 native
```

`abi` 块的语法是：

```text
abi "<动态库路径>" {
    <返回类型> <Magel侧名字>(<形参表>) = "<库里的符号名>";
}
```

**关键就是那个 `=`**：等号右边是库里**真实导出**的符号名，左边是你想用的名字。
两者可以不一样——给一批 C 函数起统一风格的 Magel 名，就靠它。

> 路径是**运行时**按当前工作目录找的。所以 `./native.dll` 得跟你的程序在同一个目录下跑。

## 21.3 结构体、引用、字符串

标量只是热身。真实场景里你还要传**结构体**（按值）、**引用**（原地改）、**字符串**：

```c
API Point move_point(Point p, int32_t dx, int32_t dy) {
    p.x += dx; p.y += dy;
    return p;
}
API void bump(int32_t *value) { ++*value; }
API const char *greet(void) { return "hello from C"; }
```

Magel 侧：

<!-- dll tmp/abi21/abi_demo.c abi_demo.dll -->
```magel
struct Point
{
    int32 x;
    int32 y;
};

abi "./abi_demo.dll"
{
    Point move_point(Point p, int32 dx, int32 dy) = "move_point";
    void bump(int32 mut& value) = "bump";
    String greet() = "greet";
}

int64 main()
{
    Point p;
    p.x = 1;
    p.y = 2;
    Point q = move_point(p, (int32)10, (int32)20);
    println("{} {} / {} {}", p.x, p.y, q.x, q.y);

    int32 n = 41;
    bump(&n);
    println("{}", n);

    println("{}", greet());
    return 0;
}
```

```text
1 2 / 11 22
42
hello from C
```

三个要点：

1. **结构体按值传**——C 的 `Point p` 对应 Magel 的 `Point p`，布局默认按 C 规则对齐。
   所以 Magel 这边得**声明一个字段顺序、类型都一致的 `struct`**；
2. **C 的 `int32_t *value` 对应 `int32 mut& value`**（第 7 章的可变引用），
   调用处写 `bump(&n)`——**取地址用 `&`**，和 Magel 内部引用是同一套写法；
3. **C 的 `const char *` 对应 `String`**。

### 支持的类型一览

| Magel 写法 | 含义 |
| --- | --- |
| `int8`…`int64`、`uint8`…`uint64`、`float32`、`float64`、`bool` | 标量，按值传 |
| `String` | 字符串（C 侧 `const char *`） |
| `T mut&` / `T const&` | 可变 / 只读引用（C 侧 `T *` / `const T *`） |
| `Option<T mut&>` / `Option<T const&>` | **可空引用**（C 侧可以是空指针） |
| `T[]` + 另给长度 | 数组视图（C 侧 `T *`） |
| 结构体 | 按值传，默认 C 布局 |
| `struct X packed { … }` | 紧凑布局，对接 C 的 `#pragma pack` |

## 21.4 数组与「可空」：边界上的两个特殊话题

**数组**用 `T[]` 传，长度**单独给一个参数**；如果返回的数组长度由某个形参决定，
在末尾用 `[count]` 标注：

<!-- no-run -->
```magel
abi "./native.dll"
{
    Packed[] packed_numbers(int32 count) = "packed_numbers" [count];
    void packed_fill(Packed[] values, int32 count) = "packed_fill";
}
```

**「空」是这个边界上唯一允许出现空的地方。** Magel 内部的引用**永远非空**（第 7 章），
但 C 函数可能返回空指针。这时候用 `Option<T mut&>` / `Option<T const&>` 接：

<!-- no-run -->
```magel
abi "./native.dll"
{
    Option<Packed const&> packed_snapshot() = "packed_snapshot";
}
```

返回 `None` 就代表 C 那边给了个空指针；传参时也可以传
`Option<Packet mut&>::None`，C 侧收到的就是空指针。

> **这是「空」唯一能跨过边界的通道。** 跨过边界之后，一切又回到「引用非空」的老规矩。

`packed` 结构体用于对接 C 侧 `#pragma pack` 的紧凑布局——C 里用
`#pragma pack(push, 1)` 压过的地方，Magel 侧就声明成 `struct X packed { … }`。

完整例子见 [`doc/examples/abi_buffers/`](../../doc/examples/abi_buffers/)——
它覆盖了结构体嵌套、紧凑布局、数组读写、可空引用、返回值长度等全部边界情况。

## 21.5 宿主胶水：把 C++ 函数注册进来

不想走动态库、想让 C++ 函数像普通函数一样调？写一个 `bindMagelGlue`
把它**注册进工具链**：

```cpp
#include <cstdint>
#include <string>

struct ExportCounterTag;
using ExportCounter = magel_glue::Handle<ExportCounterTag, std::uint64_t>;

bool bindMagelGlue(magel_glue::Registry &registry, Memory::String *error)
{
    return registry.bindTyped<std::uint32_t, Memory::String>(
               "demo_cpp_text_size",
               [](Memory::String arg0) {
                   return static_cast<std::uint32_t>(arg0.size());
               }, error);
}
```

Magel 侧就像声明普通函数：

<!-- no-run -->
```magel
int32 demo_cpp_text_size(String text);

int64 main()
{
    println("{}", demo_cpp_text_size("hello"));
    return 0;
}
```

两条约定：

- **复杂宿主对象一律用整数句柄过边界**——不要把 C++ 对象本体塞进 Magel 值里，
  而是用 `magel_glue::Handle<Tag, AbiType>` 给它一个「名义类型」，Magel 侧拿到的是个整数；
- 泛型函数实例化后键名带后缀：`demo_cpp_identity<int32>` 对应键名
  `demo_cpp_identity__int32`。

宿主类型的名字是**编译期**就绑死的，所以这条路比 `abi` 强类型、报错也早，
胶水需要编入宿主或 AOT 产物；AOT 可直接通过 --glue 指定文件。

### `impl`：把宿主函数绑定到协议

结构体用继承列表声明普通接口实现；`impl 类型 : 接口 = 宿主绑定名;` 则把宿主函数接到单方法接口或转换协议。它不是一套任意 `impl Type { ... }` 语法。

下面使用工具链自带的演示胶水。实际项目需要先在 C++ 注册同名绑定，不能只写声明就假设运行时存在它。

<!-- verify-book -->
```magel
type HostHandle<T> = uint64;
impl uint64 : ExplicitConvert<HostHandle<int32>> = demo_counter_from_uint;
impl HostHandle<int32> : ExplicitConvert<uint64> = demo_counter_to_uint;

interface HostValue
{
    int64 hostValue();
}
impl HostHandle<int32> : HostValue = demo_counter_to_uint;
HostHandle<int32> demo_cpp_add(HostHandle<int32> left, HostHandle<int32> right);

int64 main()
{
    HostHandle<int32> left = cast<HostHandle<int32>>((uint64)20);
    HostHandle<int32> right = cast<HostHandle<int32>>((uint64)22);
    HostHandle<int32> total = demo_cpp_add(left, right);
    println("{} {}", cast<uint64>(total), total.hostValue());
    return 0;
}
```

```text
42 42
```

接口签名、宿主参数和返回值必须一致。同步回调通过 `NativeCallContext::invoke` 与 `magel_glue::Function` 使用同一套 VM/AOT 规则；不要把函数值中的运行时地址当作宿主机器函数指针。完整胶水约定见[宿主集成](../08-host-integration.md)。


## 21.6 反方向：宿主调用 Magel

宿主有三种可用方式：

| 方式 | 调用路径 |
| --- | --- |
| 独立 VM | 宿主加载 .svmb 和数据区，注册胶水，由 Machine 执行；适用于当前 MCU 工程 |
| AOT C 导出 | Magel 用 export 声明，AOT 生成库和 C 头文件，宿主按头文件创建上下文并调用导出函数 |
| 同步回调 | Magel 将具名函数或 fn 值传给 C++ 胶水，胶水用 Function 包装或 Context::invoke 调回；VM/AOT 共用 |

库可以没有 main，但至少有一个 export。按后缀输出 .dll / .so 共享库或 .o 可重定位文件，
并生成同名 C 头文件；.o 需要宿主链接器，不是动态加载器直接加载的共享库。
不支持 .lib / .a 静态库。上下文初始化不自动调用源码的 main。

export 只供 AOT，VM 执行和字节码导出遇到它会报错。普通同步回调不要求 export，
支持闭包、高阶函数、引用和多层重入；函数值与上下文只在所属宿主回调期间同步使用。

AOT 的 static runMagel 是生成 C++ 内部的整程序入口，不能当作通用动态库 C 导出或字节码加载器。
完整 API 与可运行代码见[宿主集成](../08-host-integration.md)及[胶水回调示例](../../example/native-callbacks/README.md)。

## 21.7 小结

| 你会了 | 关键点 |
| --- | --- |
| 三种集成 | `abi` 块（轻）／宿主胶水（要编 C++）／AOT 嵌入（宿主调 Magel） |
| `abi` 语法 | `abi "./x.dll" { 返回类型 名字(形参) = "C符号名"; }` |
| 名字映射 | 等号右边是 C 侧真实符号名，左边随你起 |
| 结构体 | 按值传；Magel 侧声明字段一致的 `struct` |
| 引用 | C 的 `T *` ↔ Magel 的 `T mut&`，调用处写 `&x` |
| 字符串 | C 的 `const char *` ↔ Magel 的 `String` |
| 数组 | `T[]` + 长度另给；返回长度用 `[count]` 标注 |
| 「空」 | 只有 `Option<T &>` 能把空送过边界 |
| 紧凑布局 | `struct X packed { … }` 对接 `#pragma pack` |
| 胶水 | `bindMagelGlue` 注册 C++ 函数；复杂对象用整数句柄 |
| 反向 | VM 宿主执行、AOT export C 接口，或胶水同步回调 fn |
