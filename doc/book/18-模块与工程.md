# 第 18 章 模块与工程

前面十七章，程序都写在一个 `.mgl` 文件里。真实项目做不到——几千行塞一个文件，
谁也没法读。这一章讲**怎么把代码拆开**，以及工具链给工程准备的那几个命令。

拆开有两条线：

- **语言层**：`module` 声明一个文件属于哪个模块，`import` 把别的模块引进来；
- **工程层**：`magel new` 起一个带目录结构的工程，`magel test` / `magel fmt` 管测试和风格。

---

## 18.1 `module`：给文件一个名字

每个文件首行都可以声明自己属于哪个模块：

<!-- no-run -->
```magel
module mylib::math;
```

`mylib::math` 是**模块路径**，用 `::` 分隔——和标准库里的 `std::iter` 是同一套写法。

模块名不是随便起的：`import` 一个模块时，编译器要按这个名字去**找对应的文件**（见 18.2）。

**核心模块 `std::lang` 不用声明也不用 import**：`println` / `format` / `assert` / `len` /
`Any` / `Option` / `Result` 这些都是它自动带进来的（前面十七章你一直在用，从没 import 过）。

---

## 18.2 `import`：把别的模块接进来

假设有两个文件。先写一个工具模块 `util/text.mgl`：

<!-- no-run -->
```magel
module util::text;

String shout(String s)
{
    return s + "!";
}
```

再用 `import` 在另一个文件里用它：

<!-- no-run -->
```magel
module app;
import util::text;

int64 main()
{
    println("{}", shout("hi"));
    return 0;
}
```

跑 `magel run app.mgl`，输出：

```text
hi!
```

几个要点：

- `import util::text;` 之后，`util::text` 里的**公开函数按裸名就能调**——直接写 `shout("hi")`，
  不用写 `util::text::shout`；
- **模块名 `util::text` 对应文件 `util/text.mgl`**：`::` 换成目录分隔符，末尾加 `.mgl`。
  文件名和模块名对不上，`import` 就找不到；
- 路径是**相对当前文件**解析的。

**文件名 = 模块路径**这条对应关系，是把「模块」和「目录结构」绑在一起的关键：
看文件树就知道模块树。

> `import` 后也可以写完整路径来调用，或者用 `import_names` 引入短名——细节见语言参考
> 第 12 节与 `example/samples/import_names.mgl`。初学阶段先把 18.2 这套用熟。

## 18.3 起一个工程：`magel new`

手写目录、手写 `magel.toml` 太麻烦。工具链给了一条命令：

```sh
magel new demo
```

它创建一个叫 `demo` 的新目录（**目标目录必须不存在**，免得覆盖你的东西），里面长这样：

```text
demo/
├── .gitignore
├── README.md
├── magel.toml          # 工程配置
├── src/
│   └── main.mgl        # 应用源码
└── tests/
    └── test_main.mgl   # 测试
```

建完还会顺手 `git init` 建好仓库。`src/main.mgl` 是那个你熟得不能再熟的 hello：

<!-- no-run -->
```magel
int64 main()
{
    println("Hello, Magel!");
    return 0;
}
```

---

## 18.4 `magel.toml`：工程配置文件

工程靠一个 `magel.toml` 描述自己。默认生成的是：

```toml
[package]
name = "hello"
version = "0.1.0"

[magel]
run = "interpret"
main = "src/main.mgl"
```

- `[package]` 里是包名和版本；
- `[magel]` 里告诉工具链：入口是哪个文件（`main`）、默认用什么方式跑（`run`）。

工程根目录一旦有 `magel.toml`，在**这个目录里**执行命令就不用反复写路径了。

`.gitignore` 也一并给好了——构建产物不该进版本库：

```text
/build/
/.magel/
/magel_out*
*.exe
```

## 18.5 三个日常命令

工程起来了，日常就三件事：**跑、查、测**。

```sh
magel run src/main.mgl     # 运行
```

```text
Hello, Magel!
```

`run` 是解释执行（第 1 章讲过 `run` 和 `check` 的区别）：

```sh
magel check src/main.mgl   # 只检查，不运行
```

`check` 只做编译期检查，**一行都不执行**——改完代码先 `check` 一下，比 `run` 快，也安全
（不会真的动到数据）。

测试用 `test`。工程里的 `tests/test_main.mgl` 是个普通的 `main`，里面全是 `assert`
（第 16 章）：

<!-- no-run -->
```magel
int64 main()
{
    assert(1 + 1 == 2);
    return 0;
}
```

跑整个 `tests/` 目录：

```sh
magel test tests
```

输出每个测试文件的结果和合计（路径按实际位置显示）：

```text
[passed] tests/test_main.mgl
通过 1，失败 0，跳过 0
```

`assert` 就是测试的**体检项**：条件不成立，那个测试文件就判 `失败`。
你不用装任何测试框架——`main` + `assert` 就是最小可用的测试。

## 18.6 `magel fmt`：让风格统一

一个团队里，最没意义的争论是「大括号换行吗」「缩进几格」。工具链直接给了一个格式化器：

```sh
magel fmt src/main.mgl            # 打印格式化后的源码到屏幕
magel fmt src/main.mgl --write    # 直接写回文件
magel fmt src/main.mgl --check    # 只检查「格式对不对」，不修改
```

`--check` 是给 CI 用的：文件已经规范 → 安静退出；**需要格式化 → 打印文件名并以非零码退出**：

```sh
magel fmt src/messy.mgl --check
```

```text
需要格式化：src/messy.mgl
```

（退出码是 1。CI 里挂上这条，谁提交了没格式化的代码就会红。）

`fmt` 会干的事，拿一段挤成一团的代码试（它本身能跑，只是很难看）：

```magel
int64 main()
{
    int64 x = 1;
    if (x>0)
    {
        println("{}", x);
    }
    return 0;
}
```

`magel fmt` 之后：

```magel
int64 main()
{
    int64 x = 1;
    if (x>0)
    {
        println("{}", x);
    }
    return 0;
}
```

缩进统一成 4 空格、层级对齐好。注意它**只管空白和换行，不动代码内容**
（`x=1` 里没有空格、`"{}",    x` 里那串多余空格，都原样留着）——格式化器不替你做美学判断，
只保证结构清楚。

### 终端查手册

`magel man` 是终端手册入口，从同一可执行文件中的标准库数据查询。无目标时按能力域列模块，模块目标列符号，类型和方法目标显示签名、参数、返回值、错误边界及已有完整示例。

```sh
magel man
magel man std::text
magel man std::text::Text::split
magel man --search delimiter
magel man --json std::text::Text::split
magel man std::text::Text::split --run
```

搜索默认忽略大小写，`--exact` 匹配完整字段；拼错目标会给候选。`--lang zh|en` 选择界面和诊断语言，库说明仍复用中文原文。`--run` 在临时目录运行完整示例并附上输出。普通查询不需要 Python、网络或仓库；开发用 `--update` 运行既有生成脚本，重新构建后才进入内嵌数据。

完整命令和 JSON 结构见 [doc/man](../man/README.md)，标准库 API 说明仍在 [doc/library](../library/README.md)。

### 编辑器增量提示

LSP 将补全、悬停、语义着色、工作区查询、宏预览、编译诊断交给不同工作队列。修改按 UTF-16 编辑范围同步，同一源码版本复用索引。诊断延迟 250 毫秒合并连续编辑，保存立即检查；取消过期任务，并且不把旧版本结果写回编辑器。

缓存在 magel 可执行文件旁的 `build/lsp/`，与工程目录无关。未保存的依赖修改和关闭会刷新引用者，不写回源文件。缓存自动清理七天未使用的普通文件，超过 256 MiB 时淘汰到 192 MiB，保护最近十分钟的文件；活跃任务可以暂时超过额度。索引内存也有淘汰阈值，缓存损坏或不可写会退回分析。详细策略见 [LSP 增量提示与缓存](../man/lsp.md)。

### `inline`：函数定义的内联属性

`inline` 写在模块级函数定义前，参数、返回类型与函数体仍按普通函数规则检查。

<!-- verify-book -->
```magel
inline int64 square(int64 value)
{
    return value * value;
}

int64 main()
{
    println("{}", square(3));
    return 0;
}
```

```text
9
```

它是函数定义的属性，不是任意表达式的前缀，也不改变值语义。代码组织仍以清楚的职责为先，不需要给所有函数都加上它。


## 18.7 小结

| 你会了 | 关键点 |
| --- | --- |
| 模块声明 | `module mylib::math;` 放首行 |
| 导入 | `import util::text;`，公开函数按裸名调用 |
| 名字对应文件 | `util::text` ↔ `util/text.mgl`，路径相对当前文件 |
| `std::lang` | 核心模块，自动加载，永不 import |
| 起工程 | `magel new demo`（目标目录不能已存在） |
| 工程配置 | `magel.toml` 写包名、入口、运行方式 |
| 日常命令 | `run`（跑）、`check`（只查）、`test`（跑 `tests/`） |
| 测试 | 普通 `main` + `assert`，无需框架 |
| 格式化 | `magel fmt … [--check|--write]`，只动空白不碰代码 |
