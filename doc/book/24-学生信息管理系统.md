# 第 24 章 学生信息管理系统：让程序认识自己的结构

前面 23 章把语言讲完了。这一章反过来做一件「用」的事：把结构体、注解、反射、
JSON、SQL 和 `Result` / `?` 拼成一个能真正存数据的命令行程序。

它只有两百多行，却覆盖了日常业务程序最核心的那几件事：

- 一份**模型**（学生有学号、姓名、年龄、班级、成绩）；
- 一张**表**（模型直接变成 SQLite 的表）；
- 一组**命令**（增删查改、排序、搜索）；
- 一条**校验规则**（学号必须是正整数、年龄在 1 到 150、成绩在 0 到 100）；
- 一条**出错的路**（所有失败都变成可读的诊断，而不是崩溃）。

最关键的那一句话是：**这个程序从来没有手写过「学生有哪些字段」的清单。**
字段列表是它运行期从自己身上读出来的——这就是第 20 章的反射真正派上用场的地方。

示例就在仓库里：[`example/reflection-students/main.mgl`](../../example/reflection-students/main.mgl)。

---

## 24.1 先看看它能做什么

```sh
magel main.mgl students.db schema
```

```text
Student: id, name, age, className, score
```

| 命令 | 作用 |
| --- | --- |
| `schema` | 打印模型有哪些字段 |
| `add JSON` | 新增一名学生 |
| `update JSON` | 按学号更新（JSON 里必须带 `id`） |
| `get 学号` | 按学号查 |
| `delete 学号` | 按学号删 |
| `list [字段 [asc 或 desc]]` | 列出全部，可按字段排序 |
| `search 姓名` | 按姓名模糊查 |

第一个参数是数据库文件路径（不存在时 SQLite 会自动建），后面才是命令。
整个程序是「跑一次做一件事」，没有常驻进程，也没有 HTTP——
**先把业务逻辑写对，再谈套界面**，这是本章刻意的选择。

## 24.2 模型：一份声明，三处复用

<!-- reflection -->
```magel
import std::sql;
import std::reflect;
import std::json;
import std::parse;

@Reflect
@std::sql::ModelClass("students")
struct Student
{
    @std::sql::ModelField(id: true)
    int64 id;
    String name;
    int64 age;
    String className;
    int64 score;
};
```

三个注解各管一件事：

| 注解 | 谁在读它 | 读了做什么 |
| --- | --- | --- |
| `@Reflect` | 反射运行期 | 让 `getStructInfo<Student>()` 能列出字段 |
| `@std::sql::ModelClass("students")` | `std::sql` | 决定表名，并据此生成建表 / 增删改查语句 |
| `@std::sql::ModelField(id: true)` | `std::sql` | 标出主键，`update` / `delete` 用它定位 |

**这就是本章最省力的地方**：加一个字段只要在这一处加一行，
建表语句、查询列、JSON 的键、排序字段的合法性检查，**全都跟着变**。
如果在三个地方各写一遍字段清单，那三处迟早会对不上。

> 反射是语言的固定组成、不可裁剪：工具链始终编入，编译流程也始终跑完整反射处理。
> 要控制**产物**写不写反射元数据，用 `--reflection` / `--no-reflection`；
> `--hard-realtime` 会禁止整个编译单元使用反射。

## 24.3 校验单独写一个函数

业务规则不要散落在各个分支里，收成一个函数，返回**空字符串表示通过**：

<!-- no-run -->
```magel
String validate(Student const& student)
{
    if (student.id <= 0)
    {
        return "学号必须是正整数";
    }
    if (student.name.trim().isEmpty() || len(student.name) > 120)
    {
        return "姓名必须为 1 到 120 字节的非空文本";
    }
    if (student.className.trim().isEmpty() || len(student.className) > 120)
    {
        return "班级必须为 1 到 120 字节的非空文本";
    }
    if (student.age < 1 || student.age > 150)
    {
        return "年龄必须在 1 到 150 之间";
    }
    if (student.score < 0 || student.score > 100)
    {
        return "成绩必须在 0 到 100 之间";
    }
    return "";
}
```

参数是 `Student const&`：**引用，不复制**（第 7 章），而且只读。
本书到第 11 章反复说过容器和结构体都是值，按值传一次就是整份复制；
只读的大对象一律写 `const&`。

注意字节长度：`len()` 数的是**字节**不是字符（第 12 章），
所以「120」是 120 个字节，中文姓名大约 40 个字。这个上限要和数据库列长度对得上。

## 24.4 反射：把结果集变成 JSON

数据库返回的是「行 × 列」的文本网格，而我们要的是 JSON。
**字段清单从反射里拿**，不在代码里再抄一遍：

<!-- no-run -->
```magel
Result<String, String> encodeRows(std::sql::ResultSet const& rows)
{
    let fields = std::reflect::getStructInfo<Student>().unwrap().fields;
    List<String> records;
    for (int64 row in std::lang::range(0, rows.rowCount()))
    {
        List<String> values;
        for (let field in fields)
        {
            int64 column = rows.columnIndex(field.name);
            if (column < 0)
            {
                return Result<String, String>::Err("数据库缺少字段：" + field.name);
            }
            String value = rows.textAt(row, column);
            if (field.typeId == std::reflect::getTypeId<String>())
            {
                value = std::reflect::__serdeQuote(value);
            }
            values.push(std::reflect::__serdeQuote(field.name) + ":" + value);
        }
        String separator = ",";
        String text = "{" + separator.join(values) + "}";
        let checked = std::json::deserialize<Student>(text);
        if (checked.isErr())
        {
            return Result<String, String>::Err("数据库记录不符合学生模型：" + checked.error());
        }
        Student student = checked.unwrap();
        String error = validate(&student);
        if (error != "")
        {
            return Result<String, String>::Err(error);
        }
        String encoded = std::json::serialize<Student>(&student)?;
        records.push(encoded);
    }
    String separator = ",";
    return Result<String, String>::Ok("[" + separator.join(records) + "]");
}
```

这里有三个值得单独看的点：

1. **`field.typeId == std::reflect::getTypeId<String>()`** —— 运行期判断字段是不是字符串，
   是才加引号。数字字段加了引号就不是合法 JSON 数字了。
2. **反序列化再序列化** —— 先 `deserialize<Student>` 让解析器和模型对一遍，
   再 `serialize<Student>` 输出。这样「数据库里存了什么脏东西」会在这一关被拦住，
   而不是一路带进输出。同一段文本走 `validate` 再走一遍，保证读出的数据也合规。
3. **`serialize<Student>(&student)?`** —— 这一句返回 `Result`，用 `?` 向外传播。
   第 16 章说过，`?` 只能用在返回 `Result` / `Option` 的函数里；`encodeRows` 的返回类型
   正好是 `Result<String, String>`，所以成立。
   **`?` 的结果先落到局部变量 `encoded` 再 `push`，不要嵌在更外层的表达式里**——
   嵌套的 `?` 会让「哪个 `?` 在往哪里传」变得难读，也更容易触发编译期的传播规则报错。

返回类型写成 `Result<String, String>`：成功是 JSON 文本，失败是诊断文本。
**没有用异常，也没有用返回码**——第 16 章那条规则在这里就是全部的出错机制。

## 24.5 命令分派：参数化查询

`execute` 负责「读命令 → 拼查询 → 执行 → 返回文本」。看 `add` / `update` 这一段：

<!-- no-run -->
```magel
if ((command == "add" || command == "update") && args.len() == 3)
{
    Student student = std::json::deserialize<Student>(args[2])?;
    String error = validate(&student);
    if (error != "")
    {
        return Result<String, String>::Err(error);
    }
    if (command == "update")
    {
        std::sql::filter<int64>(&query, "id", student.id)?;
    }
    let statement = std::sql::insert<Student>(&query, &student);
    if (command == "update")
    {
        statement = std::sql::update<Student>(&query, &student);
    }
    let prepared = statement?;
    let rows = database.exec(prepared);
    if (!rows.ok)
    {
        return Result<String, String>::Err(rows.error);
    }
    if (rows.affected != 1)
    {
        return Result<String, String>::Err("学生不存在");
    }
    String encoded = std::json::serialize<Student>(&student)?;
    return Result<String, String>::Ok(encoded);
}
```

**所有用户值都交给 `std::sql` 绑成 SQL 参数，没有一处字符串拼接。**
`filter<int64>(&query, "id", student.id)` 里的学号是绑定进去的，
不是 `"... WHERE id = " + 学号`。这是 SQL 注入的唯一正解：
不要「转义引号」，而是**根本不让用户输入成为 SQL 文本的一部分**。

`insert` / `update` 的字段和值由生成器按模型产出，同样不经过字符串拼接。
`rows.affected != 1` 用来判断「到底有没有改到那一行」——
`update` 一个不存在的学号时，SQLite 不会报错，只会影响 0 行，所以必须自己查。

`list` 的排序字段也走同一套模型信息：

<!-- no-run -->
```magel
query.orderBy(field, descending);
let prepared = query.build()?;
```

字段名不是模型的字段时，`build()` 直接拒绝：

```text
错误：模型 Student 没有字段 badfield
```

**排序方向也要自己查**：`asc` / `desc` 之外的输入会被拒绝，
不会静默当成默认排序。

## 24.6 入口：开库、建表、跑一次

<!-- no-run -->
```magel
int64 main(List<String> args)
{
    if (args.len() < 2)
    {
        println("用法：magel main.mgl 数据库路径 命令 [参数]");
        return 1;
    }
    let database = std::sql::Database::sqlite(args[0]);
    if (!database.isOpen())
    {
        println("错误：{}", database.lastError());
        return 1;
    }
    let query = std::sql::query<Student>().unwrap();
    let created = database.exec(query.build("create").unwrap());
    if (!created.ok)
    {
        println("错误：{}", created.error);
        database.close();
        return 1;
    }
    let result = execute(&database, &args);
    database.close();
    if (result.isErr())
    {
        println("错误：{}", result.error());
        return 1;
    }
    println("{}", result.unwrap());
    return 0;
}
```

结构很直白：**先建表，再执行，最后一定 `close()`**。
两条失败路径都各自关库再返回——手工管理资源时，「出错的那条路最容易忘掉清理」，
所以要把 `close()` 写在每一条退出路径上，而不是只写在正常路径末尾。

`return 1` / `return 0` 首先是给读代码的人看的：`int64 main` 的返回值**不会**成为进程退出码——
`magel` 只在编译失败或 panic 时才非 0 退出（文档只约定 `void main` 正常完成时退出码为 0）。
所以要在脚本里判断这一步做没做成，得看程序自己给出的信号：
本程序把所有失败都打印成 `错误：…` 开头的一行，成功则打印 JSON 或 `已删除`。
**别指望靠 `$?` 区分业务成败**，这是写外壳脚本时最容易想当然的地方。

## 24.8 出错时它说什么

这一章最值得模仿的不是「成功路径」，而是**每一条失败都有话说**：

| 输入 | 输出 |
| --- | --- |
| `get 999` | `错误：学生不存在` |
| `delete 999` | `错误：学生不存在` |
| `add '{"id":0,...}'` | `错误：学号必须是正整数` |
| `add '{"id":3,...,"age":200,...}'` | `错误：年龄必须在 1 到 150 之间` |
| `add '{"id":5,...,"score":101}'` | `错误：成绩必须在 0 到 100 之间` |
| `add '{"id":4,"name":"",...}'` | `错误：姓名必须为 1 到 120 字节的非空文本` |
| `add 'not-json'` | `错误：1:1: 这里只认 true / false / null [unexpected-token]` |
| `list badfield` | `错误：模型 Student 没有字段 badfield` |
| `list id sideways` | `错误：排序方向必须是 asc 或 desc` |
| `bogus` | `错误：命令或参数错误：add/update JSON；get/delete 学号；list [字段 [排序方向]]；search 姓名；schema` |

四类错误分得清清楚楚：

- **JSON 解析错误**来自 `std::json`，带行列位置和期望；
- **业务校验错误**来自 `validate`，是人话；
- **模型 / SQL 错误**来自 `std::sql`，说明哪个字段不对；
- **命令用法错误**在最后兜底，顺便把用法打出来。

没有一种是「崩了」或者「静默什么都没做」。

## 24.9 小结

- **一份模型声明，三处复用**：建表、查询列、JSON 键、排序字段检查都由它派生；
- **校验收成一个函数**，成功返回空串，失败返回人话；
- **字段清单从反射读**，不要在代码里抄第二遍；
- **所有用户输入绑成 SQL 参数**，不要拼字符串；
- **每条失败路径都要有诊断**，并且都要记得关库；
- **`?` 的结果先落局部变量**，别嵌进更外层的表达式。

## 24.11 边界与验证

反射元数据取决于编译期的注解与产物开关；换用 `--no-reflection` 或 `--hard-realtime`
构建时，`getStructInfo` 一族不可用，本示例需要写入反射元数据的产物。

模型字段变化会影响既有数据库：新增字段后旧库缺少该列，`encodeRows` 会报
「数据库缺少字段」，需要迁移或重建。文本长度按字节计，与数据库列长度要对齐。

排序与搜索依赖数据库实现；`search` 使用模糊匹配，匹配规则与排序的稳定性由
SQLite 决定，不要把当前排列当成业务上可靠的次序。

## 24.12 习题

前两题用于理解和基本实现，第三题检查边界，最后一题为综合挑战。先独立完成，再核对参考解答。

1. 给模型新增一个 `String phone` 字段，需要改几处代码？
2. 用 `add` 连续存两名学生，再用 `list score desc` 核对顺序。
3. `update` 一个不存在的学号会发生什么？为什么必须检查 `rows.affected`？
4. 挑战：把 `search` 改成同时匹配姓名和班级，并保持参数绑定。

### 参考解答与验收要点

1. 只改 `struct Student` 一处；建表、查询列、JSON 键、`schema` 输出都由反射派生。
   旧库会缺列并被「数据库缺少字段」拦下，需要迁移。
2. 以 `list` 的 JSON 数组为准核对顺序，不看插入先后。
3. SQL 不报错但影响 0 行；不检查 `rows.affected` 会把「没改到」误报成成功。
4. 用 `std::sql::filter<String>` 加两个条件，值始终由生成器绑定，不拼接 SQL 文本；
   同时覆盖空结果和多条件同时命中的情况。

## 24.13 番外：目无全牛

改编自《庄子·养生主》庖丁解牛，以下为编程主题的独立改写。

庖丁替文惠君解牛，手碰的地方、肩靠的地方、脚踩的地方、膝顶的地方，都合着节拍。
文惠君问他技艺何以至此。庖丁说，他喜欢的不是手法，是条理。

起初他看见的是一整头牛，不知道该从哪里下刀。三年之后，他不再看见整头牛。
他说的不是牛消失了，而是眼里换成了骨节与缝隙：该走哪里、哪里要绕，都在下刀之前就清楚了。

有人请他改一改刀法。他只问一句：骨节还是那些骨节吗？
对方说骨节没变，只是想让刀走得快些。庖丁便照着骨节重新排了一遍下刀的次序，
并不去记「第一刀在哪、第二刀在哪」。因为他记的从来不是刀数，是结构。

后来换了牛，骨节的位置也变了。旁人翻出旧次序照着走，刀就卡住了。
庖丁说他并没有记次序，他看的是这一头牛的骨节；次序是看清楚之后自己长出来的。

### 技术对照

反射给出的是结构信息：**字段有哪些、各是什么类型、主键是谁**。
建表语句、查询列、JSON 键、排序字段的合法性检查，都应当从这份信息派生，
而不是在代码里各抄一份清单。抄来的清单会随模型改动而失效——
正如照着旧次序下刀，换一头牛就会卡住。
