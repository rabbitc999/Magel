# 第 15 章 函数值与闭包

到目前为止，函数在你眼里还只是「一段有名字的代码」。可有时候，你并不关心那段代码叫什么，
你只想**把它本身当参数传出去**——排序时告诉程序「怎么比」，遍历时告诉它「对每个元素做什么」。

这一章讲的就是这件事：**函数也是一种值**。而且它可以**记住**定义它的地方的一些变量——
那就是闭包。

---

## 15.1 问题：逻辑一样，只有「条件」不同

写一个「从列表里筛出满足条件的元素」的函数。筛偶数是一个条件，筛大于 10 的是另一个条件：

```chali
List<int64> filter(List<int64> xs, bool fn(int64) keep)
{
    List<int64> out;
    for (int64 x in xs)
    {
        if (keep(x))
        {
            out.push(x);
        }
    }
    return out;
}

int64 main()
{
    List<int64> xs;
    xs.push(3);
    xs.push(8);
    xs.push(15);
    xs.push(42);
    List<int64> evens = filter(xs, fn(int64 x)
    {
        x % 2 == 0
    });
    List<int64> big = filter(xs, fn(int64 x)
    {
        x > 10
    });
    println("{} {}", evens[0], evens[1]);
    println("{}", big.len());
    return 0;
}
```

```text
8 42
2
```

`filter` 只管「遍历、判断、收集」，**判断的标准**由第二参数 `keep` 带进来。
`keep` 的类型是 `bool fn(int64)`——「吃一个 `int64`、吐一个 `bool` 的函数」。
传进去的两个 `fn(…)` 就是两个不同的条件。

**一个 `filter`，无数种条件。** 这就是「把函数当值」的价值。

---

## 15.2 函数类型：`R fn(A, B)`

先认这个写法：

<!-- no-run -->
```chali
int64 fn(int64, int64)  // 吃两个 int64，返回 int64
bool fn(int64)  // 吃一个 int64，返回 bool
String fn()  // 不吃参数，返回 String
```

读法从左到右：返回类型 `fn(` 参数类型 `)`。**函数类型也是类型**，
能写在变量、字段、参数、数组上——凡是你写 `int64`、`String` 的地方，都能写 `R fn(…)`。

---

## 15.3 函数可以当值用

把一个**函数名**赋给函数类型的变量，之后就能像调用原函数一样调它：

```chali
int64 add(int64 a, int64 b)
{
    return a + b;
}
int64 sub(int64 a, int64 b)
{
    return a - b;
}

int64 apply(int64 fn(int64, int64) f, int64 a, int64 b)
{
    return f(a, b);
}

int64 main()
{
    int64 fn(int64, int64) op = add;
    println("{}", op(3, 4));
    op = sub;
    println("{}", op(3, 4));
    println("{}", apply(add, 20, 22));
    return 0;
}
```

```text
7
-1
42
```

`op` 这个变量里装的是一个**函数**：

- `op = add;` 把 `add` 装进去；
- `op = sub;` 换成 `sub`——**同一个变量，指哪打哪**；
- `apply(add, 20, 22)` 把函数当普通实参传进去。

函数值能放的地方和你想象的一样多——字段、数组都行：

```chali
struct Calculator
{
    int64 fn(int64, int64) op;
};

int64 add(int64 a, int64 b)
{
    return a + b;
}
int64 mul(int64 a, int64 b)
{
    return a * b;
}

int64 main()
{
    Calculator c;
    c.op = mul;
    println("{}", c.op(3, 4));

    int64 fn(int64, int64) table[2];
    table[0] = add;
    table[1] = mul;
    println("{} {}", table[0](6, 7), table[1](6, 7));
    return 0;
}
```

```text
12
13 42
```

`table` 是一张「操作表」，按下标取函数来调——这是实现「操作码分派」最朴素的写法。

## 15.4 `fn`：现场写一个小函数

`add` / `sub` 都是**提前定义好、有名字**的函数。可很多时候，你只想**当场写一小段逻辑**，
懒得给它起名。这就是 `fn`：

```chali
int64 main()
{
    int64 fn(int64) square = int64 fn(int64 x)
    {
        x * x
    };
    println("{}", square(6));

    let cube = fn(int64 x)
    {
        x * x * x
    };
    println("{}", cube(3));
    return 0;
}
```

```text
36
27
```

写法拆开看：`返回类型 fn(参数) { 体 }`。

- `fn` 是关键字；
- `(int64 x)` 跟普通函数的参数一模一样；
- `fn` 前面的 `int64` 是返回类型，**可以省略**（`cube` 那份就没写，编译器自己推）；
- `{ … }` 是函数体。

`let cube = …` 让编译器根据右边推出 `cube` 的类型——省得手写一长串 `int64 fn(int64)`。

---

## 15.5 省略参数类型：靠上下文推

如果 `fn` 是要**传给某个参数**的，而那个参数的类型是已知的，那么连**参数类型都能省**——
编译器按上下文补上：

```chali
int64 apply(int64 fn(int64, int64) f, int64 a, int64 b)
{
    return f(a, b);
}

int64 main()
{
    println("{}", apply(fn(x, y)
    {
        x + y
    }, 3, 4));
    println("{}", apply(fn(x, y)
    {
        x * y
    }, 3, 4));
    return 0;
}
```

```text
7
12
```

`apply` 的第一参数类型是 `int64 fn(int64, int64)`，所以 `fn(x, y)` 里的
`x` / `y` 自动就是 `int64`。这种「看上下文定类型」的能力，让 `fn` 写起来非常轻。

> 但别滥用。参数类型省掉后，读代码的人得自己回头找上下文。**类型不是一眼能看出来的地方，
> 就老老实实写上。**

---

## 15.6 闭包：记住定义处的变量

`fn` 最厉害的地方，是它能**看见外面的变量**：

```chali
int64 main()
{
    int64 base = 10;
    let addBase = fn(int64 x)
    {
        x + base
    };
    base = 100;
    println("{}", addBase(5));
    return 0;
}
```

```text
105
```

`addBase(5)` 读到的是**调用那一刻** `base` 的值 100，所以输出 105。
换句话说，闭包里那个 `base` **不是一份拷贝，而是一条指向外部变量的线**。

这条线就叫**捕获（capture）**：闭包把外部变量"抓"进来，从此你在闭包里读写它，
读写的其实是外面那个变量本身。

> **默认捕获是只读借用。** 不写任何修饰时，闭包按 `const&` 抓住外部变量：
> 能读、能看到外面的新值，但**不能改**。想改就得显式声明，见 15.7 节。

---

## 15.7 四种捕获方式

捕获方式写在 `fn` 关键字后面，一共四种：

| 写法 | 名称 | 闭包里能改？ | 外面那个变量 | 寿命限制 |
| --- | --- | --- | --- | --- |
| `fn const(...)`（也是默认） | 只读借用 `const&` | 不能改 | 不受影响 | 来源要活过闭包 |
| `fn mut(...)` | 可变借用 `mut&` | 能改 | **跟着变** | 来源要活过闭包 |
| `fn copy(...)` | 拥有副本 | 能改（改副本） | 不受影响 | 无，自己有一份 |
| `fn move(...)` | 转移所有权 | 能改（独占） | 被搬走，须重新声明 | 无，自己有一份 |

一句话区分：**`const&` / `mut&` 是"借"，`copy` / `move` 是"拿"。**
借来的东西要还，所以有寿命限制；拿了就是自己的，想活多久活多久。

### 15.7.1 `const&`：默认，只读借用

不写修饰就是它，写 `const` 也是它——下面两种写法完全等价：

```chali
int64 main()
{
    int64 n = 1;
    let implicit = int64 fn()
    {
        n
    };
    /* 默认：const& */
    let explicit = int64 fn const()
    {
        n
    };
    /* 写全，同一个意思 */
    n = 2;
    println("{} {}", implicit(), explicit());
    return 0;
}
```

```text
2 2
```

两者都**跟着外面的新值走**（`n` 改成 2 之后读出来就是 2）。
想在闭包里改它，编译器直接拦下：

<!-- fail -->
```chali
int64 main()
{
    int64 base = 10;
    let bump = fn(int64 x)
    {
        base += x;
        return base;
    };
    println("{}", bump(1));
    return 0;
}
```

```text
chali: 不可变变量（const）不能再赋值：base
```

### 15.7.2 `mut&`：写回来源

```chali
int64 main()
{
    int64 counter = 0;
    let tick = fn mut()
    {
        counter += 1;
        return counter;
    };
    println("{} {}", tick(), tick());
    println("outside {}", counter);
    return 0;
}
```

```text
1 2
outside 2
```

闭包里的 `counter` **就是外面那个 `counter`**：两次 `tick()` 累加到 2，
外面读出来也是 2。这是写**计数器、累加器**最直接的写法。

### 15.7.3 `copy`：拿一份独立副本

```chali
int64 main()
{
    int64 n = 5;
    let independent = int64 fn copy(int64 x)
    {
        n += x;
        return n;
    };
    n = 100;
    println("{} {} {}", independent(2), independent(1), n);
    return 0;
}
```

```text
7 8 100
```

闭包从 `n = 5` 起家，之后外面把 `n` 改成 100 **跟它没关系**：
它自己从 5 加到 7、再加到 8，外面始终是 100。

副本对 `String`、`List` 这类带资源的值同样成立——闭包内部改的是自己那一份：

```chali
int64 main()
{
    String text = "old";
    let grow = String fn copy()
    {
        text = text + "!";
        return text;
    };
    text = "outside";
    println("{} / {} / {}", grow(), grow(), text);
    return 0;
}
```

```text
old! / old!! / outside
```

```chali
int64 main()
{
    List<int64> values;
    values.push(4);
    let bump = int64 fn copy()
    {
        values[0] += 1;
        return values[0];
    };
    println("{} {} {}", bump(), bump(), values[0]);
    return 0;
}
```

```text
5 6 4
```

`copy` 还有个额外好处：**即使来源是 `const` 也能拷**——拷出来的是一份新值，
动不到原值：

```chali
int64 main()
{
    const int64 fixed = 7;
    let change = int64 fn copy()
    {
        fixed += 1;
        return fixed;
    };
    println("{} / {}", change(), fixed);
    return 0;
}
```

```text
8 / 7
```

### 15.7.4 `move`：把来源整个搬进闭包

```chali
int64 main()
{
    String moved = "payload";
    let take = String fn move()
    {
        return moved + "-in";
    };
    String moved = "reset";
    println("{} / {}", take(), moved);
    return 0;
}
```

```text
payload-in / reset
```

`move` 之后，原来的 `moved` **已经被搬空**，不能再用——除非重新声明同名变量。
上面就是在 `move` 之后立刻 `String moved = "reset";` 创建一个新的同名绑定。

没有重新声明就接着读写旧绑定，编译器会拦：

<!-- fail -->
```chali
int64 main()
{
    String moved = "payload";
    let take = String fn move()
    {
        return moved;
    };
    println("{}", moved);
    return 0;
}
```

```text
chali: [CHL1205] 借用来源已移动或销毁，不能继续访问（源对象已经销毁）：moved
```

> **`copy` 还是 `move`？** 之后还要用原值 → `copy`；原值从此归闭包 → `move`。
> 对 `String` / `List` / 带 `Drop` 的 struct，`move` 省一次拷贝，代价是来源作废。

### 15.7.5 同一个变量既借又 `move`：看最后一次使用

创建借用闭包之后，可以把来源移进另一个闭包；关键是旧借用闭包不能在来源作废后继续使用。下面的 `f(1)` 会被编译器以 `CHL1205` 拒绝，不会进入 VM 执行：

<!-- no-run -->
```chali
void main()
{
    int64 n = 1;
    let f = int64 fn mut(int64 x)
    {
        n += x;
        return n;
    };
    let g = int64 fn move(int64 x)
    {
        return x * n;
    };
    println("f={}", f(1));
    println("g={}", g(1));
}
```

问题出在第三步：`f` 借用 `n`，`g` 随后把 `n` 搬走，最后却又调用 `f`。闭包的副本仍然借用原来的来源，复制 `f` 也不能绕开这个检查。显式销毁或释放来源之后再使用借用闭包，同样会被拒绝。

如果先调用完 `f`，再创建 `g`，并且此后不再使用 `f`，这个顺序可以通过：

<!-- verify-book -->
```chali
int64 main()
{
    int64 n = 1;
    let f = int64 fn mut(int64 x)
    {
        n += x;
        return n;
    };
    println("{}", f(1));
    let g = int64 fn move(int64 x)
    {
        return x * n;
    };
    println("{}", g(3));
    return 0;
}
```

```text
2
6
```

两个闭包需要交替使用时，可以让其中一个拥有快照：

<!-- verify-book -->
```chali
int64 main()
{
    int64 n = 1;
    let f = fn mut(x) { n = x + n };
    let g = fn copy(x) { x * n };
    println("{} {} {}", f(1), g(1), n);
    return 0;
}
```

```text
2 1 2
```

`g` 用 `fn copy` 拿走的是创建闭包那一刻的快照（`n = 1`），`n` 不会再被搬空，
`f` 那条线始终有效。

## 15.8 捕获列表：逐个变量指定方式

`fn mut(...)` 是"**所有**外部变量都按 `mut&` 抓"。想给不同变量不同待遇，
就在 `fn` 后面加一对方括号：

```chali
int64 main()
{
    int64 a = 2;
    int64 b = 3;
    int64 c = 4;
    int64 d = 5;
    let mixed = int64 fn copy[a] mut[b] const[c] move[d](int64 x)
    {
        a += x;
        b += x;
        d += x;
        return a + b + c + d;
    };
    a = 100;
    c = 10;
    d = 200;
    println("{} | a={} b={} c={} d={}", mixed(1), a, b, c, d);
    println("{} | b={}", mixed(1), b);
    return 0;
}
```

```text
23 | a=100 b=4 c=10 d=200
26 | b=5
```

逐个看：`a` 拷了一份（外面改 100 不影响它），`b` 借用（闭包加 1 后外面就是 4），
`c` 只读借用（不能改，但能看到新值 10），`d` 被搬进闭包（外面重新赋成 200 是另一回事）。

**其余变量的默认捕获方式。** 列表后面还能指定未单独列出的变量采用什么方式捕获。

<!-- no-run -->
```chali
fn copy[a, b] mut(int64 x)
{
    ...
}
/*     ^^^^^^^^^^ ^^^                         */
/*     a、b 按 copy 抓，其余变量按 mut& 抓     */
```

```chali
int64 main()
{
    int64 left = 1;
    int64 right = 2;
    int64 shared = 3;
    let f = int64 fn copy[left, right] mut(int64 x)
    {
        left += x;
        right += x;
        shared += x;
        return left + right + shared;
    };
    println("{} | left={} right={} shared={}", f(1), left, right, shared);
    return 0;
}
```

```text
9 | left=1 right=2 shared=4
```

`left` / `right` 是副本（外面不动），`shared` 没列出、按默认 `mut&` 借用，
所以闭包加完之后外面读到的 `shared` 变成了 4。

不写默认方式时，**没列出的变量一律按 `const&` 抓**——和全局默认一致。
默认方式只能写一次，写两个会报错：

<!-- fail -->
```chali
int64 main()
{
    int64 a = 1;
    let f = int64 fn copy[a] mut const()
    {
        a
    };
    println("{}", f());
    return 0;
}
```

```text
chali: lambda：lambda 默认捕获方式只能声明一次：mut 与 const
```

方括号也可以是空的——`fn copy[](...)` 表示"一个都不特殊对待"，
其余变量仍按默认 `const&`：

```chali
int64 main()
{
    int64 bias = 9;
    let empty = int64 fn copy[]()
    {
        bias
    };
    bias = 10;
    println("{}", empty());
    return 0;
}
```

```text
10
```

传给函数参数的 `fn` 同样能带捕获列表：

```chali
int64 apply(int64 fn(int64) f, int64 x)
{
    return f(x);
}
int64 main()
{
    int64 bias = 9;
    println("{} / {}", apply(fn copy[bias](x)
    {
        bias += x;
        return bias;
    }, 2), bias);
    return 0;
}
```

```text
11 / 9
```

## 15.9 复制闭包：拥有状态会复制，借用仍然共享

闭包是值，能赋给另一个变量。那复制过去的到底是什么？

**答案是：拥有的东西各复制一份，借的东西还是同一条线。**

`copy` 捕获的闭包复制后，两份副本**互不相干**：

```chali
int64 main()
{
    int64 n = 5;
    let a = int64 fn copy(int64 x)
    {
        n += x;
        return n;
    };
    let b = a;
    println("b={} a={} b={}", b(3), a(1), b(1));
    return 0;
}
```

```text
b=8 a=6 b=9
```

`a`、`b` 各有一份从 5 开始的副本：`b` 先加到 8，`a` 加到 6，`b` 再加到 9——
三笔独立的账。

而 `mut&` 捕获的闭包复制后，**两个闭包仍指向同一个来源**：

```chali
int64 main()
{
    int64 n = 0;
    let a = int64 fn mut(int64 x)
    {
        n += x;
        return n;
    };
    let b = a;
    println("a={} b={} outside={}", a(1), b(1), n);
    return 0;
}
```

```text
a=1 b=2 outside=2
```

`a` 加完 `n` 是 1，`b` 接着加变成 2，外面读也是 2——**同一个 `n`，同一条线**。

## 15.10 生命周期：借来的，不能活过来源

`const&` / `mut&` 是借用，就有一条铁律：

> **闭包（以及它的任何副本）不能比它借的那个变量活得更久。**

最容易踩的地方是**把闭包返回出去**：

<!-- fail -->
```chali
int64 fn() counter()
{
    int64 n = 4;
    return int64 fn mut()
    {
        n += 1;
        return n;
    };
}
int64 main()
{
    let c = counter();
    println("{}", c());
    return 0;
}
```

```text
chali: [CHL1204] 返回值中的引用不能超过局部来源的生命周期
```

`n` 是 `counter` 的局部变量，函数一返回它就没了；闭包要是带走了它的引用，
调用时访问的就是一块已经死掉的内存。编译器不放行（报错里还会附上那个来源的名字）。

换成 `copy` 或 `move`，闭包**自己拥有一份**，就能安全返回：

```chali
int64 fn() counter()
{
    int64 n = 4;
    return int64 fn copy()
    {
        n += 1;
        return n;
    };
}
int64 main()
{
    let c = counter();
    println("{} {}", c(), c());
    return 0;
}
```

```text
5 6
```

`move` 同理——把 `n` 搬进闭包，闭包从此自带状态：

```chali
int64 fn() counter()
{
    int64 n = 8;
    return int64 fn move()
    {
        n += 1;
        return n;
    };
}
int64 main()
{
    let c = counter();
    println("{} {}", c(), c());
    return 0;
}
```

```text
9 10
```

**判断口诀：闭包要返回 → 捕获只能是 `copy` / `move`，或者是借"调用方"的东西。**

最后半句正是 15.14 节"闭包当工厂"的做法：借用**调用方**传进来的指针，
那个变量活在外面，闭包带回去才安全。

## 15.11 带 `Drop` 的类型：谁负责销毁

如果捕获的是带 `Drop` 的类型（有 `void drop()` 的 struct），
所有权规则就直接体现为**什么时候调用 `drop()`**。

`copy` 捕获 → 外面那个值和闭包里的副本是**两个对象**，各销毁一次：

```chali
int64 drops = 0;
struct Record: Drop
{
    String text;
    List<int64> values;
    void drop()
    {
        drops += 1;
    }
};
int64 main()
{
    Record record;
    record.text = "owned";
    record.values.push(1);
    {
        let own = int64 fn copy()
        {
            record.values[0] += 1;
            return record.values[0];
        };
        println("own={}", own());
        {
            let second = own;
            println("second={} drops={}", second(), drops);
        }
        println("drops={}", drops);
    }
    println("drops={} outside={}", drops, record.values[0]);
    return 0;
}
```

```text
own=2
second=3 drops=0
drops=1
drops=2 outside=1
```

`second` 出作用域销毁一份副本（`drops=1`），`own` 出作用域再销毁一份（`drops=2`）。
全程外面 `record.values[0]` 一直是 1——副本里加多少都影响不到它。

`move` 捕获 → 对象被搬进闭包，**只有闭包销毁时**才 `drop()`：

```chali
int64 drops = 0;
struct Record: Drop
{
    String text;
    List<int64> values;
    void drop()
    {
        drops += 1;
    }
};
int64 main()
{
    Record record;
    record.text = "moved";
    record.values.push(10);
    {
        let own = int64 fn move()
        {
            record.values[0] += 1;
            return record.values[0];
        };
        println("own={} drops={}", own(), drops);
    }
    println("drops={}", drops);
    return 0;
}
```

```text
own=11 drops=0
drops=1
```

闭包出作用域 → 它拥有的那个 `Record` 被销毁 → `drops` 从 0 变 1，全程只有一次。

## 15.12 捕获方式速查

| 写法 | 闭包内能改？ | 外面跟着变？ | 来源还能用？ | 能返回出去？ |
| --- | --- | --- | --- | --- |
| `fn(...)` / `fn const(...)` | 否 | — | 能 | 借用来源寿命足够时能 |
| `fn mut(...)` | 是 | **是** | 能 | 借用来源寿命足够时能 |
| `fn copy(...)` | 是 | 否 | 能 | 不含短寿命借用时能 |
| `fn move(...)` | 是 | 否 | 需重新声明 | 不含短寿命借用时能 |
| `fn copy[a] mut[b] const[c] move[d](...)` | 各按各的 | 各按各的 | 各按各的 | 所有借用来源寿命足够时能 |
| `fn copy[a, b] mut(...)` | 其余按 `mut&` | — | — | 取决于借用来源寿命 |

容易忘的几条：

- **默认就是 `const&`**——不写 `mut` 就改不了外面的变量。
- **`mut` 改的是外面那个**，不是副本；想各算各的用 `copy`。
- **`move` 之后来源作废**，须重新声明新绑定，普通赋值不能恢复。
- **借用本次调用局部变量的闭包不能返回**；需要自有状态时用 `copy` / `move`。借用调用方提供的对象仍须满足来源寿命。
- **借用闭包的最后一次使用要在来源作废之前**：先用完再 `move` 可以通过；
  `move` 后再使用旧借用闭包会报 `CHL1205`（见 15.7.5）。
- **复制闭包**：拥有的状态各复制一份，借用的线仍指向同一来源。

## 15.13 一个小坑：表达式体 vs 语句体

`fn` 的体有两种写法，差别就一个**分号**：

```chali
let f = fn(int64 x)
{
    x * 2
};
// 表达式体：没有分号
let g = fn(int64 x)
{
    return x * 2;
};
// 语句体：有分号 + return
```

**表达式体**是「一个表达式」，直接就是返回值——**末尾不能带分号**。
一旦你手滑写成 `{ x * 3; }`（带分号），它就成了一「条语句」，编译器会要求你补 `return`：

<!-- fail -->
```chali
int64 main()
{
    let g = int64 fn(int64 x)
    {
        x * 3;
    };
    println("{}", g(5));
    return 0;
}
```

```text
chali: 返回类型为 int64 的函数 __chali_lambda_… 不是所有路径都有 return
```

记住一句话：**体里想要「最后一行的值」当返回值 → 别加分号；想用 `return` → 加分号。**

## 15.14 闭包当工厂：返回一个函数

15.10 节说过：借用的闭包不能返回。想让工厂函数产出一个闭包，捕获来源就得由
**调用方**提供——让调用方把变量的**地址**传进来，那个变量活在外面，
闭包把它带回去才安全：

```chali
int64 fn(int64) makeAdder(int64 mut& amount)
{
    return fn(int64 value)
    {
        value + amount
    };
}
int64 main()
{
    int64 one = 1;
    int64 ten = 10;
    let plus1 = makeAdder(&one);
    let plus10 = makeAdder(&ten);
    println("{} {}", plus1(5), plus10(5));
    return 0;
}
```

```text
6 15
```

`makeAdder(&one)` 和 `makeAdder(&ten)` 返回的 `plus1` / `plus10`，各自借着
`one` / `ten`：只要这两个变量还在，两个闭包就一直能用；它们要是先没了，
闭包也就跟着失效——这正是 15.10 那条铁律的另一面。

函数值本身可以复制；复制闭包时到底复制了什么，见 15.9 节。

## 15.15 语句级具名闭包

如果你希望给局部闭包直接起名字，可以写成 `返回类型 名字(参数) { ... }`。它仍是函数值，只在声明语句位置识别，不能塞进另一个表达式中间。返回类型是检查函数体的类型锚点。

<!-- verify-book -->
```chali
int64 fn() makeNamedCounter()
{
    int64 current = 0;
    int64 next() move
    {
        current++;
        return current;
    }
    return next;
}

int64 main()
{
    int64 base = 10;
    int64 read()
    {
        return base;
    }
    int64 increment() mut
    {
        base++;
        return base;
    }
    int64 isolated() copy
    {
        base += 100;
        return base;
    }
    int64 initial = read();
    int64 changed = increment();
    int64 snapshot = isolated();
    println("{} {} {} {}", initial, changed, snapshot, base);

    let counter = makeNamedCounter();
    int64 first = counter();
    int64 second = counter();
    println("{} {}", first, second);

    int64 callback(int64 value);
    callback = int64 fn(int64 value)
    {
        return value + 1;
    };
    println("{}", callback(5));
    return 0;
}
```

```text
10 11 110 11
1 2
6
```

默认捕获方式是 `const&`，因此 `read` 能看到来源后续的变化，却不能修改来源。函数体前显式写 `mut` 是可写借用，`copy` 拥有独立状态，`move` 则接管捕获值的所有权。捕获状态在声明初始化时交给函数名绑定；普通后续赋值仍遵守值语义。

局部 `int64 callback(int64 value);` 只声明一个有确定签名的函数变量，后面再赋函数值；它与模块层的宿主函数声明不是同一个语义入口。借用捕获的闭包不能逃出来源的生命周期。工厂函数中的 `next` 使用 move 拥有状态，所以可安全返回；把它改成默认借用并返回会报错。


## 15.16 多层高阶闭包：函数也可以接收函数

`R fn(A)` 表示“接收 `A`、返回 `R` 的函数值”。这里的 `A` 也可以是函数类型，因此 `fn` 可以继续嵌套。下面保留五层嵌套的完整写法，并通过参数名和换行区分两个实参：

```chali
int64 hello(
    int64 fn(int64 fn(int64 fn(int64 fn(int64 fn(int64))))) pipeline,
    int64 fn(int64) finish)
{
    return finish(pipeline(level4));
}
```

这里是具名函数声明；有函数体时，模块层声明在右大括号结束，后面不加分号。形参要有名字，函数体才能调用它们。`fn` 后的小括号属于函数类型，不是一次函数调用。

由内向外阅读第一项形参的类型：

| 层次 | 接收什么 | 返回什么 | 下方程序中的值 |
| --- | --- | --- | --- |
| 第一层 | `int64` | `int64` | `level1` |
| 第二层 | 第一层函数 | `int64` | `level2` |
| 第三层 | 第二层函数 | `int64` | `level3` |
| 第四层 | 第三层函数 | `int64` | `level4` |
| 第五层 | 第四层函数 | `int64` | `level5` |

这些层次表示参数类型的嵌套深度，不表示连续调用五次后才得到一个返回函数；表中每一层的返回类型都是 `int64`。`hello` 的第一项实参是第五层函数，第二项实参是普通的一元闭包。

完整程序如下。最后的 `finish` 捕获了 `main` 中的 `factor`，因此这同时展示了高阶函数参数与带状态的闭包：

<!-- verify-book -->
```chali
int64 level1(int64 value)
{
    return value + 1;
}

int64 level2(int64 fn(int64) callback)
{
    return callback(10);
}

int64 level3(int64 fn(int64 fn(int64)) callback)
{
    return callback(level1);
}

int64 level4(int64 fn(int64 fn(int64 fn(int64))) callback)
{
    return callback(level2);
}

int64 level5(int64 fn(int64 fn(int64 fn(int64 fn(int64)))) callback)
{
    return callback(level3);
}

int64 hello(
    int64 fn(int64 fn(int64 fn(int64 fn(int64 fn(int64))))) pipeline,
    int64 fn(int64) finish)
{
    return finish(pipeline(level4));
}

int64 main()
{
    int64 factor = 2;
    int64 finish(int64 value)
    {
        return value * factor;
    }
    println("{}", hello(level5, finish));
    return 0;
}
```

```text
22
```

调用顺序是 `pipeline(level4)` → `level4(level3)` → `level3(level2)` → `level2(level1)` → `level1(10)`，先得到 `11`；随后 `finish(11)` 读取捕获的 `factor`，得到 `22`。具名函数和闭包都按各自的完整函数类型检查，某一层参数类型不匹配就不能传入。

`finish` 默认以 `const&` 借用 `factor`。这次调用在 `main` 的作用域内同步完成，借用始终有效。若要把这样的闭包返回或存到更长寿命的对象中，仍须满足前面介绍的捕获与生命周期规则；嵌套 `fn` 类型不会延长被借用变量的寿命。

## 15.17 组合闭包：接收函数，再返回函数

高阶函数还可以把几个操作组合成新的函数值。下面的 `combine` 接收两个 `int64 fn(int64)`，返回的类型也是 `int64 fn(int64)`：

```chali
let combine = (int64 fn(int64)) fn(int64 fn(int64) a, int64 fn(int64) b)
{
    int64 fn copy(int64 x)
    {
        a(b(x))
    }
};
```

从左到右拆开这个声明：括号里的 `int64 fn(int64)` 是返回类型，接下来的 `fn(...)` 才是创建组合器的匿名函数。它的函数体每次创建一个新闭包，先调用 `b`，再把结果交给 `a`。内层的 `a(b(x))` 与外层的闭包表达式都处在块末尾且不加分号，分别成为两层函数的返回值。

返回函数类型外面的括号用于分组，不会增加一层函数类型；也可以直接写 `int64 fn(int64) fn(...)`。参数列表最后一个参数后面不加逗号。与上一节的具名函数定义不同，这里是变量初始化语句，最外层右大括号后面需要分号。

完整程序如下：

<!-- verify-book -->
```chali
int64 main()
{
    let combine = (int64 fn(int64)) fn(int64 fn(int64) a, int64 fn(int64) b)
    {
        int64 fn copy(int64 x)
        {
            a(b(x))
        }
    };

    let f1 = int64 fn(int64 x) { x + 1 };
    let f2 = int64 fn(int64 x) { x * 2 };
    let c1 = combine(f1, f2);
    let c2 = combine(f2, f1);
    println("{} {}", c1(5), c2(5));

    let c3 = combine(fn(x) { x * 5 }, fn(x) { x - 1 });
    println("{}", c3(5));
    return 0;
}
```

```text
11 12
20
```

`c1(5)` 先执行 `f2(5)` 得到 `10`，再执行 `f1(10)` 得到 `11`；`c2(5)` 先执行 `f1(5)` 得到 `6`，再执行 `f2(6)` 得到 `12`。两次调用各自返回一个拥有 `a`、`b` 副本的组合闭包，交换实参会改变组合顺序。

内层函数不能默认借用本次调用的局部形参 `a`、`b` 后直接返回；这些形参会随 `combine` 返回而离开作用域。`fn copy` 使返回闭包拥有这两个函数值的副本。本例的 `f1`、`f2` 都没有捕获外部变量；如果它们含有借用，复制函数值不会把被借用对象变成自有状态，其来源仍必须活得足够久。

`c3` 直接把两个匿名函数作为实参传入。目标形参 `int64 fn(int64)` 为 `fn(x)` 提供参数类型与返回类型的上下文，因此两个 `x` 都推断为 `int64`，不必重复写类型。组合顺序仍然是先执行第二项实参，再执行第一项实参：`(5 - 1) * 5 = 20`。这些匿名函数没有捕获状态，传入后同样由组合闭包持有其副本。

## 15.18 泛型闭包：同一份状态，多种参数类型

闭包也能声明类型参数。`fn<T>(T value)` 中的 `T` 在调用时确定，通常可以从实参推导；需要指定时写 `f<int64>(3)`。具体实现体决定返回类型。

特化沿用主定义的名称：`f<int64> = fn(int64 value) { ... };` 是完整特化，`f<T, int64> = fn(T first, int64 second) { ... };` 是偏特化。编译器选择唯一最具体的匹配；重复定义和无法区分的重叠模式会报错。它们是编译期声明，不是在运行时给闭包重新赋值。

泛型闭包可以直接成为结构体成员。普通闭包和泛型闭包也都可以传给泛型类型参数 `F`；`apply` 里的 `F` 由实参推导，不必写出一个固定的函数指针签名。

<!-- verify-book -->
```chali
struct Mapper
{
    let transform = fn<T>(T value)
    {
        value
    };
    transform<int64> = fn(int64 value)
    {
        value + 1
    };
};

int64 apply<F>(F operation, int64 value)
{
    return operation(value);
}

int64 main()
{
    let identity = fn<T>(T value)
    {
        value
    };
    Mapper mapper;
    println("{} {} {}", mapper.transform(2), mapper.transform<String>("member"), apply(identity, 4));
    return 0;
}
```

```text
3 member 4
```

闭包作为 `F` 传递后，仍保留捕获环境，也能放进 `Box<F>` 这样的泛型聚合。借用来源的寿命要求不会因为经过泛型而消失。

不同类型的调用共享同一个闭包的状态。下面的 `count` 在创建 `next` 时复制一次；`bool`、`int64` 和 `String` 调用都修改这份副本，完整特化也不另建环境。

<!-- verify-book -->
```chali
int64 main()
{
    int64 count = 0;
    let next = fn<T> copy[count](T value)
    {
        count += 1;
        return count;
    };
    next<int64> = fn(int64 value)
    {
        count += 10;
        return count;
    };
    println("{} {} {} {}", next(true), next(2), next("text"), count);
    return 0;
}
```

```text
1 11 12 0
```

特化沿用主定义的捕获方式；要获得另一份独立状态，复制整个闭包。默认借用、`mut`、`copy`、`move` 仍按本章前面的规则处理，来源作废后使用借用闭包仍会被拒绝。

## 15.19 小结

| 你会了 | 关键点 |
| --- | --- |
| 函数类型 | `R fn(A, B)`，和别的类型一样能当变量/字段/参数 |
| 函数当值 | `int64 fn(int64, int64) op = add;`，可重新指向 |
| 传函数 | 把函数名或 `fn` 当实参传，实现回调 |
| `fn` | `返回类型 fn(参数) { 体 }`，返回类型可省 |
| 上下文推断 | 目标类型已知时，参数类型也能省 |
| 闭包 | 记住定义处的变量；默认 `const&` 只读借用 |
| 四种捕获 | `const&` 只读、`mut&` 写回、`copy` 独立副本、`move` 转移所有权 |
| 捕获列表 | `fn copy[a] mut[b] const[c] move[d](...)`；列表后可加默认方式 |
| 复制闭包 | 拥有状态各复制一份，借用仍指向同一来源 |
| 生命周期 | 借用的闭包（及其副本）不能比来源活得更久 |
| 返回闭包 | 只有 `copy` / `move`、或借调用方的指针，才能安全带出函数 |
| `Drop` | `copy` 两份各销毁一次，`move` 只在闭包销毁时销毁一次 |
| 体例坑 | 表达式体**别加分号**；用 `return` 就要加分号 |
| 工厂 | 返回闭包，配不同的「料」造出不同的函数 |

## 15.21 边界与验证

4. 挑战：将一个捕获局部变量而逃逸的反例修复为合法版本。

### 参考解答与验收要点

1. 默认读取来源，mut 允许借用写回，copy 拥有独立副本，move 转移拥有关系；仍需遵守各自类型和生命周期要求。
2. 让返回结果拥有所需状态，离开构造函数后调用仍有效；不要以延长局部变量存活作为解释。
3. 记录两份闭包各自的返回序列；与显式共享对象的捕获情形分开。
4. 先证明反例因借用来源失效被拒绝，再根据需要选择拥有副本或转移，验证调用结果。

## 15.23 番外：孔乙己与闭包

改写自鲁迅《孔乙己》，正文采用本书读者提供的改编稿。人物对白中的判断不代替本章的语言规则。

鲁镇的码栈的格局，是和别处不同的：都是当街一个曲尺形的大柜台，柜里面预备着服务器，可以随时跑代码。做工的人，傍午傍晚散了工，每每花四文铜钱，开一个沙箱——这是二十多年前的事，现在每个沙箱要涨到十文——靠柜外站着，快快地编译了休息；倘肯多花一文，便可以买一碟调试用例，或者跑一段开心代码，做练手项目了；如果能出到十几文，那就可以买一个完整项目。但这些顾客，多是短衣帮，大抵没有这样阔绰。只有穿格子衫的，才踱进店面隔壁的房子里，要项目要算力，慢慢地坐写。

我从十二岁起，便在镇口的咸亨码栈里当伙计。掌柜说，样子太傻，怕侍候不了格子衫主顾，就在外面做点事罢。外面的短衣主顾，虽然容易说话，但唠唠叨叨缠夹不清的也很不少。他们往往要亲眼看着代码从沙箱里拉出，看过你的代码有没有水，又亲看将沙箱放到服务器上，然后放心。在这严重监督下，掺水也很为难。所以过了几天，掌柜又说我干不了这事。幸亏荐头的情面大，辞退不得，便改为专管跑代码的一种无聊职务了。

我从此便整天地站在柜台里，专管我的职务。虽然没有什么失职，但总觉得有些单调，有些无聊。掌柜是一副凶脸孔，主顾也没有好声气，教人活泼不得；只有孔乙己到店，才可以笑几声，所以至今还记得。

孔乙己是站着接单而穿格子衫的唯一的人。他身材很高大；青白脸色，皱纹间时常夹些伤痕；一部乱蓬蓬的花白胡子。穿的虽然是格子衫，可是又脏又破，似乎十多年没有补，也没有洗。他对人说话，总是满口捕获借用，教人半懂不懂的。因为他姓孔，别人便从描红纸上的“上大人孔乙己”这半懂不懂的话里，替他取下一个绰号，叫作孔乙己。

孔乙己一到店，所有写代码的人便都看着他笑。有的叫道：“孔乙己，你头顶又空出一块了！”

他不回答，只对柜里说：“开两个沙箱，跑一段开心代码。”说完，排出九文大钱。

他们又故意高声嚷道：“你一定又写返回闭包了！”

孔乙己睁大眼睛说：“你怎么这样凭空污人清白……”

“什么清白？我前天亲眼见你写了个返回闭包，被编译器报 CHL1204，吊着打。”

孔乙己便涨红了脸，额上的青筋条条绽出，争辩道：“借用不能算逃逸……闭包！……程序员的事，能算逃逸么？”

接着，便是一串难懂的话，什么“const& 只读”，什么“mut& 写回”之类，引得众人都哄笑起来。店内外充满了快活的空气。

听人家背地里谈论，孔乙己原来也读过书，还钻研过语言设计，但终于没有当程序员，又不会营生。于是愈过愈穷，弄到将要断网了。幸而写得一手好代码，便替人家敲敲代码，接点外包，换一点托管费。

可惜他又有一样坏脾气，便是好闲懒做。坐不到几天，便连人和电脑键盘鼠标，一齐失踪。如是几次，叫他接外包的人也没有了。

孔乙己没有法，便免不了偶然做些偷窃的事。但他在我们店里，品行却比别人都好，就是从不拖欠。虽然间或没有现钱，暂时记在粉板上，但不出一月，定然还清，从粉板上拭去了孔乙己的名字。

孔乙己跑过半段代码，涨红的脸色渐渐复原。旁人便又问道：“孔乙己，你当真会闭包么？”

孔乙己看着问他的人，显出不屑置辩的神气。

他们便接着说道：“你怎的连半个 counter 也捞不到呢？”

孔乙己立刻显出颓唐不安模样，脸上笼上了一层灰色。嘴里说些话，这回全是“默认捕获是只读借用”之类，一句也听不懂了。

这时候，众人也都哄笑起来。店内外充满了快活的空气。

在这些时候，我可以附和着笑，掌柜是决不责备的。而且掌柜见了孔乙己，也每每这样问他，引人发笑。

孔乙己自己知道不能和他们谈天，便只好向孩子说话。

有一回，他对我说道：“你读过书么？”

我略略点一点头。

他说：“读过书……我便考你一考。闭包的捕获方式，有几种？”

我想，连沙箱都开不起的人，也配考我么？便回过脸去，不再理会。

孔乙己等了许久，很恳切地说道：“不能写罢？……我教给你，记着！这些方式应该记着。将来写回调的时候，要用。”

我暗想，我和写回调的还差得远呢。再说，我们掌柜也从不把闭包上账。我又好笑，又不耐烦，懒懒地答他：“谁要你教，不是四种么？”

孔乙己显出极高兴的样子，将两个指头的长指甲敲着柜台，点头说：“对呀对呀！……闭包有四种捕获，你知道么？”

我愈不耐烦了，努着嘴走远。

孔乙己刚用指甲在柜台上画 fn mut()，见我毫不热心，便又叹一口气，显出极惋惜的样子。

有几回，邻舍孩子听得笑声，也赶热闹，围住了孔乙己。他便给他们一人一段ChaLi代码。

孩子跑完示例，仍然不散，眼睛都望着屏幕。

孔乙己着了慌，伸开五指将屏幕罩住，弯腰下去说道：“不多了，我已经不多了。”

直起身又看一看屏幕，自己摇头说：“不多不多！多乎哉？不多也。”

于是这一群孩子都在笑声里走散了。

孔乙己是这样的使人快活，可是没有他，别人也便这么过。

有一天，大约是中秋前的两三天，掌柜正在慢慢结账，取下粉板，忽然说：“孔乙己长久没有来了。还欠十九个钱呢——那还是违约金零头。”

我才也觉得他的确长久没有来了。

一个写代码的人说道：“他怎么会来？……他写代码写垮了。”

掌柜说：“哦！”

“他总仍旧是接外包。这一回，是自己发昏，竟接了个写编译器的大项目。那家的活，是人接的么？”

“后来怎么样？”

“怎么样？先写文档，后来是改，改了大半夜，越改越写不出来。”

“那家的活，难在哪？”

“难在哪？闭包捕获要全过，借用检查要全过，循环引用检测要全过，还要零警告。少一样，都不算交付。”

“后来呢？”

“后来交不出货了。”

“交不出货怎样呢？”

“怎样？……合同上写着违约金，许是赔不起了。”

掌柜也不再问，仍然慢慢算他的账。

中秋过后，秋风一天凉比一天。看看将近初冬，我整天靠着火，也须穿上棉袄了。

一天的下半天，没有一个顾客，我正合了眼坐着。忽然间听得一个声音：“开一个沙箱。”

这声音虽然极低，却很耳熟。看时又全没有人。

站起来向外一望，孔乙己便在柜台下，对着门槛坐着。

他脸上黑而且瘦，已经不成样子；穿一件破夹袄，怀里抱着个旧键盘，手指还搭在键帽上；见了我，又说道：“开一个沙箱。”

掌柜也伸出头去，一面说：“孔乙己么？你还欠十九个钱呢——违约金零头还没清呢！”

孔乙己很颓唐地仰面答道：“这……下回还清罢。这一回是现钱，代码要新。”

掌柜仍然同平常一样，笑着对他说：“孔乙己，你又写循环引用了！”

但他这回却不十分分辩，单说了一句：“不要取笑！”

“取笑？要是不写，怎么连回收器都不拦你，跑出来个 counter 只涨不跌？”

孔乙己低声说道：“循环引用，对象里存闭包，闭包又捕获对象，环套环，回收不掉的……”

他的眼色，很像恳求掌柜，不要再提。

此时已经聚集了几个人，便和掌柜都笑了。

我开了沙箱，放到门槛上。

他从破衣袋里摸出四文大钱，放在我手里。见他满手是茧，指节上还有键帽印，原来，他便用这手敲了一路的代码。

不一会，他跑完代码，便又在旁人的说笑声中，抱着旧键盘，慢慢走去了。

自此以后，又长久没有看见孔乙己。到了年关，掌柜取下粉板说：“孔乙己还欠十九个钱呢——违约金零头。”

到第二年的端午，又说：“孔乙己还欠十九个钱呢——违约金零头。”

到中秋可是没有说，再到年关也没有看见他。

我到现在终于没有见——大约孔乙己的确死了。

### 技术对照

返回闭包本身合法；问题是它是否携带活得不够久的借用。默认只读借用、mut 写回借用、copy 拥有副本和 move 转移拥有关系各有规则。循环持有与借用逃逸也不是同一个问题，应按实际所有权图和宿主资源协议分析，不能从人物对白推断存在通用追踪式回收器。
