# 05 交付安全

Magel 可交付普通字节码、无名变长符号字节码或 AOT 可执行文件。交付时选择运行形态、保存诊断映射，并明确可执行逻辑仍可被分析。

字节码加密功能已删除。`--encrypt` 与 `[magel] encrypt` 不再受支持，历史加密产物须从源码重新导出。

## 1. 交付形态

| 形态 | 接收方需要什么 | 适用场景 |
| --- | --- | --- |
| `.mgl` 源码 | Magel 编译器 | 开放源码、联合开发 |
| 普通 `.svmb` | 匹配能力的 StackVM 宿主 | 设备加载、跨平台部署 |
| 无名变长符号 `.svmb` | 支持紧凑格式的 StackVM 宿主 | 减小文件、去除可读符号名 |
| AOT 可执行文件 | 对应平台运行环境 | 本地独立部署 |

`.svmb` 本身不是操作系统可执行文件；它需要 VM 或嵌入式宿主。AOT 将同一程序导出为本地可执行文件。

## 2. 导出与分发

普通字节码：

```sh
magel svmb src/main.mgl out build/app
```

无名变长符号字节码：

```sh
magel svmb src/main.mgl out build/app --compress-symbols
```

第二条命令生成 `build/app.svmb` 与 `build/app.symbol_map.json`。映射表由开发方保存；可用 `--symbol-map FILE` 指定路径。不要将其作为用户运行所必需的文件。

AOT 可执行文件：

```sh
magel aot src/main.mgl out build/app
```

按目标平台交付可执行文件；Windows 产物带 `.exe` 后缀。普通字节码、紧凑字节码和 AOT 的格式及能力差异见[部署指南](06-deployment.md)。

## 3. 能力边界

符号压缩移除可读符号名并减少体积，保留指令、常量与可执行逻辑。字符串常量仍可能包含业务信息；取得产物的人可以分析其行为。AOT 产物同样可以进行原生反汇编。

容器校验和用于发现意外损坏，不提供身份认证。需要控制发布来源或设备访问权限时，应由部署系统和宿主实现对应策略。

默认不写源码位置；需要调试记录时显式使用 `--debug`。符号映射可用于离线诊断，保存与部署版本对应的映射表。

## 4. 产物管理

| 文件 | 保存方 | 用途 |
| --- | --- | --- |
| `.mgl` | 开发方或协作方 | 源码与重新构建 |
| `.svmb` | 运行方 | VM 加载 |
| `.symbol_map.json` | 开发方 | 离线诊断映射 |
| AOT 可执行文件 | 运行方 | 对应平台运行 |
| 调试构建与构建记录 | 开发方 | 复现和定位问题 |

升级时从源码重新构建，并验证目标 VM 支持程序需要的能力。移除加密后，加载器拒绝历史加密标志，项目配置中的旧键也会报错。
