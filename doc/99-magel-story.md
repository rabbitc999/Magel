# 99 Magel 的故事：一门被"删"出来的语言

> **一次编写，处处运行。**
> 一份逻辑，从 MCU 到云端；值语义、非空引用、无 GC。
>
> 这一篇不是语法手册，是**这门语言怎么变成今天这个样子**的记录：它从哪儿起步，撞过哪几次墙，
> 删掉了什么，还剩什么没做完。当前语法查[语言参考](04-language-reference.md)，
> 逐条变更查 [`CHANGELOG.md`](../CHANGELOG.md)。

如果只看今天的样子，Magel 很容易被读成"一门 C 风格的、带 VM 的静态语言"。
但这份形状不是一次设计出来的，而是**被一次次撞墙撞出来的**：每撞一次，就删掉一批东西。
所以这篇故事里，真正推动语言前进的都是**减法**——删除裸指针、删除空引用、删除别名语义、
删除没人负责的临时值、删除一整条交付路线、删除宏里多出来的那套 DSL。

> 早先还有一版用“方块世界”比喻写的故事（25 章），已随旧的开发者文档归档一起删除
> （内容可在 Git 历史里查到）；这一篇是它的替代品，只讲今天仍然成立的事实与取舍。

---

## 1. 起点：一份长得像课程实验的 C 子集

最早它不叫 Magel，而叫 **Magic-C**。起点非常朴素：C 风格的声明、表达式、`if`、循环和函数，
编译产物是**四元式**——直观、适合教学，也方便对照优化前后的变化。那时长得像一份课程实验，
最初的自我描述也就是"C 子集"。

指针的写法是 `T mut*`。一切像 C 那样朴素而危险：可以声明 `int64 mut* p = &a;`，
可以顺着指针读写，也可以写指针算术。很快，能力越过了这块牌子：结构体有了方法，
枚举能携带载荷，泛型能约束接口，lambda 可以做类型化回调，模块能装进 `.svmb` 由另一台机器加载。

```c
int64 main() {
    println("hello, Magel");
    return 0;
}
```

这句 `hello, Magel` 现在看起来平淡，但它背后已经换过一次名字、删掉过一套指针体系、
重写过一次值语义。下面按时间顺序讲这几次转折。

### 三个别名，三种看法

这门语言有过几个帮助理解它的叫法，它们照向同一张地图，不是改名时间线：

- **C+-**：保留 C 的声明、表达式与控制流（加号），收紧空引用、地址算术和含糊的类型转换（减号）。
- **cust**：C 的外形，加上 Rust 式的资源关切——值归谁、引用从哪来、何时释放要交代清楚。
  它描述的是方向，不是照搬所有权系统：Magel 没有要求用户掌握的移动语义。
- **cava**：写下的是 C 风格源码，交付的可以是 `.svmb`，执行它的是 StackVM。

今天的正式名字只有 **Magel**，工具叫 `magel`，源码扩展名是 `.mgl`。

## 2. 第一次撞墙：无 GC 的世界里留不住指针

指针最先出问题。在没有垃圾回收器的前提下，`T mut*` 同时带来了三件事：空指针、悬垂指针、
地址越界。真实故障不只是理论：字符串地址曾经能沿赋值、返回值或函数指针调用混进整数槽；
`&&` 与 `||` 会先点亮两侧再做位运算；非 `void` 函数走到尽头时悄悄给出零。

修法不是在每个入口贴补丁，而是**换掉这套机制本身**：

- `T mut*` / `T const*` 整体废除，改成 **`T mut&` / `T const&`**；
- 删除 `null` 关键字、复合引用类型和地址算术；引用必须初始化，缺省值写 `Option<T mut&>`；
- `T &` 是 `T const&` 的语法糖，可写引用能隐式转只读，反过来必须显式；
- 地址不再靠算术得到，观察地址只走 `address`；
- 跨语言边界时，C 的可空单对象指针用 `Option<T mut&>` / `Option<T const&>` 表达，
  C++ 胶水对应 `std::optional<Reference<T>>`；宿主交回空指针就是 `None`。

```c
int64 main() {
    int64 count = 1;
    int64 mut& current = &count;
    current = current + 1;
    println("count={} current={}", count, current);
    return 0;
}
```

输出 `count=2 current=2`。看起来和 C 的指针几乎一样，但性质变了：
**`&count` 不再是"取一个地址"，而是"绑定一个引用"**——没有空引用，没有 `p + 1`，
没有 `*p` 强制解引用。

这一轮同时把类型检查汇到了一条公共入口：赋值、初始化、返回、调用都过同一道目标类型检查。
`bool` 与数值之间必须显式转换，`&&` / `||` / `!` 只接受 `bool` 并真正短路，
非 `void` 函数必须证明所有可达路径都返回。

## 3. 第二次撞墙：号称值语义，其实有别名

第二堵墙藏在最基础的地方。**`string a = b;` 曾经是别名**——改 `a` 会动 `b`。
语言嘴上说值语义是默认，实际在最常用的类型上并不成立。

于是有了一次明确的破坏性变更：**字符串变成值类型**，复制就是复制出一块属于自己的存储。
同一条规则推广到 `std::lang::List<T>` / `Set<T>` / `Map<K,V>`、`BigInteger` / `BigDecimal`，
以及结构体、枚举、元组、数组的元素：借来的先复制，当场造出来的按接管处理，
覆盖之前先还掉旧值。聚合销毁时按叶子递归释放，`drop()` / `close()` 先于递归释放执行。

```c
int64 main() {
    String a = "left";
    String b = a;
    b = "right";
    println("a={} b={}", a, b);
    return 0;
}
```

输出 `a=left b=right`。这行现在平淡无奇，改成它之前，`a` 会跟着变成 `right`。

**代价是立刻出现的。** 值语义一旦真的成立，临时值的归属就成了问题：
`t.f1().f2()` 里的中间值归谁？当时的解法是**一条禁令**——
不许在持有资源的临时值上直接调方法，`f().g()` 必须写成 `T t = f(); t.g();`，否则编译期报错。

那条禁令是对的，但它只是止血带。

## 4. 第三次撞墙：让编译器接住每一个中间值

禁令保住了内存，代价是写法：迭代器流水线、`t.f1().f2()`、
`(t.f1() + 1).f2() + 2` 都得手工插满临时变量。这不是一门语言该让用户操心的事。

真正的修法在编译器里，分三层落地：

1. **链式临时值由编译器保存**，完整表达式结束时按创建逆序 `close` / `drop`、递归释放并清空内部槽；
   最终结果先保存或移交，再清理。短路没搭起来的分支不析构。
2. **具名引用借用临时值时**，相关临时所有者延长到声明块结束，不会提前释放；
   用户下标（有 `Index<R,K>` 实现的下标）按值返回也算"当场造出来的值"，避免深拷贝泄漏。
3. **软释放后立刻清槽**（`MakeDrop`），并登记定长数组以便出块时按元素释放——
   这两条修掉了"地址被复用后，旧槽又释放一次"的经典故障。

禁令随之撤销。曾经必须手工拆开的写法，现在可以直接串：

```c
List<int64> make() {
    List<int64> xs;
    xs.push(1);
    xs.push(2);
    return xs;
}

int64 main() {
    println("len={}", make().len());
    return 0;
}
```

输出 `len=2`——`make()` 造出来的列表由编译器接住，用完再收走。迭代器流水线也才真正接得起来：

```c
import std::iter;
int64 square(int64 value) { return value * value; }

int64 main() {
    auto picked = std::iter::range(1, 10).map(square).take(3);
    List<int64> values = picked.collect();
    println("{} {} {}", values[0], values[1], values[2]);
    return 0;
}
```

输出 `1 4 9`。

### 借来的东西不能带走

引用非空只回答了"有没有对象"，还剩一个更难的问题：**对象到什么时候还在**。
返回局部变量的引用、把临时对象里的引用带出作用域、把只读来源藏进可写容器，都要沿着来源追。

Magel 补上了**来源追踪**（判定生命周期按词法作用域，而来源身份会沿聚合传播）：
跟踪引用别名和含引用的聚合来源，拒绝返回局部地址、
按值形参地址和局部字段地址，阻止通过 `Option`、元组、模式绑定和容器绕过去。
诊断码是 **`MGL1204`**，报的是源码位置。

来源追踪后来与独立控制流检查共同组成当前借用检查：前者限制引用逃逸，后者跟踪函数内的
move、drop、delete 和后续访问，诊断包括 MGL1204 与 MGL1205。
多个别名仍可共享同一对象，不采用全局独占借用；跨函数副作用、动态下标、递归路径和宿主
原始内存有具体分析边界。详见[借用验证](11-algorithm-validation.md)与[核心概念](03-core-concepts.md)。

## 5. 改名，也改了责任：0.7.0

2026-10-10，项目正式采用 **Magel** 这个名字，版本重置为 **0.7.0**：

有一件事要讲清楚：更名之前的 0.0.1–0.6.2 是更早的记录，排在 0.7.0 前面，
不是它的后续版本。2026-10-15 又做了一次整体重排：从当年这一版起的各版本统一往下挪，
把原先的 2.5.3 定为语言 **0.18.0**（新旧号对照见 [`CHANGELOG.md`](../CHANGELOG.md) 各版本节的日期与标题）。今天以 [`VERSION`](../VERSION) 为准，
不兼容变更升主版本、兼容新增升次版本、修复升补丁版本。

双语也留下了一个至今没补完的洞：**只有语法错误有中英两份**，
类型不匹配、未定义符号这类语义错误仍是中文——那些文案写在编译器核心里，不在报错呈现层。
已列进[路线图](10-roadmap.md)的短期项。

## 6. 交付这条线：从"能跑"到"能交出去"

语言能力的增长是一条线，**交付形态的演化是另一条线**，而且后者才是今天定位的来源。

| 阶段 | 交付出去的是什么 | 局限 |
| --- | --- | --- |
| 四元式 | 可读的中间表示 | 像把整条线路铺在地面上，能工作，不适合运输 |
| `.svmb` 字节码（PESVMB v4） | 指令、数据、类型、模块导出和待绑定宿主符号 | 名字还在，文件本身可读 |
| 压缩符号（MCVM0004） | 名字换成 FNV-1a 64 稳定编号、用 ULEB128 编码的产物 | 映射文件留在自己手里，不能随产物分发 |

板端也走过一次真实验收：电脑端编译、裁剪、打包，更新到 **STM32F407VET6** 开发板，
由固定容量的虚拟机调用板载 HAL 胶水执行，整数与双精度程序正常结束，Flash 镜像读回一致。
那份独立工程后来按要求从仓库移除，记录仍可从 Git 历史查阅——
**这份历史实测不等于当前全部语言特性都已重新上板回归**。现状与边界见[使命宣言](00-vision.md)。

同样的原则贯穿整个标准库：**能力属于模块，不属于 VM 指令集**。
`sin`、`cos`、`pow` 曾经差点被做成指令，最后进了 `std::math`；
VM 指令集只保留语言执行所需的最小集合。今天标准库已有二十多个模块，
覆盖数学、文本、数据格式、并发、网络、SQL 等，见[标准库概览](07-stdlib-overview.md)。

## 7. 第四次：编译器已经知道的事，别让用户再写一遍

前三堵墙都是"出了故障才改"。这一轮不是故障，是**摩擦**：代码能跑、结果也对，
但到处是编译器明明知道、却要人手写的那半个表达式。

### 7.1 强转写到手酸：字面量按上下文定型

整数字面量以前一律按 `int64` 走。于是只要表达式里混进一个窄类型，就得手动补强转：

```c
int32 b = a + (int32)1;     /* 1 按 int64 算，不转就报错 */
```

这不是在表达意图，是在替编译器补它本来就知道的事——`a` 是 `int32`，
结果要装进 `int32`，那个 `1` 还能是什么？

0.16.0 让**目标类型顺着表达式往下传**：赋值、初始化、实参、`return` 的目标类型会传进表达式，
二元算术与位运算按另一侧操作数的类型定型。上面那句现在直接写 `int32 b = a + 1;`。

```c
int32 twice(int32 value) { return value * 2; }
int64 main() {
    int32 a = 1;
    int32 b = a + 1;                 /* 1 按 int32 定 */
    int32 sum = 1 + 2;               /* 两边都是字面量：按 int32 槽位定型 */
    println("{} {} {}", a, b, sum);
    return 0;
}
```

输出 `1 2 3`。比较与逻辑不参与这层定型，没有上下文时仍是默认 `int64`；
十进制字面量装不进目标类型就退回默认类型，由既有的「缩窄要强转」报错，
**不静默截断**（`int8 x = 200;` 照旧报错）。十六进制 / 二进制仍按位模式看待。

### 7.2 每个运算符都要写两份：交换律与对偶

第二处摩擦在运算符重载上。要给自己的类型加一个 `+`，得同时实现 `Add` 和 `RightAdd`——
`a + 5` 走前者，`5 + a` 走后者。可 `+` 是交换的，`a + 5` 和 `5 + a` 本来就该是同一件事，
凭什么要写两遍？

0.16.0 给编译器补了两条推导：

- **交换律**：`+` `*` `==` `!=` `&` `|` `^` 满足交换律，类型只声明左接口时，
  右操作数那侧自动换边。`-` `/` `%`、大小比较和移位不交换，反向仍须显式声明。
- **比较对偶**：只声明 `Less` 时，`5 > a`（对偶）、`a >= 5`（取反）、
  `5 <= a`（对偶 + 取反）都推得出来。

```c
struct Vec : Add<int64, int64>, Less<bool, int64> {
    int64 v;
    int64 leftAdd(int64 other) { return self.v + other; }
    bool leftLess(int64 other) { return self.v < other; }
};
int64 main() {
    Vec a;
    a.v = 10;
    println("{} {}", a + 5, 5 + a);     /* 交换律 */
    println("{} {}", a < 5, 5 > a);     /* 对偶 */
    return 0;
}
```

输出 `15 15` 与 `0 0`。

换边要把右操作数借来当接收者，所以类型可以表态：实现 `RightAdd<R,T>` 就把右向收归自己，
实现空标记接口 `NoRightAdd` 就明令禁止右向（`5 + f` 直接报错，左向 `f + 5` 照旧）。
**换边不改变求值顺序**——两个操作数仍按源码从左到右求值，副作用顺序与不换边时一致。

同一对操作数还可以配多个返回类型（`Add<int64,int64>` 与 `Add<Vec,int64>` 共存，
两个 `leftAdd(int64)` 只在返回类型上不同——普通方法重载做不到这件事），
挑哪条由表达式的目标类型定；没有目标类型就报错并列出候选。

`&&` / `||` 明确不参与重载：短路要先决定左边，与「先求两个操作数再调方法」的模型对不上。
报错直接说这件事，不再落到「找不到 `Add`」的通用文案上。

### 7.3 同一轮里的减法：宏里多出来的那套写法

这一轮还删掉了两样东西——宏 DSL 的 `$match` 那一套，和 `##` 拼接 / `#形参` 字符串化。
理由和上面两处一样：**它们不是新能力，是同一件事的第二种写法**。
`$match` 是在文本替换宏上又叠的一层迷你 DSL，用的人少、报错面却很大；
`##` / `#形参` 曾经是 `$concat` / `$stringify` 的兼容别名，现已删除；当前只接受后两者。
细节见下一节的减法清单。

## 8. 减法清单

这门语言的形状，一半来自删掉的东西：

| 删掉 | 换成 | 为什么 |
| --- | --- | --- |
| `T mut*` / 地址算术 / `null` | `T mut&` / `T const&`、`Option<T mut&>` | 无 GC 下留不住裸指针 |
| `switch` / `goto` / `int` / `uint` / `float` / `double` | `match`、定宽名 `int64` / `uint32` / `float64` | 公共类型只留一个名字 |
| `using` | 核心 `lang` 自动可见 + 无冲突时省略限定 | 少一块牌子，靠清楚的名字解析次序 |
| `extern` / `extern cast` | `abi` 块声明 + 宿主签名声明 | 边界显式化，不再有隐式外部符号 |
| `printf` / 裸 `putchar` / 往变量里写输入 | `println` / `putChar` / `inputLine()` 等返回表达式 | 类型写在签名上，不靠目标变量反推 |
| `generic<T>` 前缀 | 后置 `T name<T>` / `struct Box<T>` | 与调用写法一致，`generic` 回归普通标识符 |
| `.mcpp` 宿主描述语言 | `abi "..."` 块 + VM 宿主注册 | 为描述层再维护一套语法，代价超过省下的注册代码 |
| `IterChain` 链式物化 | `std::iter` 惰性适配器 | 拥有型中间值的清理责任说不清 |
| `magel zip` | `tools/package_compiler.py` | 工具本体不必为了发行自带压缩实现 |
| 宏里的 `##` 拼接 / `#形参` 字符串化 | `$concat(a, b)` / `$stringify(x)` | 同一件事的第二种写法，留着等于把报错面翻倍 |
| 宏 DSL `$match` / `$when` / `$else` 一套 | `$for` + 按实参个数重载 | 在文本替换宏上又叠一层迷你 DSL，用的人少、报错面很大 |

删掉的东西**没有特权**：不保留专门的迁移提示，写出来就是普通错误。
指望用旧语法绕过新规则，等于没写。
