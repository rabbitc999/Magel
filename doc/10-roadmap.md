# 10 路线图与生态愿景

当前能力见[能力与实现边界](17-capabilities.md)，版本读取 [`VERSION`](../VERSION)，
发布历史统一见 [`CHANGELOG.md`](../CHANGELOG.md)。本页列出待完善的方向，不把计划写成已实现。

## 已有基础

静态类型、值语义、非空引用、独立借用控制流检查、泛型、接口和闭包已经实现。
源码运行、共享 VM 字节码和 C++ 中转 AOT 均可用；C/C++ 双向集成有可运行示例。
标准库按[API 索引](library/README.md)维护。H743 板端使用同一 VM 核心，具备独立工程与实机记录。
原生 LSP、DAP、测试、格式化、在线依赖锁定与离线缓存已可使用；根目录工具链默认编入反射。

## 优先完善

| 方向 | 当前边界与下一步 |
| --- | --- |
| 诊断 | 持续统一文件行列、诊断码与多语言覆盖，避免总览对所有错误文案作统一承诺 |
| 文档 | 当前能力、默认配置和限制以实现为依据；历史测试标识实际版本，不把旧快照当当前状态 |
| 调试 | 完善 DAP 的变量、作用域与表达式求值；已有断点、步进和调用栈继续回归 |
| 反射部署 | 当前默认产物有反射要求；评估按需特征位与元数据裁剪，兼容规则保持明确 |
| 发布与平台 | 持续检查编译器、插件、产物版本、依赖和各平台构建的一致性 |
| 稳健性 | 扩大长期运行、耗尽、异常宿主行为、并发和板端预算的验证 |

## 持续建设

- 包管理已支持来源摘要、固定 Git 提交、传递锁定和离线缓存；继续完善分发体验、平台可移植性和第三方生态。
- AOT 当前通过 C++ 工具链生成本地代码，继续优化代码生成、构建耗时与模块缓存。
- VM 与 IR 继续按默认最高优化口径验证正确性和性能，历史基准保持可复现。
- 按实际项目反馈补强标准库和宿主适配；HTTP/TLS、数据库驱动和 GUI 各自按真实后端说明能力。
- 嵌入式继续使用一份共享核心，分别维护编译期模块门禁、MCU 宏裁剪和具体板级胶水。

## 保持的原则

无 GC、引用非空、拥有值确定性清理；可选引用由 Option 表达。借用检查遵循当前别名契约，
不声称覆盖任意宿主内存行为。字节码和 AOT 用于交付，符号压缩不承诺无法逆向。
不为兼容保留已确认的错误行为；兼容性与版本规则见[语义契约](21-semantics-frozen.md)。

## 参与和验证

问题报告附最小程序、实际命令、平台、构建配置和输出。修改语言规则从权威文法和语义层开始；
修改文档同步中文、英文、书稿及对应生成物。局部门禁用于开发，发布记录须写明实际运行范围。
仓库构建与门禁入口见[工具链](09-toolchain.md)和 [`AGENTS.md`](../AGENTS.md)。
