# 21 语义契约与兼容边界

当前版本由 [`VERSION`](../VERSION) 定义，历史变更与编号调整只在 [`CHANGELOG.md`](../CHANGELOG.md)
维护。本页描述持续有效的语义；已实现能力与部署限制见[当前能力](17-capabilities.md)。

## 核心契约

入口 `main` 返回 `int64` 或 `void`；void 正常完成的进程退出码为 0，panic 失败。带花括号的类型声明在 `}` 结束，尾分号可选。

- 普通拥有值的赋值和按值传参复制。`move(T mut&)` 转移现有资源，不复制后析构来源。
- 移动后的原绑定禁止读取、写入或重绑。只有所有到达路径都完整移动后，才允许二次声明同名变量；新声明具有独立存储，旧别名仍关联旧来源。
- 引用非空，`T &` 等价于 `T const&`，`T mut&` 允许修改。`Option<T &>` 的 None 表示没有引用，不产生空引用。
- 独立借用检查跟踪来源寿命、别名与控制流中的移动/释放；允许多个别名，不采用全局独占借用规则。具体边界见[算法与借用验证](11-algorithm-validation.md)。
- 无 GC，拥有值按作用域执行 Closeable/Drop。手动分配、宿主句柄、幂等释放与 sweep 各按其资源契约处理，不承诺自动回收任意宿主资源。
- 匿名函数只使用 `fn`，返回类型前置；默认局部捕获为 const&，支持 mut/copy/move 和逐项捕获。引用捕获不延长来源寿命。
- 使用定宽数值类型。小写 f 固定为 float32；小写 u 为无符号整数，直接对 u 字面量使用一元负号会报错。
- String 下标、切片及基础字符迭代按 UTF-8 字节处理；码点操作使用 std::utf8。
- 每个非 void 值有默认 `toString()` 和字符串转换，结构体/Set/Map 使用大括号、List/数组使用中括号、元组使用小括号；嵌套字符串转义。用户无参 String toString 与 ImplicitConvert<String> 补齐彼此缺失入口，专用显式转换优先。默认路径不依赖反射，不转移源值；引用和不透明资源不解引用。
- 整数 match 的静态单值／区间模式重叠发出非致命警告；开闭端点、空区间与完整 64 位精度参与判断，分支顺序与守卫语义保持不变。
- 枚举分支用 match；错误值使用 Option/Result 及显式传播协议。块表达式可通过 `yield value;` 给出结果；`yield (a, b);` 产生元组；显式 `yield i;` 优先移动内部可写局部变量，外部变量复制，元组中的直接变量逐项应用同一规则。带值退出穿透无值循环并交给最近接收结果的表达式，普通无值退出仍只结束最近循环；`break level N;` 退出第 N 层循环，`break all;` 退出当前函数内全部包围循环，非循环块不计层数且沿途清理。
- 带值退出写 `yield 值;`；层级退出写 `break level N;` / `break all;` / `break level all;`；堆分配写 `heap T;`、`new T(实参);`、`heap new T(实参);`。堆分配仍只能给引用（`T mut&`），构造函数 / 工厂重载仍按实参与目标类型选取（不匹配照常报错）。`heap` 为保留关键字，只在分配位置有意义，不能用作变量名。旧写法 `break 值;`、`break #level(N);`、`break #level(ALL);`、裸 `new;` / `new(实参);` 与 `static T new(形参)` 工厂均已删除，一律按语法错误或缺少构造函数报错。

## 执行与构建契约

返回控制表达式、具名闭包和派生的类型、捕获、移动及清理规则见[声明语法糖](28-declaration-sugars.md)。派生不创建新的所有权或析构模型，借用来源仍必须覆盖结果和闭包的存活期。

宏保持 Lexer 前的纯文本替换：多括号组按定义顺序独立绑定，支持重复括号、每组 `..rest` 和跨行大括号；不构建参数 AST，维护原始文件与行列映射。单空圆括号对象宏及原有参数保护语义保持兼容，详见[文本宏](24-literals-operators-macros.md#有序多括号文本宏)。

源码运行、字节码与 AOT 在共同支持的范围内共享类型、值和资源语义。C export 只支持 AOT；
VM 运行和字节码导出明确拒绝。
AOT 默认启用 `checked` 的分配护栏和 panic 跟踪，宿主默认 `-O3`，静态标量与数组访问优化保留边界、失效内存和错误传播语义；宿主参数缓冲区按调用帧隔离，回调重入不覆盖外层实参。桌面与 MCU 使用同一份 `library/stackvm/`，平台能力由宿主和宏决定。
根目录工具链默认编入前端和运行时反射，单次编译默认启用；无反射目标显式使用 `--no-reflection`。
独立生成工程和板端配置按各自构建文件说明默认值。

IR 指四元式。日常构建、运行和交付使用完整 IR 优化与最高可用 VM 执行优化，调试和差分验证才显式降级。
构建配置、特征位和数据格式仍须匹配目标 VM；同一语言语义不意味着全部平台具备相同外设和标准库后端。

## 兼容性与仍需完善的边界

| 项目 | 维护约定 |
| --- | --- |
| 版本 | 不兼容变更升主版本，兼容新增升次版本，修复升补丁版本；变更记入 CHANGELOG |
| 诊断 | 优先使用诊断码、退出码和结构化结果；不冻结逐字报错文案及翻译 |
| 标准库 | 模块与 API 以索引和源码为准，签名变更明确记录；不在总览复制固定模块总数 |
| 反射 | 当前是显式暴露声明、封闭值和受限调用；后续扩展须保持特征位与调用签名校验 |
| AOT | 当前以 C++ 为中转，构建缓存及导出布局可演进；C 导出与运行时 ABI 按生成头文件使用 |
| 依赖 | 已支持锁定、缓存和离线验证；分发体验和第三方生态继续完善 |
| 安全 | 生命周期检查、运行时校验、宿主安全和硬实时是不同范围；不把回归通过当完整安全证明 |
| 测量 | 保留被测版本、平台和配置；历史基准不随当前 tag 改名重测或重新解释 |

借用、移动及闭包的详细规则分别见[核心概念](03-core-concepts.md)、[语言参考](04-language-reference.md)
和[所有权移动](23-ownership-move.md)。后续方向见[路线图](10-roadmap.md)。
