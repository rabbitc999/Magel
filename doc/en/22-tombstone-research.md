# Tombstone implementation research

Historical configurations and measurements are preserved below. Programs execute through the VM.

This report records the original design and the implementation points used for compression,
explicit sweeping and watchdog restart. Following the later consolidation request, desktop
and embedded builds both compile the single core in `library/stackvm/`; embedded features are trimmed
with macros rather than maintained in a second fork.

## Original storage and execution paths

`library/stackvm/allocation_index.hpp::AllocationIndex` stored active logical intervals in
`Memory::Map<std::size_t, Allocation> active_` and every released logical base in
`Memory::Set<std::size_t> retired_`. A monotonically increasing `next_` assigned identities,
while each allocation stored its physical offset separately. Physical reuse therefore did
not bound the retired set.

| Operation | Implementation path |
| --- | --- |
| Allocation | Language lowering → VM allocation → `Heap::allocate()` → `AllocationIndex::add()` |
| Release | `LowerDelete()` / VM free or drop → heap `release()` → `AllocationIndex::release()` |
| Repeated release | Retired identity lookup suppresses another physical release; aggregate guards suppress another destructor call. |

The default physical heap is implemented in `library/stackvm/parts/machine_natives.cpp`. It splits
free blocks during allocation and merges adjacent free blocks during release.

## Compression changes

The modified index operations are `add`, `release`, `retired`, `find`, `contains` and `reset`.
New operations implement sweeping, physical-slot statistics and compatible placement within
a free physical interval. Each physical root has one slot containing its latest generation,
sweep boundary and displacement width. Active intervals remain separate.

Logical addresses encode a stable slot, generation and decoding widths, so an old reference
can be checked without retaining a record for every allocation. Placement prefers reusable
roots and handles size changes and finite generation exhaustion without wrapping identities.
Integer address and handle conversions in execution preserve their full integer precision.

## Explicit sweep and restart insertion points

`source/epilogue/builtins.cpp` registers the return type of `sweep()`;
`source/epilogue/boxing.cpp` lowers it to `__std_heap_sweep`. Explicit aggregate deletion uses
`__std_heap_delete_live` to distinguish retained old identities from swept identities.
Both native entries are registered in `library/stackvm/parts/machine_natives.cpp`.

`HeapAllocator` exposes sweep and retired-identity contracts. Unsupported custom heaps report
that sweeping is unavailable. Sweeping advances per-slot boundaries, preserves active
allocations and their future idempotence, and never traces or releases live objects.

The embedded host in `library/stackvm_mcu/mcu_host.cpp` explicitly sweeps and resets its byte pool and
identity slots before resetting the arenas. Watermark restarts after normal execution use
the same cleanup path.

Core-library pages and API indexes are generated by `tools/library_reference.py` and its
builtin/data helpers. Watchdog behavior is documented alongside `std::watchdog`.

## Allocator and automatic-cleanup scope

The per-allocation `MAGEL_USE_MALLOC` fallback and C heap allocation/release wrappers are
removed. Pool APIs and host bootstrap allocation of an entire dynamic arena remain.

An identity older than every live allocation does not prove that its old references have
disappeared. A reference to released A can survive while newer B is the oldest live object.
Function returns and iteration boundaries similarly do not prove that references did not
escape. No automatic sweep, root scanner or garbage collector is introduced.

## fn borrowing research

The capture-analysis organization was checked against Rust's
[upvar.rs](https://github.com/rust-lang/rust/blob/main/compiler/rustc_hir_typeck/src/upvar.rs)
and lifetime-constraint conversion against
[constraint_conversion.rs](https://github.com/rust-lang/rust/blob/main/compiler/rustc_borrowck/src/type_check/constraint_conversion.rs).
Magel retains its own scope-source facts and control-flow checker, with mutable borrowing
as its requested default capture rule.

Capture discovery lives in `CheckLambdaCaptures` in `source/epilogue/generic_inference.cpp`;
`source/epilogue/artifacts.cpp` prepares stable storage and `source/epilogue/boxing.cpp` builds/restores
borrowed environments. `source/epilogue/borrow_facts.cpp` propagates source lifetimes through
assignments, returns and aggregate fields. Assignment inference must discover captures
before recording a storage constraint. Copying a closure does not extend its sources.

Asynchronous event entry signatures require static callback sources, including public
interrupt callback fields. Capturing local variables cannot be hidden behind an ordinary
function-pointer conversion of an event registration entry. Synchronous algorithm callbacks
can borrow the caller's live variables.


## Checking later closure uses

Capture discovery and later uses are modeled separately. `FlowState::captures` records external borrowed places held by function values and aggregate fields. Copies, assignments, tuples and enum payloads propagate these sets; reference fields inside owned captures still depend on their external referents. Reading a callable checks whether a captured place was freed, moved or dropped on a reachable path. The callable itself and its captured sources are checked again after argument evaluation, preventing `callback(move(&source))` from invalidating its environment before invocation. Callable results conservatively inherit known external borrows from arguments and receivers. Reassignment replaces the previous capture set, and destruction after the closure's final use remains valid.

The design follows the explicit loan registration in Rust's [borrow_set.rs](https://github.com/rust-lang/rust/blob/main/compiler/rustc_borrowck/src/borrow_set.rs), capture-mode distinctions in [upvar.rs](https://github.com/rust-lang/rust/blob/main/compiler/rustc_hir_typeck/src/upvar.rs), and projection conflicts in [places_conflict.rs](https://github.com/rust-lang/rust/blob/main/compiler/rustc_borrowck/src/places_conflict.rs). It uses Magel's own place and control-flow analysis without copying Rust implementation code.

Checks cover invalidation and propagation visible within the current function. Opaque host code, raw memory writes and erased interprocedural side effects still depend on interface lifetime contracts. This analysis does not establish the absence of all undefined behavior.
